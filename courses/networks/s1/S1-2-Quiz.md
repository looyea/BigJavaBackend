# 小测验 · 以太网、交换机与 VLAN

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分，≥ 60 分过关。

### 1. 交换机收到一个单播帧，若 MAC 表中没有目的 MAC 的表项，会怎么做？（15分）

- A. 丢弃该帧
- B. 泛洪到除接收端口外的所有端口
- C. 上送给默认网关
- D. 发 ARP 请求查询

> 答案：B
> 解析：交换机的两条规则是"学源 MAC、按目的 MAC 转发或泛洪"。表项缺失（老化、非对称路由、表满）时只能泛洪，即"未知单播泛洪"，大规模发生时会打满端口带宽。

### 2. VXLAN 封装给报文带来的额外开销大约是？（15分）

- A. 4 字节
- B. 20 字节
- C. 50 字节
- D. 0 字节

> 答案：C
> 解析：外层 Ethernet(14) 之外的新增部分是 UDP(8) + IP(20) + VXLAN(8) = 50 字节（还有 FCS/CRC 4）。因此 Overlay 内容器的可用 MTU 通常要设成 1450，否则大包分片或被丢弃，出现"小包通、大包卡死"的 MTU 黑洞。

### 3. 【多选】关于 ARP 与 VLAN，正确的有哪些？（20分）

- A. ARP 请求是广播、应答是单播，且通信双方都会更新各自的 ARP 缓存
- B. 主机 IP 变更后不刷新邻居表，对端可能在缓存有效期内继续把包发向旧 MAC；keepalived VIP 漂移用免费 ARP 解决
- C. VLAN trunk 端口允许多个 VLAN 通过并保留 4 字节 tag，access 端口属于单一 VLAN 并剥离 tag
- D. 两个交换机之间直接拉两根网线而不启用 STP/链路聚合，可能因广播风暴秒级瘫痪整个二层域

> 答案：ABCD
> 解析：四项都是本节的核心工程结论。B 对应 `arping -U` 与 `arp_ignore/arp_announce`；C 是裸金属多平面组网与 CNI 排障的基础；D 的解法是 STP/RSTP 或 M-LAG/vPC/堆叠。

### 4. 判断：在排查 A 与 B 之间的通信问题时，在第三台机器 C 上抓包通常抓不到 A→B 的单播流量。（10分）

- A. 正确
- B. 错误

> 答案：A
> 解析：交换机对单播按目的 MAC 定向转发、不广播，因此 C 看不到；必须在被测主机本机抓包，或配置端口镜像（SPAN）。这也是"抓包要在故障两端同时抓"这条排障纪律的由来（呼应 s4-2）。

### 5. 填空题：以太网帧的类型字段中 `0x0800` 表示 ______ 、`0x0806` 表示 ______ ；VLAN 的 ID 字段占 ______ 位，因此最多 ______ 个 VLAN。（10分）

> 答案：IPv4 / ARP / 12 / 4094 / 4096

### 6. 现象：K8s 集群里 Pod 之间同节点通信正常，跨节点访问 Service 时小请求成功、返回体超过 ~14 KB 就稳定卡住超时。请给出根因分析与至少三条修复方案。（30分）

> 参考答案：
> - 判断：这是典型的 **MTU 黑洞 / 路径 MTU 不匹配**，而不是应用或 Service 逻辑问题
> - 机理：CNI 采用 VXLAN（或 Calico IPIP）封装，跨节点报文额外加 50（或 20）字节；Pod 内按 MTU 1500 发包并置 DF 位，封装后超过物理网卡 MTU → 中间设备直接丢弃（DF 置位不能分片），且丢弃方常不回 ICMP Fragmentation Needed，两端都收不到错误 → 小包（远小于 MSS）正常、大包永久丢失、TCP 重传直至超时
> - 佐证手段：跨节点 `ping -M do -s 1472 <peer>`（=1500）失败而 `-s 1400` 成功；`tcpdump` 看只重传同一 seq 的大包；`ip link` 比对 Pod veth、CNI 口、物理口 MTU
> - 修复：① 统一调小 Overlay 接口 MTU（VXLAN 用 1450、IPIP 用 1480），并同步 `cni-conf` 与 Pod 内；② Underlay 全网启用巨帧 9000（需所有交换机同配）；③ 开启 `net.ipv4.tcp_mtu_probing=1` 做黑盒 PMTUD 探测；④ 让中间设备放行 ICMP Type3 Code4（别被防火墙规则吃掉）；⑤ 应用侧避免超大单响应（分页、压缩、流式）作为兜底
> - 加分：指出"同节点正常"是因为流量走本地 bridge 不经封装；这正是按分层与路径切分定位故障的范例
