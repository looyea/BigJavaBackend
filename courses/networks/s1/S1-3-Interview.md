# 面试考点 · IP、子网划分与路由

> 这一节最能区分"写过分布式系统"和"只写过业务代码"。面试官会用一个具体报错（`No route to host` / `Connection refused` / 超时）打开话头，然后逐层追问你的定位路径。

## 考点 1：子网与 CIDR（快速笔试，必须秒答）

**起手**：`/27` 有几个可用地址？250 台机器要什么前缀？

**期望**：`/27` → 32 地址、**30 可用**；250 台 → `2^8 − 2 = 254 ≥ 250` → **/24**。

**追问链**：
1. 掩码反推？→ `/25=128、/26=192、/27=224、/28=240、/29=248、/30=252`（最后一段的"块边界"）。
2. `/31`、`/32` 有什么特殊？→ `/32` 单主机（主机路由、VIP 常用）；`/31` 点对点链路（RFC 3021，2 地址都可用）。
3. VPC 规划的经验值？→ 主网段一次给足（/16），按 AZ 连续切大块（/19）以便路由聚合；与办公网/其他 VPC **不可重叠**；Docker 默认 `172.17/16` 与 `172.16/12` 冲突是经典事故。

## 考点 2：路由判定与"包到底怎么走"

**起手**：机器访问一个跨网段 IP，内核做了哪些决策？

**期望**：查路由表（**最长前缀匹配**）→ 判断是否同网段 → 同网段 ARP 目的 IP、跨网段 ARP **网关** → 出接口 → 过 OUTPUT 链/安全组。

**追问链**：
1. 最快的定位命令？→ `ip route get <dst>`：直接给出出接口、源 IP、下一跳。**先跑它**再看别的。
2. `No route to host`、`Connection refused`、`timed out` 分别是什么层次的问题？→ 无路由 / 无人监听（有 RST 或 ICMP 3/3）/ 被静默 DROP 或队列满。**这一题几乎是必考**，能讲清就说明有真实排障经验。
3. 为什么"IP 是最终目的、MAC 是网关"？→ 三层负责端到端、二层只负责一跳（呼应 s1-1）。
4. 双网卡机器为什么"时通时不通"？→ 非对称路由 + 状态防火墙；修复靠"只留一条默认路由"或策略路由 `ip rule from ... table`（配合 `rp_filter` 的调整与安全代价）。
5. `169.254.169.254` 是什么？为什么要有 `/32` 明细路由？→ 云元数据服务；`/32` 比默认路由更精确，因此不会被 NAT 网关吞掉。

## 考点 3：NAT（工程视角的四连问）

**起手**：SNAT 和 DNAT 的区别？举一个你线上见过的 NAT 相关故障。

**期望**：SNAT 改源（内网出公网、Pod 出网 MASQUERADE）；DNAT 改目的（端口映射、K8s ClusterIP → Pod）。

**追问链**：
1. NAT 的表项有限吗？→ 有，`nf_conntrack_max`；打满时新包被直接丢弃且只在 `dmesg` 留一行日志 → 表现为"偶发连不上、重启后好一阵"。处置：扩 `max` + `hashsize`、缩短超时、内部大流量走 `NOTRACK`、根本解法是**连接复用降低新建速率**。
2. NAT 会让服务端看到的客户端 IP 失真，怎么解决？→ `X-Forwarded-For` / Proxy Protocol（s3-1、s3-4）；按 IP 限流与风控要据此还原真实来源，否则"一栋写字楼被限流"。
3. 长连接为什么需要心跳？→ NAT 映射会老化（UDP 常 30~120 s），空闲即被回收，且**不会通知任何一方** → TCP keepalive 默认 2 小时太慢，必须应用层心跳（s2-2、netty/s3-2）。
4. P2P/RTC 怎么穿透？→ STUN 探测公网映射 + TURN 中继 + ICE 择优；原理是"打洞靠先发包建立映射"。

## 考点 4：ICMP 与诊断工具（说出原理才算懂）

**起手**：`traceroute` 是怎么工作的？

**期望**：发 TTL 递增的探测包（Linux 默认 UDP 高端口、Windows 用 ICMP echo），沿途路由器 TTL 归零时回 **ICMP Type 11**，从而列出每一跳；最后一跳回 ICMP 端口不可达（3/3）表示到达。

**追问链**：
1. 为什么中间出现 `* * *`？→ 该设备不返回 ICMP 或限速（运营商边界常禁 ICMP），不代表故障。
2. `ping` 通能说明服务可用吗？→ 不能（ICMP 与 TCP 独立、可能只放行一方）。要用 `nc -vz` / `curl` / `traceroute -T -p <port>` 按端口验证。
3. ICMP Type3 Code4 为什么重要？→ 它是 PMTUD 的信使；被防火墙丢弃 → 大包黑洞（小请求正常、大响应卡死），K8s/VXLAN 场景头号故障（s1-2）。
4. `mtr` 与 `traceroute` 的差别？→ 持续逐跳统计丢包/抖动，能区分"哪一跳开始丢"；配合 `tcpdump` 双向验证才敢下结论。

## 考点 5：IPv6（现在会问到）

**期望要点**：128 位、无 NAT、无广播（NDP/组播替代 ARP）、头固定 40 字节、**只能源端分片**（ICMPv6 Packet Too Big 做 PMTUD）、URL 地址要加方括号 `http://[2001:db8::1]:8080/`、常见段 `::1`/`fe80::/10`/`fd00::/8`/`2000::/3`。

**追问**：双栈排查注意什么？→ ① 客户端可能优先 AAAA，服务端 IPv6 监听缺失就表现为"部分用户打不开"；② Java 老版本需 `java.net.preferIPv4Stack`/`preferIPv6Address` 权衡；③ **安全组/防火墙必须同步配 IPv6 规则**，否则成为绕过路径；④ 回环 `::1` 与 `127.0.0.1` 是两个地址，只监听其一就会"本地通、远程不通"。

## 考点 6：架构与行业落点（资深必答）

- **VPC/网段规划**：主网段一次给足、按 AZ 连续切块、显式预留增长、与所有对端（办公网/专线/其他 VPC/容器网）做重叠检查。**改网段的代价是迁移级的**，规划阶段就要当架构决策对待。
- **金融专线**：静态路由 + 固定源地址（不做 SNAT）+ 双侧 IP 白名单；出现"只通部分端口"要查 ACL 而非路由。
- **电力海量终端**：运营商 APN 天然是 NAT，主站无法主动下连 → 协议必须"终端主动注册 + 长连接 + 应用层心跳 + 断点续传"，这是网络约束直接塑造应用协议的范例。
- **通用结论**：**"超时且无 RST"= 被静默丢弃；"refused/RST"= 被明确拒绝**。把这一条当成网络排障的第一公设，能省掉大量无效排查。
