# 拥塞控制、粘包拆包与队头阻塞 · 面试题

> 本节三个主题各自都是高频：拥塞控制（考四阶段与 BBR/CUBIC）、粘包拆包（考协议设计）、队头阻塞（考 HTTP/2 vs QUIC 的理解深度）。能串成"可靠有序→HOL→QUIC"一条因果链的是加分项。

## 考点 1：讲一遍 TCP 拥塞控制

**起手**：从连接建立开始，cwnd 怎么变？

**期望**（Reno 四阶段）：
- **慢启动**：从 ~10 MSS 起，每 ACK +1 MSS → 每 RTT 翻倍（指数），到 ssthresh 止。
- **拥塞避免**：每 RTT +1 MSS（线性）。
- **快重传 + 快恢复**：3 个 dupACK → 立即重传，ssthresh=cwnd/2、cwnd≈ssthresh 进拥塞避免。
- **超时（RTO）**：重罚，ssthresh=cwnd/2、cwnd=1 回慢启动。

**追问链**：
1. 为什么 dupACK 只减半、超时却回到 1？→ dupACK 说明后续段到了、网络还活着；超时说明整窗没回、可能严重拥塞。
2. AIMD 是什么？→ 加性增（线性涨）、乘性减（减半），是收敛到公平的核心。
3. 慢启动为什么"名字慢其实快"？→ 指数增长，"慢"是相对"一上来填满管道"而言。

## 考点 2：CUBIC vs BBR（区分架构视野）

**起手**：Linux 默认为什么是 CUBIC？BBR 好在哪、有什么代价？

**期望**：
- CUBIC：以**丢包**为拥塞信号，三次函数逼近最大窗口，高 BDP 友好、与同族公平，但**需要缓冲、深缓冲下 bufferbloat**。
- BBR：以**带宽 + 最小 RTT** 建模 BDp，主动把发送速率钉在"填满管道但不制造排队"，**抗丢包、低延迟**，不靠制造丢包探测。
- 代价：BBR 与 loss-based 流共存时**抢带宽**（公平性争议）、需要较准的 RTT/bandwidth 采样。

**追问链**：
1. 跨地域高丢包专线选哪个？→ BBR（+fq），cubic 会因丢包反复腰斩吞吐。
2. BBR 一定要配 fq 吗？→ 建议，需要 pacing 平滑发包，避免突发。

## 考点 3：粘包 / 拆包（协议设计必问）

**起手**：为什么会出现粘包？怎么解决？

**期望**：
- 根因：**TCP 是字节流，不保留 send 边界**（+ Nagle 攒包、MSS 分片、接收缓冲）→ 读到的可能是多条拼接或一条被截。
- 是特性不是 bug；UDP 有消息边界不会粘包。
- 定界四法：**固定长度 / 分隔符 / 长度字段（推荐）/ 高层协议自带边界**。

**追问链**：
1. 长度字段方案里，服务端怎么处理"只到了一半"？→ 累积缓冲，够 `header+length` 才切一条，否则等待（半包），Netty `ByteToMessageDecoder` 自动做。
2. Netty 用哪个解码器？五参数？→ `LengthFieldBasedFrameDecoder(maxFrameLength, lengthFieldOffset, lengthFieldLength, lengthAdjustment, initialBytesToStrip)`；能说清 offset/adjustment/strip 的推导即高分。
3. 分隔符方案的坑？→ 正文出现分隔符要转义（HTTP 头 `\r\n\r\n`、Redis RESP 靠长度前缀规避）。

## 考点 4：队头阻塞（HOL）—— HTTP/1 vs /2 vs QUIC

**起手**：三层 HOL 分别是什么？谁解决了谁？

**期望**：
- **传输层 HOL**：TCP 按序交付，一个段丢失阻塞其后所有字节 —— 一切的地基问题。
- **HTTP/1 应用层 HOL**：一条连接一次一问一答，慢请求挡后面 → 靠多连接（6 上限）绕。
- **HTTP/2**：一条 TCP 多路复用，消灭应用层 HOL，但**仍受制于传输层 HOL**（丢一个段全流卡）。
- **QUIC/HTTP3**：每条流独立序号+独立重传，**根治传输层 HOL**。

**追问链**：
1. "QUIC 解决 HOL 是因为用了 UDP" 这句话准确吗？→ 不准确。UDP 只是把可靠层搬到用户态的**手段**，本质是**每流独立重传**打破了"全局单一有序"约束。
2. 为什么有时 HTTP/2 反而比 HTTP/1 慢？→ 高丢包链路下 h2 单连接被传输层 HOL 放大，而 h1 多条连接互不阻塞。
3. QUIC 还有什么附带好处？→ 0-RTT、连接迁移（用 Connection ID 而非四元组）、用户态可插拔拥塞控制。

## 考点 5：综合串联题

**起手**：请把"拥塞控制、重传、队头阻塞、QUIC"串成一条因果链。

**期望链路**：
- 想要可靠有序 → TCP 按序交付 + 丢包重传；
- 丢包既触发重传（造成该连接 HOL）又触发 cwnd 收缩（拥塞控制降速）；
- loss-based（cubic）在高 RTT/高丢包下 cwnd 反复腰斩 → 吞吐差、长尾；
- 为绕过应用层 HOL 上 HTTP/2 多路复用，但把 HOL 收敛到一条 TCP → 传输层 HOL 更致命；
- 于是 QUIC：每流独立重传（解 HOL）+ 用户态拥塞控制（可为弱网定制）→ 同时缓解长尾与 HOL。
- 能画出/口述这条链，即达到"架构级网络理解"。
