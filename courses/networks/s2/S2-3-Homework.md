# TCP 可靠传输与流量控制 · 课后作业

> 两题各 50 分，动手验证本节"重传/窗口/Nagle"三件事。做完你会对"P99 为什么莫名 +40ms""重传率怎么量化"有肌肉记忆。

## 作业 1：定位并消除 Nagle × 延迟 ACK 的 40 ms 魔咒（50 分）

**要求**：
1. 写一个最简"请求-响应"聊天式 TCP 应用：客户端每输入一行就 `write` 一个短包，然后阻塞 `read` 服务端回显；服务端 `read` 一行后 `write` 回去。两端都用默认 Socket 选项。
2. 用两个小请求连续往返，测量每次往返耗时，观察是否出现"约 40 ms 的整数倍台阶"。
3. 在客户端与服务端 socket 上设置 `setTcpNoDelay(true)` 后重测，对比延迟变化。
4. 用 `ss -tin`（或抓包看时间戳）确认设置前后小包发送节奏的差异。

**验收标准**：
- 能贴出开/关 `TCP_NODELAY` 两组往返延迟数据，并指出默认 Nagle 下"发小包→等 ACK→再发"的节奏。
- 能解释：这个 ~40 ms 台阶来自**延迟 ACK 定时器**、与链路 RTT 基本无关（所以低 RTT 内网上反而更显眼，因为它相对放大了）；以及为什么批量写（一次 write 大 buffer）能规避。

**参考答案要点**：
- 默认 Nagle：有未确认小段时攒包，配合对端 delayed ACK（最多 40 ms），形成"每往返 +~40 ms"。
- `TCP_NODELAY=true` 后小包立即发出，往返回落到接近真实 RTT。
- 结论：请求-响应/RPC/DB 一律关 Nagle；批量传输可留。

## 作业 2：用 min(rwnd,cwnd) 视角测算一次大文件传输的窗口配置（50 分）

**背景**：从机房 A 向异地机房 B 传备份，链路带宽 1 Gbps、RTT 60 ms。默认 TCP 初始窗口约 64 KB、未协商 wscale。

**要求**：
1. 计算 BDP（带宽时延积）= 带宽 × RTT，换算成字节。
2. 说明仅靠 16 位 `win` 字段（≤65535）能否填满这条管道；为什么必须启用 `wscale`。
3. 给出打开 BBR（`net.core.default_qdisc=fq`、`net.ipv4.tcp_congestion_control=bbr`）前后，用 `ss -tin` 观察 `cwnd`、`retrans`、`rtt` 三项指标的命令与预期差异。
4. 结合本节：若接收端应用消费慢导致 rwnd 收缩到很小，即使 cwnd 很大能跑满带宽吗？说明 rwnd 与 cwnd 谁在"卡脖子"。

**验收标准**：
- BDP 数值正确：`1 Gbps × 60 ms = 0.125 GB/s × 0.06 s ≈ 7.5 MB`，远大于 64 KB。
- 明确"没 wscale → 窗口最大 64 KB → 利用率仅 64KB/7.5MB ≈ 0.85%"。
- 说清"可发=min(rwnd,cwnd)，任一为瓶颈都跑不满"。

**参考答案要点**：
- 需要 wscale（×2^7 起）才能表达 MB 级窗口；同时接收缓冲 `tcp_rmem` 上限要够。
- BBR 相较 CUBIC 在丢包链路上不因乱序丢包盲目减半 cwnd，吞吐更稳；观察 `retrans` 不升、`cwnd` 平滑。
- rwnd 小 → 再大的 cwnd 也发不出去（被流量控制卡住），呼应"慢消费→零窗口→雪崩"。
