# DNS、CDN 与负载均衡

> 这三样是"把一个域名变成一次落到某台机器的请求"的基础设施三件套，也是高可用架构的第一道闸。本节把 **DNS 解析与多级缓存、CDN 回源、四层/七层负载均衡**串成一条从域名到后端的选址链。（重要度 4/5，重点标准；承接 s3-1/s3-3，铺垫 s4-3 全链路）

## 一、DNS：把域名翻译成 IP

### 1. 解析过程：递归 + 迭代

浏览器输入 `www.example.com`：
```
客户端 → 本地解析器(LR，OS/路由器，做递归)
   ├─ 查浏览器缓存 → OS hosts/缓存 → 本地DNS(LR)缓存   （命中即返回）
   └─ 未命中：LR 代客户端"递归"地问下去 ↓
LR → 根域名服务器      ：.com 归谁管 → 返回 gTLD 权威
LR → .com 顶级域(TLD)  ：example.com 归谁管 → 返回权威 NS
LR → example.com 权威  ：www 的 A/AAAA 记录 → 返回 IP（带 TTL）
LR → 把结果按 TTL 缓存后返回客户端
```
- 对客户端是**递归**（一次问到底），LR 与各级服务器之间是**迭代**（我给你下一级，你自己去问）。
- **权威服务器**是域名真正的答案源；中间都是缓存。

### 2. 记录类型（够用即可）

| 记录 | 含义 |
|---|---|
| A / AAAA | 域名 → IPv4 / IPv6 |
| CNAME | 别名 → 另一个规范名（CDN/GSLB 常用，不能和同名的其他记录共存） |
| NS | 该域的权威服务器 |
| MX | 邮件服务器 |
| TXT | 任意文本（SPF、域名验证、DKIM） |
| **SOA** | 区域的权威起点（主 NS、序列号、刷新参数） |

### 3. TTL 与多级缓存：为什么"改了 DNS 半天不生效"

- 一条记录在**浏览器 / OS / 本地解析器 / 公共递归 / 权威**各级都按 **TTL** 缓存。TTL 越大越省权威查询，但变更生效越慢。
- **降低爆炸半径的改法**：提前把 TTL 调小（如 3600→60）→ 变更 → 生效后再调回。切流窗口里的长 TTL 会让新旧地址并存（有人还解析到旧 IP）。
- **公共 DNS（8.8.8.8/223.5.5.5）** 面向公网用户；内网常用**私有 DNS/Hosts/ServiceDiscovery**（K8s CoreDNS、Nacos）做服务发现。

### 4. DNS 的工程与安全议题

- **HTTPDNS**：App 绕过运营商 Local DNS，直接用 HTTP(S) 向自建/云解析服务查 IP。收益：**规避 DNS 劫持/污染、精准调度（拿到客户端真实出口而非 LD 位置）、避免改 DNS 不生效**。移动 App 普遍用。
- **DNS 劫持/污染**：LD 返回假 IP（运营商广告/中间设备/审查）。对抗：HTTPDNS、DoH（DNS over HTTPS）、DoT。
- **DNS 放大 DDoS**：UDP 源地址可伪造 + 响应远大于请求 → 反射放大。对抗：源地址验证、响应速率限制、Anycast 吸收。
- **EDNS Client Subnet（ECS）**：递归把客户端子网带给权威，让 GSLB 更精准调度（隐私有争议）。

## 二、GSLB 与智能线路：全局流量调度

**GSLB（全局负载均衡）** 在 DNS 层做就近/健康调度：权威 DNS 根据**来源 IP 的地理位置 / 运营商线路 / 机房健康 / 负载**返回**不同 IP（或不同 CNAME）**，实现"用户就近接入、故障自动切换"。手段：
- **分线路解析**：电信/联通/移动、各省返回不同 VIP。
- **健康检查**：某机房挂了就不返回它的 IP。
- **权重/就近**：按 RTT 或容量返回。
- 局限：**受客户端缓存 TTL 与 LD 定位误差影响**（把北京联通用户算成上海），精确调度要靠 HTTPDNS/应用层。

## 三、CDN：把内容推到离用户最近的地方

### 1. 命中链路

```
用户 →(GSLB/CNAME 调度)→ 就近 CDN 边缘节点
   ├─ 命中缓存 → 直接返回（含 Cache-Control/HIT 头）
   └─ 未命中(MISS) → 边缘 →（可能经中间层 Shield）→ 回源站取 → 缓存后返回
```
- **静态内容**（图片/JS/CSS/视频）是 CDN 主战场；配合 s3-1 的 `Cache-Control` 决定边缘缓存时长。
- **回源**要防"缓存击穿/雪崩"：大量 key 同时过期一起打源 → 用**过期打散、回源合并（一个 key 只放一个回源请求）、长 max-age + 主动刷新**。

### 2. CDN 关键操作

- **刷新（purge）**：内容更新了，主动让边缘缓存失效（发布后刷 URL/目录）。
- **预热（prefetch）**：大版本上线/大促前，把资源提前推到边缘，避免首波全 MISS 打穿源。
- **动态加速（全站加速 DCDN）**：静态走边缘缓存、**动态请求走 CDN 内部优化的回源链路（专线/长连接/路由优化）**，加速 API。
- **回源 Host / SNI / 协议**：CDN 以什么 Host 头、什么 TLS 版本回源，要和源站约定（呼应 s3-3 SNI）。

## 四、负载均衡 LB：把流量分到一组后端

### 1. 四层 vs 七层

| 维度 | 四层 LB | 七层 LB |
|---|---|---|
| 依据 | IP + Port（传输层） | URL/Host/Header（应用层） |
| 代表 | **LVS**、云 SLB 四层、AWS NLB | **Nginx/HAProxy**、AWS ALB、网关 |
| 能力 | 极高吞吐、透明转发、不解析 HTTP | 按路径/域名路由、灰度、改写、TLS 卸载 |
| 开销 | 低 | 高（要解析报文） |

### 2. LVS 三种模式（经典）

- **NAT**：LB 改目的 IP，请求响应都过 LB → LB 成瓶颈。
- **DR（直连路由，最常用）**：LB 只改**目标 MAC** 把帧转给后端，后端**用 VIP 直接回客户端**（响应不过 LB）→ 吞吐极高；要求后端与 LB **同二层**、后端配 VIP 且抑制 ARP（`arp_ignore/arp_announce`）。
- **TUN（IP 隧穿）**：跨网段用 IP-in-IP 隧道，后端解封装直接回。

### 3. 调度算法

- **轮询/加权轮询（WRR）**、**最少连接（LC）/加权最少连接**、**源地址哈希（一致性哈希）**、**最快响应/带健康检查的 least-time**。

### 4. 会话保持（sticky）与其替代

- 有状态后端需要"同一用户总落同一台"：可用 **源 IP 哈希** 或 **Cookie 植入/重写（七层）**。
- **更优解：无状态化 + 把会话外置（Redis/JWT）**，从根上免去 sticky，扩缩容才平滑。

### 5. 健康检查与平滑上下线

- **主动探测**（HTTP/TCP 探活、`/health`）+ **被动熔断**（连续 5xx/超时摘除）。
- **平滑上下线**：新后端**预热**（慢慢加权，避免冷启动 JIT/连接池/缓存未热被打爆）；下线**先摘流量 → 等 in-flight → 再关**（呼应 s2-2 优雅发布）。

### 6. 一致性哈希（扩缩容时少迁移）

- 普通 `hash(key) % N`：N 一变（加减机器）几乎所有 key 重映射 → 缓存集体 MISS / 会话全乱。
- **一致性哈希**：把节点和 key 都映射到一个环形哈希空间，key 顺时针找最近节点；加减节点只影响**相邻区段**的 key。再配**虚拟节点**（每物理机拆很多虚拟点）打散倾斜。用于：分布式缓存分片、带会话保持的 LB、对象存储。

## 五、把三件套串起来（选址全景）

```
域名 ──DNS/GSLB──► 就近VIP/边缘 ──CDN缓存?──► 命中直返 / MISS回源
                                                      │
                                          源站入口：四层LVS(DR) ──► 七层Nginx ──► 后端集群
                                                      │            (TLS卸载/路由/灰度)
                                          服务发现(K8s/Nacos) + 一致性哈希缓存 + 平滑上下线
```

## 六、三大行业场景钩子

- **电商**：静态资源全上 CDN（发布预热 + 变更刷新 + 回源合并防击穿）；GSLB 多机房就近接入 + 单元化容灾切流（改 DNS 权重前先把 TTL 调小）。
- **金融**：交易入口用**四层 LVS-DR 抗量 + 七层做灰度/风控路由**；同城双活/异地多活靠 GSLB + 健康检查秒级摘除故障机房；DNS 用 HTTPDNS 防劫持（防把用户导向假站）。
- **电力**：主站海量终端接入前置 LVS-DR 摊连接、后端按终端 ID **一致性哈希** 保证"同一终端稳定落到同一采集节点"（便于状态/去重）；边缘站点用私有 DNS + 静态映射保证断网时本地仍可解析。

## 七、要点回顾

1. DNS = **客户端递归 + LR 迭代**问 根→TLD→权威；记录 A/AAAA/CNAME/NS/TXT/SOA；**多级缓存受 TTL 控制**，改记录有生效延迟（切流先调小 TTL）。
2. **HTTPDNS/DoH** 抗劫持与精准调度；**GSLB** 在 DNS 层按线路/健康/就近返回不同 IP；受 TTL 与 LD 定位误差限制。
3. **CDN** = 就近边缘缓存静态、**回源**要防击穿（打散/合并/预热/刷新）；**动态加速**优化回源链路。
4. **LB 四层(LVS/NLB)** 看 IP+Port 高吞吐、**七层(Nginx/ALB)** 看 HTTP 做路由/TLS卸载/灰度。
5. **LVS-DR** 只改 MAC、响应不过 LB（最高吞吐）；调度 WRR/LC/哈希；**一致性哈希 + 虚拟节点**让扩缩容少迁移。
6. **会话保持不如无状态化**（会话外置）；**健康检查 + 预热 + 先摘流量后关**实现平滑上下线。
