# HTTP/2 与 HTTP/3（QUIC） · 面试题

> 高频追问集中在"h2 改了什么""h2 为什么还有队头阻塞""QUIC 到底解决了什么、代价是什么"。答好这套题的关键是**把队头阻塞的层级讲清楚**。

## 考点 1：HTTP/2 相比 1.1 做了哪些优化

**起手**：列一下并说清各自解决什么。

**期望**：
- **二进制分帧**（替代文本，健壮易解析）。
- **单连接多路复用**（多 stream 交错，解决应用层 HOL）。
- **HPACK 头部压缩**（静态/动态表 + 哈夫曼，解决头部冗余）。
- **服务端流控 + 优先级**、**Server Push**（后者已近乎废弃）。

**追问链**：
1. 多路复用怎么做到不串？→ 每帧带 Stream ID，接收端按 ID 重组。
2. 为什么 h2 基本强制 TLS？→ 生态/中间盒对明文 h2 支持差，浏览器只在 TLS+ALPN 下协商 h2。

## 考点 2：h2 的队头阻塞（区分层级，重点）

**起手**："h2 不是多路复用了吗，怎么还有队头阻塞？"

**期望**：
- h2 消灭的是**应用层** HOL；但所有 stream 跑在**同一条 TCP** 上，TCP 要求按序交付，**丢一个段 → 全连接所有流阻塞等重传** = **传输层 HOL**。
- 后果：弱网下 h2 可能不如 h1 多连接（h1 各连接独立丢包只卡自己）。

**追问链**：
1. 怎么根治？→ 换掉 TCP → QUIC（每流独立序号与重传）。
2. 为什么说"应用层并行 ≠ 传输层并行"？→ 复用在一条有序字节流上，底层一旦有序等待，上层并行全被拖住。

## 考点 3：QUIC / HTTP3

**起手**：QUIC 解决了什么问题、用了哪些手段？

**期望（四特性）**：
- **每流独立重传** → 消灭传输层 HOL。
- **0-RTT/1-RTT 建连**（TLS1.3 并入握手）→ 首包更快。
- **Connection ID 连接迁移** → 切网/换端口不断连。
- **用户态可插拔拥塞控制** → 迭代快、逐连接定制。

**追问链**：
1. QUIC 跑在 UDP 上是为了"复用现成拥塞控制"吗？→ 不是，是为绕过内核 TCP 的有序/重传约束，自己在用户态实现可靠层。
2. QUIC 代价？→ CPU 高（用户态处理每包 + 加解密、丢硬件卸载）、UDP 被防火墙/QoS 差别对待、需 Address Validation 抗反射攻击。
3. 怎么回退？→ `Alt-Svc: h3=":443"`，客户端不支持 h3 时回落 h2/h1。
4. 0-RTT 有什么安全风险？→ 重放攻击，只用于幂等请求（呼应 s3-3）。

## 考点 4：选型题

**起手**：给你一个系统，问哪里用 h1 / h2 / h3。

**期望**：
- 内网 RPC / 服务间 → **h2/gRPC**（低丢包、要双向 stream）。
- 公网移动用户、弱网/切网多 → 边缘 **h3/QUIC**（CDN 侧开）。
- 兼容极老客户端 / 纯静态走 CDN → h1.1 也仍够用。
- 一句话：**越靠近不可靠的公网末端，QUIC 收益越大；越在内网，h2 足够且更省 CPU**。
