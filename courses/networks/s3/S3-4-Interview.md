# DNS、CDN 与负载均衡 · 面试题

> 这组题偏"基础设施全景 + 排障"。高分答案能画出从域名到后端整条选址链，并对 DNS 生效延迟、CDN 回源、四层/七层分工、一致性哈希有实操理解。

## 考点 1：DNS 解析全过程

**起手**：输入域名到拿到 IP，中间发生了什么？

**期望**：
- 逐级查缓存：浏览器 → OS(hosts) → **本地解析器 LR** → 未命中则 LR 代表客户端**递归**、对根/TLD/权威**迭代**地问，最终权威返回 A/AAAA（带 TTL）。
- 能说清"递归 vs 迭代是相对谁"。

**追问链**：
1. 改了 DNS 记录为什么不立即生效？→ 各级按 TTL 缓存；切流要提前调小 TTL。
2. 什么是 DNS 劫持、怎么防？→ LD 返回假 IP；用 HTTPDNS/DoH 绕开 LD、证书二次校验。
3. `dig +trace` 干嘛？→ 从根开始看完整迭代链路。

## 考点 2：GSLB / CDN

**起手**：怎么让不同地区/运营商用户就近接入？

**期望**：
- **GSLB**：权威 DNS 按来源线路/地理/健康/权重返回不同 IP 或 CNAME。
- **CDN**：边缘缓存静态内容，MISS 才回源。

**追问链**：
1. CDN 回源被打穿怎么办？→ 过期打散、回源合并、预热、主动刷新。
2. 发布后 CDN 还是旧内容？→ 没做 purge/文件名没带 hash；讲刷新与 `max-age`/hash 的配合。
3. GSLB 调度的局限？→ 受客户端 TTL 与 LD 定位误差影响，精确调度靠 HTTPDNS/应用层。

## 考点 3：四层 vs 七层负载均衡

**起手**：两者区别、分别用在哪？

**期望**：
- **四层**：看 IP+Port（传输层），不解析 HTTP，吞吐高（LVS/NLB）。
- **七层**：看 URL/Host/Header，能做路径路由、灰度、TLS 卸载、改写（Nginx/ALB/网关），开销大。
- 典型组合：入口四层抗量 + 其后七层做灵活路由。

**追问链**：
1. LVS-DR 为什么快、有什么前提？→ 响应不过 LB（后端 VIP 直回）；需同二层、后端抑制 ARP。
2. NAT 与 DR 的取舍？→ NAT 请求响应都过 LB 成瓶颈、但可跨网段/改端口；DR 高吞吐但同二层、不能改端口。

## 考点 4：一致性哈希（缓存/分片高频）

**起手**：为什么不用 `hash%N`？

**期望**：
- `hash%N` 在 N 变化时几乎所有 key 重映射（缓存集体失效/数据大迁移）。
- **一致性哈希**：节点与 key 上映射到环，增删只影响相邻段；**虚拟节点**解决分布倾斜。
- 应用：分布式缓存分片、会话保持 LB、对象存储。

**追问链**：
1. 虚拟节点解决什么？→ 物理节点少时环上分布不均、加减造成负载倾斜。
2. 数据/缓存节点找"顺时针下一个"行不行？→ 是常见做法；也可多副本存顺时针后 N 个。

## 考点 5：高可用 / 平滑上下线（架构综合）

**起手**：一台后端要发布，怎么不中断？

**期望**：
- **先摘流量**（从 LB 下线/健康检查置不通过）→ **等在途请求排空**（设上限）→ 停 → 启 → **预热**（JIT/连接池/本地缓存热了再慢慢加权）→ 恢复满权重。
- 呼应 s2-2 优雅发布、s3-1 keep-alive idle timeout 与中间层关系。

**追问链**：
1. 会话保持怎么处理？→ 优先无状态化 + 会话外置（Redis/JWT），sticky 只是兜底且不利扩缩容。
2. 健康检查怎么不误摘不漏摘？→ 主动探测 + 被动 5xx/超时熔断，配"连续 N 次失败才摘、连续 M 次成功才恢复"防抖。
3. 机房级容灾切流要注意什么？→ DNS TTL 生效延迟（HTTPDNS 加速）、会话外置、跨机房数据复制 lag。
