# HTTPS、TLS 1.2/1.3 与证书体系 · 面试题

> 这题的天花板在于：能不能讲清"为什么混合加密""前向安全为什么需要临时密钥""证书信任怎么传递""TLS1.3 改了啥"。答不出定位链=没排查过线上证书事故。

## 考点 1：HTTPS 到底解决了什么、怎么解决

**起手**：HTTPS 比 HTTP 多了什么？

**期望**：
- 三件事：**加密（机密性）、完整性（防篡改）、身份认证（防冒充）**。
- 手段是**混合加密**：非对称/ECDHE 在握手协商对称密钥并认证，对称 AEAD 加密数据，摘要/签名做完整性与认证。

**追问链**：
1. 为什么不全程用非对称？→ 太慢，只够握手用。
2. 对称加密怎么防篡改？→ 用 AEAD（AES-GCM/ChaCha20-Poly1305）自带认证标签。

## 考点 2：前向安全（PFS）

**起手**：什么是前向安全？怎么获得？

**期望**：
- 定义：长期私钥日后泄露，也**解不开之前录下的历史会话密文**。
- 手段：用**临时**密钥交换 **ECDHE**（每会话临时密钥用完即弃），私钥只签名不参与密钥加密。
- 反例：旧 **RSA 密钥交换**（客户端用服务器公钥加密预主密钥）无前向安全。

**追问链**：
1. TLS1.3 为什么删 RSA 密钥交换？→ 强制 PFS，只留 (EC)DHE。
2. ECDHE 里的 E 是什么？→ Ephemeral，临时。

## 考点 3：TLS 1.2 vs 1.3

**起手**：1.3 改进了什么？

**期望**：
- **2-RTT → 1-RTT**（ClientHello 带 key_share），恢复会话 **0-RTT**。
- 套件精简、**默认 PFS**、握手大部分**加密**（证书不再明文）、删除压缩/renegotiation/静态 RSA。

**追问链**：
1. 0-RTT 的风险？→ **重放攻击**，只能放幂等/无副作用数据；服务端做 single-use ticket/freshness。
2. SNI 是什么、有什么问题？→ ClientHello 明文带域名供多主机选证书；明文泄露 SNI → TLS1.3 用 ECH/ESNI 加密。

## 考点 4：证书链与信任

**起手**：浏览器怎么确认一张证书可信？

**期望（验证四步）**：
- **验签**：叶子←中间←根，逐级用上级公钥验签，直到本地信任库里的**根**。
- **域名匹配**：看 **SAN**（不是 CN）。
- **有效期**：notBefore/notAfter。
- **吊销状态**：CRL / **OCSP Stapling**。

**追问链**：
1. 服务器要不要发根证书？→ 不，只发叶子+中间；根在客户端信任库。
2. 为什么某些安卓连不上而 iPhone 正常？→ 常见是**缺中间证书**，安卓不自动补链。
3. OCSP Stapling 好处？→ 服务器预取吊销凭证随握手带上，省客户端往返 + 隐私。
4. CA 乱签怎么防？→ 证书透明度 CT（公开日志 + SCT）。

## 考点 5：mTLS

**起手**：双向认证和单向有何不同、用在哪？

**期望**：
- 单向只认证服务器；mTLS 客户端也出示证书、服务器验 → 身份绑证书。
- 用于零信任服务间、开放银行/机构对接（金融高频）。
- 代价：客户端证书分发/吊销体系重，常配短证 + 自动化（SPIFFE）。

## 考点 6：线上证书故障定位（送命题）

**起手**：用户报"网站证书有问题打不开"，你怎么查？

**期望顺序**：**有效期（过期？）→ SAN 域名（不匹配？）→ 链完整性（缺中间？）→ 协议/套件（老客户端只 TLS1.0 被拒？）→ 客户端信任根（自签/内部 CA 未进 truststore？）**。

**追问链**：
1. Java 报 PKIX 怎么办？→ 把对应根/内部 CA `keytool` 导入 truststore；别写"信任所有证书"。
2. 能不能为了省事让 App 忽略证书校验？→ 绝对不行（等于裸奔、易 MITM），是安全红线。
3. 如何避免"证书过期事故"？→ ACME/Let's Encrypt 短证 + 自动续期 + 到期监控告警。
