# 从输入 URL 到页面渲染全链路 · 面试题

> 这是把整个网络分区串起来的**终极综合题**，也是校招/社招几乎必考的开放题。区分度在于：有没有**结构**（分段清晰）、能不能**逐段深入**（面试官会挑一段追问到底）、有没有**测量与优化**的工程视角。下面给出满分骨架。

## 主线答案（先给全景，再让面试官选一段深挖）

**建议这样开场**（体现结构化）：
> "我把它分成三大段：**请求发出前**（URL 解析 + 缓存 + DNS）、**网络传输**（TCP + TLS + HTTP + LB）、**服务端处理与浏览器渲染**。每一段我可以展开，您想先听哪块？"

链路一览：
```
URL→强缓存→DNS→TCP握手→TLS→(LB四层→七层→服务发现)→发HTTP→后端(网关/服务/DB/缓存)
→响应(min(rwnd,cwnd)传输/缓存头)→浏览器(DOM+CSSOM→渲染树→布局→绘制→合成)→子资源再来一轮
```

## 追问 1：DNS 这一段能讲到多深

- 逐级缓存（浏览器/OS/LD）→ 递归+迭代问 根→TLD→权威 → TTL。
- **GSLB**：按来源线路/健康返回不同 IP/CNAME（就近 + 容灾）；**HTTPDNS** 抗劫持。
- 加分：改记录生效延迟、`dig +trace`。

## 追问 2：TCP/TLS 为什么分开讲还得合起来

- 三次握手交换 ISN+窗口+选项、两个队列（半/全连接）。
- TLS 用 **SNI** 选证书、**ALPN** 定 h1/h2/h3、证书链验证、**ECDHE 前向安全**；1.2 是 2-RTT、1.3 是 1-RTT/0-RTT。
- 加分：TLS 卸载在 LB/边缘、会话复用降延迟。

## 追问 3：HTTP 版本选型（高频落点）

- h1：短连接/keep-alive、应用层 HOL、多连接硬扛。
- h2：二进制分帧、单连接多路复用、HPACK；但**传输层 HOL** 仍在。
- h3/QUIC：每流独立重传解 HOL、0-RTT、连接迁移；代价 CPU/UDP 生态。
- 一句话：**越靠公网末端越该上 h3，内网 h2/gRPC 足够**（s3-2）。

## 追问 4："慢在哪" —— 用测量说话（最能加分）

**期望**：
- `curl -w` 分段：DNS / connect / appconnect / starttransfer(TTFB) / total。
- **TTFB 大而 connect 正常 → 后端慢，别怪网络**；有重传(`ss -tin`)才是网络。
- 浏览器 DevTools Waterfall 看子资源并发/Stalled；全链路 TraceID 定位哪一跳。

## 追问 5：浏览器渲染

- HTML→DOM、CSS→CSSOM、合成渲染树、Layout、Paint、Composite。
- **同步 JS 阻塞解析** → defer/async；CSS 阻塞渲染；关键渲染路径优化。
- 指标：FCP/LCP/CLS/INP（Core Web Vitals）。

## 追问 6：综合优化题"首屏很慢怎么优化"

**期望**：沿链路逐段给手段（就近/长连接/TLS 复用/CDN/h3/强缓存+hash/降 TTFB/关键渲染路径），且**每条都挂一个可量化指标**，最后强调"**先测量定位瓶颈段，再优化，别全面撒网**"。

## 评分锚点（自查）

| 段位 | 表现 |
|---|---|
| 及格 | 能按顺序说出 DNS→TCP→HTTP→渲染 主要步骤 |
| 良好 | 每段有原理（握手/证书/多路复用）+ 知道 TTFB 区分前后端 |
| 优秀 | 有**结构**、能**逐段被追问到底**、用**测量工具**定位、给**带指标**的优化、点出 h2/h3 与 HOL 的因果 |

> 记住：这题考的不是背步骤，而是**你是否真的理解每个包、每个数字从哪来、慢的时候去查哪**。能把 s1~s4 的知识在这条链上任意一点展开，就是满分。
