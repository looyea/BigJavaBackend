# 接入层限流、削峰与流量整形 · 面试题

## 题 1：常见限流算法有哪些？各有什么问题？

- 固定窗口：简单，但交界处瞬时可达 2× 阈值（临界突刺）。
- 滑动窗口：细分小格滚动统计，平滑临界，仍是计数量。
- 漏桶：恒定速率流出，强行整形、不容突发。
- 令牌桶：按速率放令牌、桶容量允许有限突发，最贴合真实流量。
- 加分：入口默认令牌桶；保护极脆弱下游用漏桶；避免裸固定窗口。

## 题 2：为什么只限全局总量不够？

- 单个用户或单个热点商品能把全部配额刷光，形同被 DoS。
- 要叠加单用户(uid 频次)、单参数(sku 热点)、单 IP 的细粒度限流 + 黑名单。
- 加分：多维分层限流（全局/接口/用户/参数）才成体系。

## 题 3：单机限流和集群限流怎么选？

- 单机：每实例各限一份，简单，但整体 = 实例数 × 阈值，扩缩容会漂移。
- 集群：用 Redis 计数或 Sentinel Token Server 统一发配额，全局精确，但依赖中心。
- 加分：中心不可用要有降级（回退单机阈值），别把限流做成新单点。

## 题 4：什么是削峰？和限流什么关系？

- 限流是"进不去就拒/等"，削峰是"先进队列、下游按能力匀速处理"。
- 写洪峰投 MQ 异步化即削峰填谷；前端排队/验证码/错峰把峰值摊平到时间轴。
- 加分：削峰队列必须有界 + 丢弃/降级策略，否则积压到 OOM。

## 题 5：限流阈值怎么定？

- 由单机与集群容量压测推导真实上限，再留安全水位。
- 拍脑袋：过高形同虚设、过低误杀正常流量。
- 加分：把"被限/被熔断"的兜底响应（缓存快照、友好提示）一并设计，体验与保护并举。

## 题 6：流量整形里的 warm-up 是解决什么？

- 冷启动/扩容新实例尚无 JIT 预热、连接池与缓存未热，直接满额接流会打崩自己。
- 令牌桶 warm-up 模式逐步放开速率，平滑冷启动抖动。
- 加分：配合 K8s readiness 探针与小流量灰度回流，让新 pod 逐步加热。
