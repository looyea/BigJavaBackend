# 接入层限流、削峰与流量整形 · 作业

### 作业 1：四种限流算法对比实验

- 目标：用数据看清各算法对"突发"的不同表现。
- 任务：分别实现固定窗口、滑动窗口、漏桶、令牌桶，以同一"交界突刺"流量回放，统计实际放行量与拒绝率；把阈值设为 100/s，制造两窗口交界的瞬时 200 请求，观察固定窗口放行超阈。
- 验收标准：能复现固定窗口临界 2×；令牌桶允许有限突发且均值受控；漏桶输出恒定。
- 参考解法要点：突发多的入口用令牌桶；保护极脆弱下游用漏桶；滑动窗口缓解临界。

### 作业 2：分层 + 集群限流落地

- 目标：在总量之外做单用户与热点参数限流，并实现全局精确。
- 任务：用 Sentinel 或 Redis 计数实现"全局 QPS + 单接口 + 单 uid 频次 + 单 sku 热点"四维限流；对比单机阈值 ×实例数 的漂移，接入集群限流（Token Server / Redis）统一配额；配黑名单拦截异常高频 IP。
- 验收标准：单个用户刷不出全局配额；扩缩容时总量稳定；热点商品有独立细粒度阈值。
- 参考解法要点：多维叠加才防绕过；集群限流精度与中心可用性需权衡降级。

### 作业 3：削峰队列 + 快速失败兜底

- 目标：把入口挡不住的洪峰安全地缓冲并匀速处理。
- 任务：秒杀写请求投 MQ 由下游匀速消费；前端加排队/验证码错峰；设置队列容量上限与超限丢弃/友好降级；被限/被熔断返回缓存快照或"排队中"提示。
- 验收标准：过载时系统快速失败而非雪崩；队列不无限增长；被限请求有兜底响应体验。
- 参考解法要点：限流—熔断—降级成套；阈值取自容量压测结论，不拍脑袋。
