# 高并发三大原则与容量模型 · 作业

## 作业 1：把一个有状态接口改造成无状态

- 目标：消除会话粘滞与本地状态，让实例可水平替换。
- 任务：把一个"把购物车存进程内 Map + 依赖 session 粘滞"的接口，改造为购物车状态外置到 Redis（key=用户/设备）、鉴权走无状态 Token；说明改造后如何做滚动发布与水平扩容。
- 验收标准：任一实例都能处理任一用户的请求、去掉会话粘滞配置；扩容只需加实例；宕机一台不丢购物车状态。
- 参考解法要点：状态外置是无状态化的关键，进程内只留可重建的计算态。

## 作业 2：用 Little 定律做容量测算并压测校准

- 目标：从 QPS/RT 推导并发与实例数，并用压测找拐点。
- 任务：给定目标峰值 QPS 与 P99 RT 预算，用 L=λ×W 估算稳态并发，折算所需实例数与线程池/连接池上限（留安全水位与故障接管余量）；再设计阶梯压测，记录吞吐上升过程中 P99 的劣化点，验证/修正估算。
- 验收标准：给出"估算值 vs 压测拐点"的对比与差异解释；线程池/连接池不是拍脑袋大数，而与并发测算挂钩。
- 参考解法要点：估算定数量级、压测定拐点；关注 IO 等待对 W 的贡献。

## 作业 3：为读多写少接口设计多级缓存 + 异步写

- 目标：把读前移、把非关键写后置。
- 任务：为一个商品详情接口设计本地缓存(Caffeine)+分布式缓存(Redis)+回源 DB 的多级读路径（含失效策略）；把"浏览计数/埋点/推荐特征更新"改为 MQ 异步处理，主链路只保留必要同步读。
- 验收标准：命中缓存时 RT 显著下降、DB 读压力受控；异步链路失败不影响主流程但有补偿；能说明各层缓存的一致性与击穿/雪崩防护。
- 参考解法要点：读走缓存分层、写走异步解耦，二者共同支撑高并发而保护后端。
