# 池化、异步化与削峰填谷

> 本节难度：★★★★☆
> 本节重要性：★★★★★
> 学习产出：能讲清高并发降本的三板斧——**池化**（连接/线程/对象复用，把"每次新建"的昂贵初始化摊薄）、**异步化**（把非关键路径从同步链路剥离，用线程池/MQ/回调缩短响应、隔离慢操作）、**削峰填谷**（用队列缓冲突发流量，让后端按自身吞吐平稳消费）；能为线程池正确设置核心参数并解释拒绝策略，能用 MQ 做解耦与峰值缓冲同时守住"最终一致"，并识破"线程池参数拍脑袋导致 OOM/打满""异步吞异常导致请求假成功""无界队列把内存当缓冲最终雪崩"等坑。

## 一、池化：把"新建成本"摊薄成"复用成本"

```text
图目的：昂贵的是初始化，不是使用
连接池(DB/Redis/HTTP)：TCP 握手 + 认证 + 建会话很贵，池化后借出/归还不重建
线程池：线程创建/销毁与栈内存有成本，复用固定 worker 执行排队任务
对象池(重量对象)：如 Netty ByteBuf、DB Statement，减少 GC 与分配
核心矛盾：池太小→排队拖慢；池太大→上下文切换/内存开销反噬，须按压测定容
```

```java
// 目的：线程池按任务性质设定参数，而不是一律 Executors 快捷方法
ThreadPoolExecutor pool = new ThreadPoolExecutor(
    16,                                  // 说明：core——常驻线程，按并发到达率×单任务耗时估算
    32,                                  // 结果：max——突发可扩到的上限，非 CPU 密集才有意义
    60L, TimeUnit.SECONDS,               // 说明：空闲超出 core 的线程回收时间
    new ArrayBlockingQueue<>(200),       // 结果：有界队列！无界队列会让 max 失效并把内存撑爆 ❌
    new NamedThreadFactory("order-async"),
    new ThreadPoolExecutor.CallerRunsPolicy());  // 拒绝策略：队列满时回压调用线程，而非静默丢弃
// 反例：Executors.newFixedThreadPool 用 Integer.MAX_VALUE 无界队列 ❌ 积压任务 OOM
// 反例：CPU 密集却把 max 设到上千 ❌ 线程越多上下文切换越重，吞吐反降
```

## 二、异步化：把慢的、非关键的从主链路剥离

```text
图目的：用户只等"必须同步确认"的那部分
同步链路：下单必须原子扣库存、返回订单号——这些不能异步
异步剥离：发短信/邮件、积分累积、数据大盘、生成分享海报——丢进 MQ/线程池后台做
收益：接口 RT 从"所有步骤之和"降到"关键步骤"，且慢操作失败不阻塞主流程
代价：结果最终一致而非即时，前端要接受"处理中"状态，需幂等与补偿
```

```java
// 目的：主链路只留关键操作，非关键副作用异步化并防吞异常
orderService.deductAndCreate(req);                 // 结果：同步——扣减+建单必须即时确认
mqProducer.send(new OrderCreatedEvent(orderId));   // 说明：通知/积分/报表改为事件驱动，消费端各自幂等
// 反例：@Async 方法里抛异常无人 catch，主流程以为成功 ❌ 副作用静默丢失
// 反例：同步链路里串行调用短信+风控+推荐三个远程接口 ❌ 任一超时拖垮整条 RT
```

## 三、削峰填谷：用队列把"突发"熨平为"平稳"

```text
图目的：入口洪峰不直接砸穿后端
削峰：秒杀 10 万请求先入 MQ，后端按 DB 能承受的 2000 TPS 匀速消费，多出的排队而非报错
填谷：低谷时消费端把积压吃掉，资源利用率拉平
前置：入口必须有总量闸(限流)+ 队列必须有界 + 消费者要能水平扩
本质：用"时间换空间"，把瞬时容量转成可承受的持续吞吐
```

- 典型组合：网关限流挡住超量 → Redis 预扣快速拒绝无库存请求 → 通过的进 MQ 缓冲 → 消费端匀速写库，DB 只看到平稳流量。

## 四、坑与边界

- 无界队列不是缓冲是炸弹：容量再大也有上限，突发一旦超过就是 OOM 与全链路雪崩，坚持**有界 + 拒绝策略**。
- 异步不等于免费：线程上下文切换、MQ 网络与存储都有成本，过度异步会让排障、事务、顺序都变难。
- 削峰要守住用户体验底线：对"必须即时知道结果"的操作（支付、下单成功与否）不能一味排队假装成功。
