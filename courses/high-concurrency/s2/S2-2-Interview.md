# 池化、异步化与削峰填谷 · 面试题

## 题 1：为什么需要连接池和线程池？池化的本质是什么？

- 本质是把昂贵的初始化（TCP 握手、认证、建线程、栈分配）从"每次请求"摊薄为"一次性创建 + 反复借还"。
- 复用降低创建/销毁开销与 GC 压力，也让并发资源可控（不会瞬间建爆）。
- 加分：指出池太小会排队拖慢、池太大会因上下文切换与内存反噬吞吐，容量必须按压测定。

## 题 2：说说 ThreadPoolExecutor 的执行流程和七个参数。

- 流程：任务来 → core 未满建核心线程 → core 满进队列 → 队列满扩到 max → 还满走拒绝策略。
- 参数：corePoolSize、maximumPoolSize、keepAlive、unit、workQueue、threadFactory、handler。
- 常见坑：`newFixedThreadPool` 用无界队列，max 失效且积压 OOM；`newCachedThreadPool` max 近乎无限易建爆线程。
- 加分：强调"先入队后扩容 max"这个反直觉顺序，解释为何固定大小池其实用 LinkedBlockingQueue。

## 题 3：线程池满了有哪些拒绝策略？生产上你怎么选？

- JDK 四种：AbortPolicy 抛异常、CallerRunsPolicy 回压调用线程、DiscardPolicy 静默丢、DiscardOldestPolicy 丢最老。
- 关键业务：要么快速失败并告警、要么 CallerRuns 回压，绝不静默丢弃。
- 自定义：落库/入死信 + 告警 + 降级，保证不丢。
- 加分：结合队列有界性谈"回压即限流"，把线程池饱和当作系统自我保护信号。

## 题 4：什么该异步、什么不该？异步化有哪些代价？

- 该异步：非关键副作用——通知、积分、报表、风控后置。不该异步：需即时确认结果的核心操作（扣库存、支付结论）。
- 收益是缩短主链路 RT、隔离慢依赖；代价是结果变最终一致、需接受"处理中"状态。
- 坑：@Async 吞异常导致"假成功"、顺序与事务边界被打破、排障变难。
- 加分：给出防吞异常手段（回调/UncaughtExceptionHandler/死信）与消费幂等设计。

## 题 5：MQ 怎么做削峰填谷？为什么说它是"时间换空间"？

- 洪峰先进队列缓冲，后端按自身可承受速率匀速消费，把瞬时容量转成可持续的吞吐。
- "时间换空间"：宁可让请求多等一会排队，也不用无限内存/连接硬扛峰值。
- 前提三件套：入口限流 + 有界队列 + 可水平扩的消费者。
- 加分：说明积压时如何扩容加速消化，以及"须即时反馈"的请求为何不能一味假装排队。

## 题 6：无界队列有什么问题？如何给缓冲定容？

- 无界队列让 max 参数失效，生产快于消费时积压撑爆内存 → OOM 与全链路雪崩。
- 定容思路：容量 = 可接受的积压时长 × 消费速率；超过就走拒绝/回压而非继续堆。
- 加分：区分"内存队列(进程内、有界防 OOM)"与"MQ(持久化、跨进程、真正削峰)"的适用边界。
