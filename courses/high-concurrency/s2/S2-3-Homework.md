# 容量规划、压测与线性扩展验证 · 作业

### 作业 1：Little 定律反推 + 逐层折算

- 目标：为一个服务从目标 QPS 反推线程/连接/实例规模。
- 任务：给定目标峰值 5000 QPS、平均 RT 40ms、单请求消耗 CPU ~8ms，用 Little 定律估并发，按核数折算实例数，并核对下游 DB 连接上限是否匹配；预留 30% 水位给出最终配置。
- 验收标准：能指出瓶颈层（应用 vs DB 连接）；结论含安全水位；不是只算机器数。
- 参考解法要点：短板决定容量；应用并发必须与 DB 连接池、下游能力对齐。

### 作业 2：找吞吐拐点与长尾

- 目标：用负载测试定位容量拐点，读懂分布而非平均值。
- 任务：以固定步长递增并发跑压测，画 TPS–并发、P99–并发曲线，标出拐点；在拐点附近观察 GC、线程池队列、锁等待对 P99 的影响。
- 验收标准：能指出拐点并发与对应容量；能解释 P99 在拐点后骤升的原因；不拿平均 RT 下结论。
- 参考解法要点：拐点是稳定承载上限；长尾劣化往往先于平均体现，盯 P99/P999。

### 作业 3：全链路影子压测演练

- 目标：在不污染真实数据前提下演练大促链路。
- 任务：给压测流量打染色 tag 并全链路透传，命中时写影子库/影子表、走影子缓存 key、第三方用 Mock；压测后整体清理并核对真实表零写入。
- 验收标准：真实数据零污染；影子隔离覆盖 DB/缓存/MQ/第三方无死角；能定位任何一处漏染色的资损风险。
- 参考解法要点：隔离验证是上线前置；把测出的容量交给接入层限流做阈值。
