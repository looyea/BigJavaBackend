# 热点治理与读写分离 · 小测

> 本卷满分 100 分：单选 7×6=42，多选 2×9=18，简答 1×40=40。

### 1. 高并发系统里"热点"最本质的危害是（6分）

- A. 整体 CPU 利用率过高
- B. 海量请求压在一个无法再分的单点上（单分片/单行锁）
- C. 磁盘空间不足
- D. 网络带宽整体饱和

> 答案：B
> 解析：热点不是总量扛不住，而是总量集中在单 Key/单行/单账户这类不可再分的点，导致单分片网卡饱和或行锁串行，其余资源却空闲。

### 2. 秒杀中"同一库存行被高频更新导致 TPS 被锁死"属于哪类热点（6分）

- A. 读热点（热 Key）
- B. 写热点（热行）
- C. 网络热点
- D. 缓存热点

> 答案：B
> 解析：单 SKU 库存行的 update 会被行锁串行化，是典型写热点（热行），治理靠分桶打散而非加缓存。

### 3. 关于本地缓存(Caffeine)与分布式缓存(Redis)的关系，正确的是（6分）

- A. 本地缓存能跨实例共享，Redis 不能
- B. 多级缓存中 L1 本地先挡最热 Key，未命中再走 L2 Redis，最后回源 DB
- C. 有了 Redis 就不需要本地缓存
- D. 本地缓存容量不受单机内存限制

> 答案：B
> 解析：L1 进程内纳秒级、扛最热 Key 第一层但每台各存一份需注意容量；L2 Redis 跨实例共享；DB 只接长尾冷数据。

### 4. 读写分离后"下单成功却查不到刚下的订单"，根本原因是（6分）

- A. 缓存穿透
- B. 主从复制延迟，读请求打到了尚未同步的从库
- C. 行锁等待超时
- D. 分片路由错误

> 答案：B
> 解析：异步复制存在延迟，写主库后立读从库可能读到旧值（读不到自己的写），需强制走主/会话一致性/写后回填缓存遮蔽延迟。

### 5. 对"平台商户账户被高频记账"这一写热点，最合适的治理手段是（6分）

- A. 加更多从库
- B. 本地/内存累加、按阈值合并成一笔批量更新主账（热点账户合并）
- C. 提高 Redis 过期时间
- D. 把账户拆成更多读副本

> 答案：B
> 解析：热点账户的单行 update 排队是吞吐瓶颈，靠"增量累加+定期合并快照"把高频小更新降频为批量写。

### 6. 缓存与数据库一致性，业界推荐的基础写法是（6分）

- A. 先写缓存再写数据库
- B. Cache-Aside：更新 DB 后删除缓存（而非直接写缓存）
- C. 只更新缓存不更新 DB
- D. 双写且不加任何顺序约束

> 答案：B
> 解析：Cache-Aside + 更新后删除，配合 binlog(CDC) 异步失效或延迟双删，收敛并发读回填旧值导致的双写不一致。

### 7. "热 Key 过期瞬间海量请求同时穿透到 DB"描述的是（6分）

- A. 缓存雪崩（大量 Key 同时过期）
- B. 缓存击穿（单个热点 Key 失效）
- C. 缓存穿透（查不存在的数据）
- D. 主从延迟

> 答案：B
> 解析：击穿是单个热 Key 过期瞬间被并发击穿到 DB，对策是互斥重建或逻辑过期/永不过期+后台刷新；雪崩是大批 Key 同刻过期，靠过期时间打散。

### 8.（多选）以下哪些属于"读热点"的有效治理手段（9分）

- A. 本地+多级缓存承接最热 Key
- B. 静态化 + CDN 动静分离，把不变内容从服务端剥走
- C. 给单行库存加更多索引
- D. 热 Key 探测后打散到多个分片

> 答案：A、B、D
> 解析：读热点靠缓存拦截、动静分离卸载、热 Key 打散分摊；C 是写/查询优化范畴，不解决热 Key 集中在单分片的读压力。

### 9.（多选）关于主从延迟带来的"读不到刚写"，下列对策合理的有（9分）

- A. 写后一段时间内该会话强制读主（会话一致性）
- B. 关键读直接走主库
- C. 写完立即把最新值回填缓存，用缓存遮蔽从库延迟
- D. 让所有读都强制走最慢的从库

> 答案：A、B、C
> 解析：会话一致性/关键读走主/写后回填缓存都能规避读到旧值；D 会放大延迟问题，与目标相反。

### 10. 结合一个具体业务（如爆款商品详情读 + 秒杀库存写），说明你会如何分别定位并治理其读热点与写热点，并解释读写分离在该场景下要注意什么。（40分）

> 参考答案：
- 要点1：识别热点类型——商品详情是被海量读的单个热 Key（读热点），秒杀库存是被高频 update 的单行（写热点/热行），二者手段不同（10分）
- 要点2：读热点治理——本地 Caffeine + Redis 多级缓存承接热 Key，静态化/CDN 动静分离，探测到超热 Key 后打散到多分片或多副本，并用互斥/逻辑过期防击穿（10分）
- 要点3：写热点治理——库存行拆成 N 个子桶分摊行锁争抢（分桶预扣），必要时热点累加+异步合并落库，把单行 update 降频（10分）
- 要点4：读写分离注意——详情读可打从库，但下单/扣减后涉及"写后立读"的关键路径要走主或写后回填缓存保证会话一致性，双写场景用 Cache-Aside 更新后删除+binlog 失效保证最终一致（10分）
