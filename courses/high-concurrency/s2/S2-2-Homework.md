# 池化、异步化与削峰填谷 · 作业

### 作业 1：为线程池正确定容并验证拒绝策略

- 目标：理解 core/max/队列/拒绝策略四者的协作顺序，摆脱 Executors 快捷方法。
- 任务：用一个 IO 密集型接口任务，分别用 `Executors.newFixedThreadPool`（无界队列）与手写 `ThreadPoolExecutor`（有界队列 + CallerRunsPolicy）压测；观察在任务生产快于消费时两者的内存与延迟表现。
- 验收标准：能画出"先 core → 入队 → 扩到 max → 拒绝"的时序，并展示无界版本积压导致内存上涨/延迟飙升、有界版本被回压而不 OOM。
- 参考解法要点：按压测得到到达率×RT 估 core，max 留突发余量，队列容量按可容忍积压设定；拒绝策略选回压或快速失败+告警。

### 作业 2：把一条同步链路改造为"关键同步 + 非关键异步"

- 目标：缩短主链路 RT，同时守住正确性。
- 任务：给定"下单 = 扣库存 + 建订单 + 发短信 + 加积分 + 刷大盘"，把后三步改为发领域事件、消费端异步处理；为异步任务加异常回调，避免吞异常。
- 验收标准：主链路 RT 明显下降；模拟短信服务超时不影响下单成功；异步失败能被捕获、进死信/重试且不产生重复积分（幂等）。
- 参考解法要点：主链路只保留需即时确认的操作；副作用走 MQ 事件；消费端幂等（唯一键/去重表）；异常走回调 + 死信队列，绝不静默丢弃。

### 作业 3：设计一个削峰填谷的下单缓冲方案

- 目标：用队列把瞬时洪峰熨平为后端可承受的持续吞吐。
- 任务：为秒杀/大促下单设计"网关限流 → Redis 预扣 → MQ 缓冲 → 消费端匀速写库"链路，队列有界、消费者可水平扩，并对"须即时反馈结果"的请求设计降级返回。
- 验收标准：压测下 DB 只看到平稳写入速率；超量请求被限流或快速拒绝而非打崩 DB；积压可被扩容消费者逐步消化且不丢单。
- 参考解法要点：限流做总量闸、预扣做快速失败、MQ 做时间换空间；对下单成功与否需即时反馈的，用"排队中/稍后通知"体验兜底而非假装成功。
