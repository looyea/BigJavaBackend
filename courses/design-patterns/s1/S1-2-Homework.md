# 创建型与结构型模式 · 作业题

> 本节作业 3 题：一次拷贝陷阱实验、一组结构型实战、一轮仓库模式考古。

## 作业 1：clone 陷阱复现与三种"复制"方案对比（动手）

给一个含 `List<Item>` 与 `LocalDateTime` 字段的订单草稿类：

1. 用 `clone()` 得到"副本"后修改子列表，证明原件被改（截图断言失败输出）；
2. 三种修复各实现一遍：手写深拷贝（递归 clone）、拷贝构造器（内部 `new ArrayList<>(...)`）、字段不可变化（`List.copyOf` + record）；
3. JMH 或简单计时对比三方案复制 10 万次的耗时与代码行数；
4. 结论：为什么"不可变 + 需要时再拷贝"通常优于"到处 clone"。

**验收标准**：陷阱复现测试 + 三方案基准表 + 一段"团队规范建议"（禁止直接使用 Object.clone 的理由）。

## 作业 2：用桥接+适配器+装饰器各解决一个真实问题（动手）

三个小题：

1. **桥接**：设计"文件存储渠道（头像/附件/报表）× 后端（本地磁盘/MinIO/OSS）"的结构，用新增一个假想后端 `FakeCloudProvider`（写内存 Map 即可）验证"渠道类零改动"；
2. **适配器**：把一个第三方 SDK 的 `LegacySmsClient.sendMobileMessage(String, String[])` 适配到你系统的 `SmsProvider.send(phone, text)` 接口，写两个契约测试（参数映射、异常翻译）；
3. **装饰器**：给 `SmsProvider` 加 `RateLimitedSms`（每号每分钟 1 条）与 `RetryingSms`（失败重试一次）两个装饰器，组合出"限流+重试"四种叠法并测试顺序差异（先限流还是先重试，行为有何不同？）。

**验收标准**：桥接部分有 git diff 证据；装饰器部分能答出"重试包在限流外面会疯狂触发限流异常"这类顺序语义分析。

## 作业 3：仓库模式考古（分析）

在任一开源 Java 项目（Spring Boot 应用、mall、ruoyi 均可）：

- 找出全部 `XxxFactory / XxxBuilder / XxxAdapter / XxxWrapper / XxxProxy` 命名的类，逐个判定其真实模式（允许判为"名不副实"——如 Factory 里只有一个 `new`）；
- 对每个模式类回答：没有它时会怎么写？该写法差多少（引用具体调用点数）；
- 特别检查：有没有"手写单例 + Spring bean"双轨并存的类（搜 `private static.*instance` 与 `@Component` 同现）。

**交付物**：考古表（类 × 声称模式 × 实际模式 × 存废建议），至少包含 2 个"建议删除该抽象"与 2 个"抽象不足需补"的案例。

**提示**：判定标准来自本课——接口变了没（适配器）？谁决定 new（工厂）？值不值一个类（过度抽象）？
