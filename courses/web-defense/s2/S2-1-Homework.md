# 文件上传、SSRF 与命令注入 · 作业

### 作业 1：做一个"打不穿"的文件上传

- 目标：实现多重校验 + 存储/执行隔离的上传，绕过尝试全部失败。
- 任务：白名单校验真实 MIME/魔数（非后缀）、限大小、`UUID` 随机重命名、存到与 Web 根隔离且关脚本执行的目录（或对象存储）、图片二次转码。构造攻击样本验证：`.jpg.jsp`、双扩展、含 webshell 的"图片"、`../../evil.jsp` 路径穿越名，均被拒或失效。
- 验收标准：只信后缀的绕过不成立；上传目录不可执行脚本；随机名使覆盖/穿越无效；恶意载荷被转码剥离。
- 参考解法要点：Content-Disposition + 正确 Content-Type 下载防解析成 HTML。

### 作业 2：SSRF 出网管控

- 目标：让服务端抓取用户 URL 时无法够到内网/元数据。
- 任务：实现校验：解析 URL → host 解析成 IP → 拦私网/回环/链路本地（含十进制、IPv6 归一化）、只允 http/https、关闭自动跳转或对每一跳复检、设短超时与响应体上限、模拟 DNS 重绑定防护。用 `http://169.254.169.254`、`http://127.0.0.1:8080`、302 跳内网等用例验证被拦。
- 验收标准：上述绕过用例全部被拒；协议/网段白名单生效；超时与体积限制兜底存在。
- 参考解法要点：服务账号最小权限；解析与连接目标一致化防 TOCTOU 式重绑定。

### 作业 3：安全的外部命令调用重构

- 目标：把一个命令注入点改造为无 shell 解析的安全调用。
- 任务：给出问题代码 `Runtime.exec("convert " + name + " out.png")`，重构为 `ProcessBuilder` 参数数组 + `sanitizeName` 白名单（拒绝 `;|&../` 空格），或改用纯 Java 图像库彻底去掉 exec。构造 `name = "a.png; curl 内网"` 证明注入失效。
- 验收标准：元字符不再被 shell 执行；非法名被白名单拒绝；能不用 exec 就不用。
- 参考解法要点：黑名单/编码不可靠；从"能执行什么"源头收窄。
