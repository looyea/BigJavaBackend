# 安全开发生命周期与依赖漏洞治理 · 作业

### 作业 1：给项目加一道 SCA 门禁

- 目标：让依赖高危漏洞在合入/发布前被自动拦下。
- 任务：在 CI 里接入 OWASP dependency-check（或等价工具），设置 `--failBuildOnCVSS 7` 阻断，扫描覆盖传递依赖，产出 SBOM。故意引入一个含已知 CVE 的旧版本依赖，验证流水线变红并定位到具体 jar。
- 验收标准：高危依赖能阻断构建；报告含组件、版本、CVE、CVSS；传递依赖也被扫出。
- 参考解法要点：常态化每次构建而非发版前手扫；把报告归档供应急盘查。

### 作业 2：一次威胁建模演练

- 目标：用 STRIDE 对一个真实接口/流程做设计期安全评审。
- 任务：选一条链路（如"文件上传 + 第三方回调"），列出资产与数据分级、入口与信任边界，按 STRIDE 六类逐项枚举滥用路径，给出缓解措施并标注落到 SDL 哪个阶段（编码/测试/运行）。
- 验收标准：至少覆盖欺骗、篡改、信息泄露、提权四类威胁；每条威胁有对应缓解；识别出的问题能关联到具体攻击面小节（SSRF/越权/CSRF）。
- 参考解法要点：建模在前、编码在后，体现"安全左移"。

### 作业 3：Log4Shell 式应急桌面推演

- 目标：验证"SBOM + 分级流程"能否在真实 0day 下快速止血。
- 任务：模拟某天爆出某常用组件 RCE，走一遍流程：用 SBOM 秒级盘出受影响服务与版本 → 定级 → 先上临时缓解（升级/删类/关特性/WAF/网络隔离）→ 排期彻底修复 → 回归验证 → 复盘。输出时间线与决策记录。
- 验收标准：影响面盘点依赖 SBOM 而非人工回忆；有明确"缓解优先"动作而非干等补丁；复盘沉淀出新规范/门禁项。
- 参考解法要点：强调应急期间没有缓解预案是最大坑；把复盘固化进 CI 防复发。
