# 文件上传、SSRF 与命令注入 · 小测

> 本卷满分 100 分：单选 7×6=42，多选 2×9=18，简答 1×40=40。

### 1. 文件上传校验最可靠的做法是（6分）

- A. 只判断文件名 endsWith(".jpg")
- B. 读取魔数/真实 MIME 做白名单校验，并限制大小
- C. 信任前端传的 Content-Type
- D. 只在前端 JS 校验

> 答案：B
> 解析：后缀、前端声明都可伪造；只有探测真实内容类型 + 白名单才能挡住 `.jpg.jsp`、双扩展绕过。

### 2. 上传文件的存储应如何隔离以防线被 getshell？（6分）

- A. 存进 src/main/webapp 并保留原文件名
- B. 存到与 Web 根隔离的目录/对象存储，关闭脚本执行，随机重命名
- C. 存到临时目录不管
- D. 存进 classpath

> 答案：B
> 解析：放可执行 Web 根 + 原名会被当 JSP 执行；隔离目录、关执行、随机名防路径穿越与覆盖是关键。

### 3. SSRF 攻击的本质是（6分）

- A. 前端脚本注入
- B. 诱导服务端去访问攻击者指定的地址（常是内网/云元数据）
- C. 数据库拖库
- D. 密码爆破

> 答案：B
> 解析：SSRF 借服务端可信身份去够内网资源，如 127.0.0.1、169.254.169.254 元数据、内部服务。

### 4. 防御 SSRF 的核心措施是（6分）

- A. 黑名单禁掉 "localhost" 即可
- B. URL 解析成 IP 后按白名单网段/域名拦截私网/回环/链路本地，并限制协议、防跳转与 DNS 重绑定
- C. 只校验是不是 http 开头
- D. 不给超时

> 答案：B
> 解析：只黑 localhost 会漏 127.0.0.1/十进制/IPv6；须在解析后按 IP 段拦，并对每一跳复检、限协议。

### 5. `Runtime.exec("convert " + userInput)` 的主要风险是（6分）

- A. 性能差
- B. 用户输入含 `;`/`|` 等 shell 元字符造成命令注入
- C. 编码问题
- D. 内存泄漏

> 答案：B
> 解析：把输入拼进命令、经 shell 解析元字符即可注入任意命令；应用参数数组或库 API、白名单过滤。

### 6. 下列关于命令执行的正确实践是（6分）

- A. 用黑名单删除特殊字符
- B. 优先用库 API 替代 exec；必须 exec 时用参数数组 + 白名单枚举命令与参数
- C. Base64 编码输入就安全
- D. 拼进 `sh -c` 更灵活

> 答案：B
> 解析：黑名单/编码都能绕过；参数数组不经 shell 解析、白名单从源头限定可执行内容才稳。

### 7. 云环境里 SSRF 尤其要重点防护的目标地址是（6分）

- A. 公网 CDN
- B. 169.254.169.254 元数据服务
- C. 静态资源站
- D. DNS 服务器

> 答案：B
> 解析：链路本地元数据接口常泄露临时凭证/实例信息，SSRF 打它危害极大，应默认屏蔽。

### 8.（多选）文件上传应组合采用的防御有（9分）

- A. 真实类型/魔数白名单校验
- B. 随机重命名防路径穿越与覆盖
- C. 存储与 Web 执行隔离、关脚本执行
- D. 只信文件后缀

> 答案：A、B、C
> 解析：D 是可被绕过的错误做法；A/B/C + 大小限制、图片转码构成纵深。

### 9.（多选）SSRF 常见绕过手段（需专门防）的有（9分）

- A. DNS 重绑定（解析后再变内网 IP）
- B. 302 跳转引导到内网
- C. 十进制/IPv6 混淆的回环地址
- D. 使用 HTTPS 协议

> 答案：A、B、C
> 解析：D 本身不是绕过手段；A/B/C 都要求"解析后复检、每跳复检、多形态 IP 归一化判断"。

### 10. 为一个"用户提交 URL 让服务端抓取预览图 + 支持文件上传 + 调用图像转换命令"的功能做安全设计。请给出方案。（40分）

> 参考答案：
- 要点1：上传——魔数/真实 MIME 白名单 + 限大小 + 随机重命名 + 存隔离目录/对象存储关执行 + 图片二次转码，杜绝 webapp 根与原名（10分）
- 要点2：SSRF——URL 解析成 IP 后按白名单网段拦私网/回环/链路本地，禁 file/gopher 等协议，每跳复检防 302、防 DNS 重绑定，短超时+限响应体，屏蔽元数据地址（10分）
- 要点3：命令执行——优先库 API，必须 exec 用参数数组 + 白名单枚举命令/参数，绝不 `sh -c`+拼接、不靠黑名单/编码（10分）
- 要点4：底线——纵深防御叠加 + 服务账号最小权限，任一层被绕过仍有下一层；日志审计异常目标与失败尝试（10分）
