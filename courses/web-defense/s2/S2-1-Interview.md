# 文件上传、SSRF 与命令注入 · 面试题

## 题 1：文件上传怎么防才安全？

- 多重校验：真实 MIME/魔数白名单、限大小、随机重命名；存储与执行隔离（Web 根外、关脚本执行、或对象存储）、图片二次转码。
- 只信后缀/前端声明都是错的。
- 加分：讲 `.jpg.jsp`、双扩展、路径穿越 `../` 这些绕过与对应防御。

## 题 2：什么叫 SSRF？怎么防？

- 诱导服务端去访问其内网/云元数据地址。
- URL 解析成 IP 后按白名单网段拦私网/回环/链路本地，限协议、关跳转或每跳复检、短超时+限响应体、屏蔽元数据地址。
- 加分：点出 DNS 重绑定、302 跳转、十进制/IPv6 混淆这些绕过。

## 题 3：为什么黑名单拦 SSRF 不够？

- 黑名单永远列不全：`localhost` 挡了还有 `127.0.0.1`、`0x7f...`、IPv6 `::1`、重绑定。
- 应解析出真实 IP 后用"允许集合"判断。
- 加分：解析与连接要一致化，防 TOCTOU 式重绑定。

## 题 4：`Runtime.exec` 拼用户输入有什么问题？

- 输入含 `; | & &&` 等被 shell 当元字符执行 → 命令注入。
- 用参数数组（ProcessBuilder）不经 shell，或干脆用库 API 替代 exec，命令/参数白名单枚举。
- 加分：强调黑名单过滤/编码（Base64）都可被绕过。

## 题 5：上传目录为什么不能放 Web 根？

- 放可执行 Web 根且保留原名，恶意 `.jsp` 会被容器当脚本执行 → getshell。
- 应存隔离目录/对象存储、关脚本执行、随机名。
- 加分：下载侧用 Content-Disposition + 正确 Content-Type 防被解析成 HTML 触发 XSS。

## 题 6：这类攻击面防御的共同原则是什么？

- 纵深防御 + 白名单优先 + 最小权限：校验、隔离、限制叠加，任一层被破仍有下一层。
- 服务账号、网络出网、执行能力都收窄到必要范围。
- 加分：把这些检查固化进 CI/SDL（与依赖漏洞治理小节呼应），别靠人工临时想起。
