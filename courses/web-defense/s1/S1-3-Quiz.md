# 反序列化、越权与业务逻辑漏洞 · 小测

## 一、单项选择题（每题 6 分，共 42 分）

### 1. Java 原生反序列化危险的根本原因是？（6分）

- A. 太慢
- B. readObject 依据流中元数据重建对象并可能触发 gadget 链执行任意代码
- C. 占用内存
- D. 不兼容 JSON

> 答案：B
> 解析：把不可信字节流当"对象重建指令"执行，classpath 有可用 gadget 即 RCE，无需业务漏洞配合。

### 2. 防反序列化攻击优先推荐的替代方案是？（6分）

- A. 把对象转成字符串再 eval
- B. 改用 JSON/Protobuf 等数据格式，只映射到指定类型
- C. 关闭防火墙
- D. 加大堆内存

> 答案：B
> 解析：数据格式不做任意类实例化，从根上去掉 readObject 魔法；必须用原生序列化时再配 ObjectInputFilter 白名单。

### 3. 水平越权的典型特征是？（6分）

- A. 普通用户调到管理员接口
- B. 同权限用户通过改 id 访问到他人数据
- C. 密码明文存储
- D. SQL 注入

> 答案：B
> 解析：只验"登录了"没验"这条资源是不是你的"；A 描述的是垂直越权。

### 4. 防御水平越权最可靠的工程做法是？（6分）

- A. 每个接口自觉写 if 判断 userId
- B. 把归属条件（owner_id/tenant_id）下推为数据访问层统一查询条件
- C. 前端不显示别人的数据
- D. 只记录日志

> 答案：B
> 解析：统一拦截/查询条件下推避免"某处忘写 if 即破防"，前端隐藏不是安全。

### 5. 越权查询查不到他人资源时，返回什么更能避免信息泄漏？（6分）

- A. 500
- B. 403 并说明"这不是你的资源"
- C. 404（资源不存在）
- D. 200 空对象并提示无权

> 答案：C
> 解析：403/明确提示会泄漏"该 id 确实存在"的存在性信息，404 对越权与不存在给同样响应。

### 6. "先 select 判断状态再 update" 的用券逻辑的主要问题？（6分）

- A. 太简洁
- B. 读-改-写竞态（TOCTOU），并发两个请求都通过校验导致重复核销
- C. 无法记日志
- D. 违反命名规范

> 答案：B
> 解析：应把判断下推进带条件的原子 UPDATE，用 affected rows 判定成败，杜绝竞态窗口。

### 7. 以下哪项不属于业务逻辑漏洞的常见被薅点？（6分）

- A. 支付金额改负数
- B. 优惠券叠加绕过互斥
- C. 验证码无限重发
- D. PreparedStatement 参数化查询

> 答案：D
> 解析：D 是防注入手段；A/B/C 都是"没特征码、扫不出来、靠设计期审视滥用路径"的逻辑漏洞。

## 二、多项选择题（每题 9 分，共 18 分）

### 8. 关于反序列化治理，正确的有？（多选）（9分）

- A. 升级/移除含 gadget 的依赖（如老版 commons-collections）
- B. 必须用原生序列化时设 ObjectInputFilter 白名单且默认拒绝
- C. JNDI 注入与反序列化同源，属不可信输入触发远程类加载
- D. 只要走 HTTPS 就不用管反序列化入口

> 答案：A、B、C
> 解析：D 错——HTTPS 只保护传输，服务端信任内部/消息里的字节流照样中招，信任边界要按来源判。

### 9. 守住业务不变式的通用手段有哪些？（多选）（9分）

- A. 关键金额/数量以服务端重算为准，不信前端传值
- B. 用唯一流水/幂等键防重复
- C. 状态流转用原子操作 + 条件更新
- D. 把校验逻辑全放前端

> 答案：A、B、C
> 解析：D 反例——前端可绕过，业务裁决必须在服务端；三件套"服务端为准 + 原子 + 幂等"是通用防线。

## 三、简答题（40 分）

### 10. 秒杀下单接口 `POST /seckill?skuId=&couponId=`，请以架构师视角列出会防的越权与逻辑滥用点及对策。（40分）

> 参考答案：
- 归属：下单人从登录态取，绝不接受前端传 userId（防垂直/水平冒用）。
- 券越权：核销券校验其 owner==当前用户 且状态 UNUSED，条件 UPDATE 原子占用防并发双花。
- 库存：DB 条件扣减 stock>=n 防超卖；不"查了再扣"。
- 价格：金额服务端按活动价重算，拒绝前端传价、防改负/改 0。
- 幂等：唯一订单流水 + 去重，防重放/连点重复下单。
- 回调/限流：验签去重 + 按用户/设备频控，防脚本薅。

> 解析：能覆盖"归属、原子、服务端重算、幂等、频控"且不信任任何前端传值即达生产水准。
