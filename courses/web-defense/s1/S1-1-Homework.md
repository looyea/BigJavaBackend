# 注入原理与预处理防御 · 作业

## 作业 1：把一段拼接 SQL 改造成安全的

- **目标**：亲手把 `${}` 拼接迁到 `#{}` + 白名单。
- **任务**：给出一个用 `${}` 拼 username、`${}` 拼 ORDER BY 列的 MyBatis 查询，先写一个注入 payload（如 `' OR '1'='1`）证明能拖全表；再把值条件改 `#{}`、把排序列改白名单枚举，重跑证明同一 payload 失效。
- **验收标准**：改造前 payload 返回异常数据量，改造后被当作普通值匹配 0 行 / 非法列被拒；给出前后 diff。
- **参考解法要点**：值走参数化、结构走白名单（见 [课文](S1-1-Lesson.md) 第二、三节）；对照 [MyBatis 动态 SQL](../../mybatis/s1/S1-1-Lesson.md)。

## 作业 2：NoSQL / 命令注入防御

- **目标**：把"数据当代码"的防御迁移到非 SQL 场景。
- **任务**：① 一段把前端 JSON 直接塞进 Mongo 查询的代码，构造 `{"$ne":null}` 登录绕过并修复（只取白名单字段、强类型校验）；② 一段 `Runtime.exec("convert " + file)` 命令注入，用 `../; rm -rf` 类 payload 复现后改为参数数组传参 + 文件名校验。
- **验收标准**：两类 payload 修复后均不再生效；写清各自"输入不再参与解释器语法"的原理。
- **参考解法要点**：统一心法——所有把外部输入交给"会解析语法的引擎"（SQL/Shell/LDAP/JSON 查询）的地方都要结构化传参或白名单。

## 作业 3：注入面自查清单（书面）

- **目标**：形成可复用的代码评审项。
- **任务**：为一个遗留 Java Web 项目列出注入自查清单，至少覆盖：`${}` 使用点、动态表/列/排序、字符串拼 SQL、Runtime.exec、路径拼接、反序列化入口、二阶注入；每项给"危险信号 + 正确做法 + grep/静态扫描建议"。
- **验收标准**：清单能落到具体检索词（如全局搜 `${`、`Statement`、`exec(`）；对每条给出可执行整改动作而非空泛"注意安全"。
- **参考解法要点**：把清单沉淀进 CI（Sonar/Checkstyle 自定义规则），与 [静态代码质量](../../sonar/s1/S1-1-Lesson.md) 结合做长期防回归。
