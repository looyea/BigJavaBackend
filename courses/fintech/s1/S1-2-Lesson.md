# 对账、清算与资损防控

> 本节难度：★★★★★
> 重要程度：★★★★★
> 学习产出：能搭建金融级**资金核对与结算**体系：分三层理解**对账**——账务内部**总分核对**(明细↔总账)、与**三方渠道逐笔对账**(银行/支付/银联账单)、**账实核对**(账面余额↔银行实际头寸)；掌握**清算**链路(交易→**清分**拆账→**轧差**抵消→**结算**划拨→T+n 多批次)与多边参与方的资金流转；会用**差错池**分类处置掉单/**长款**(渠道有我方无)/**短款**(我方有渠道无)/金额不符，坚持"自动补单或退款 + 人工复核"闭环；死守**金额精度**底线(整数分/Decimal、四舍五入口径全局一致、汇差手续费留明细)；建立**资损防控**的多道闸门(限额限次、逐笔对账告警、幂等防重复入账、反向冲正、灰度与双人复核)。识破"只比总额掩盖对冲差错""掉单当没发生""吞差擅自调平""重复入账造成资损"等坑。

## 一、对账三层：从自证平到账实相符

```text
图目的：对账不是"比个总数"，是三个口径逐层收敛
① 账务内部：逐笔明细汇总 = 总账发生额，全账 Σ借 = Σ贷（承复式记账）
② 对三方渠道：拉渠道 T+1 账单，按渠道单号逐笔 diff（不是比总额！）
③ 账实核对：账面备付金余额 = 银行实际头寸，防"账面有、钱没到"
```

```java
// 目的：逐笔对账产出差错清单，绝不"比总额相等"就放行
List<Diff> reconcile(Day day) {
    Map<String,Record> ours = ledger.byChannelNo(day);      // 说明：我方流水按渠道单号建索引
    Map<String,Record> theirs = channelBill.download(day);  // 结果：渠道账单可能延迟，需带重试与截止
    List<Diff> diffs = new ArrayList<>();
    for (String no : union(ours, theirs)) {
        Record o = ours.get(no), t = theirs.get(no);
        if (o == null && t != null) diffs.add(long款(no));   // 异常：渠道有我方无=长款(多为掉单/回调丢)
        else if (o != null && t == null) diffs.add(short款(no)); // 我方有渠道无=短款(未真实到账/伪造)
        else if (!o.amt().equals(t.amt())) diffs.add(amtMismatch(no, o, t)); // 金额不符
    }
    return diffs; // 总额相等也会漏掉"A多B少"的对冲差错，必须逐笔
}
// 反例：只比对当日总金额相等就收工 ❌ 两笔方向相反的错误相互抵消，账面平了资损照旧
// 反例：发现差异手工 UPDATE 余额凑平 ❌ 吞差掩盖真实资金缺口，审计追不回
```

## 二、清算链路：拆账、轧差、划拨

```text
图目的：从"成交"到"钱真正到账"的流水化过程
清分：把一笔交易按参与方(商户/平台/渠道/分账方)拆成应收应付明细
轧差：多边之间先互相抵消，只算净额划拨，减少真实转账笔数
结算：按净额在 T+n 批次把资金从备付金账户划拨到各方；批次要对齐营业日
```

- 多边清算要防"轧差后净额方向错误导致备付金被记反"；清分明细必须可回溯到复式分录，保证 `清算结果 ↔ 账务` 能再对一次平。

## 三、差错处置与资损防控闸门

```text
图目的：差错不是异常终点，是进入可闭环处置流程的入口
差错池：掉单/长款/短款/金额不符分类入池，带状态机(待处理/处理中/已闭环)
自动闭环：长款→补单或原路退款；掉单→主动查单补记；不可自动的一律人工复核
多道闸门：① 限额限次 ② 逐笔对账告警 ③ 幂等防重复入账 ④ 反向冲正 ⑤ 灰度+双人复核
```

## 四、金额精度铁律

- **整数分/Decimal**：全链路统一最小货币单位，禁浮点；四舍五入(银行家舍入)口径必须全局一致，否则每笔差 1 分、海量累积对不平。
- **汇差/手续费留明细**：分摊要有可核对口径，保证"借=贷"仍成立(通向复式记账)，不能靠一个笼统"手续费"字段吞差。
