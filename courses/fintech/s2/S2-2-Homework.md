# 两地三中心、监管合规与信创 · 作业

### 作业 1：复制策略选择器与 RPO/RTO 映射

- 目标：把"能容忍丢多少数据、停多久"落到具体复制配置。
- 任务：实现 `pick(from,to,dc)`：同城核心=同步、异地=异步、其它=半同步；为给定业务(转账核心=低 RPO、日志查询=可高 RPO)标注 RPO/RTO 目标并选策略。构造"误配异地同步"观察主库提交延迟剧增。
- 验收标准：同城核心 RPO≈0、异地不同步阻塞主库；每个业务能说出其 RPO/RTO 与所选策略一致。
- 参考解法要点：距离用是否同城判定；核心数据宁可牺牲部分写吞吐换同步，非核心走异步；给出监控指标(复制延迟)。

### 作业 2：单元化路由 + 切换演练脚本

- 目标：让一次"单元故障→切走流量→恢复回切"可重复演练。
- 任务：按分片键(如用户 ID 段)把请求路由到对应单元；写故障转移：将某单元流量经网关/DNS 切到备用单元，回切前校验数据追平；加入脑裂防护(仲裁/写围栏，避免双主)。
- 验收标准：单单元故障只影响其承载用户、其余单元正常；回切前若增量未追平则阻止回切；模拟网络分区不出现双主同时写。
- 参考解法要点：跨单元调用尽量少且显式；切换要有一致性核对与灰度回流；演练常态化。

### 作业 3：信创迁移的双跑比对与回退

- 目标：把国产 DB/中间件替换做成可验证、可回退的灰度过程。
- 任务：新旧栈并行处理同一批请求(或影子流量)，比对结果与关键 SQL 方言/驱动差异；定义回退触发条件与一键切回旧栈的流程；对审计日志设计 append-only 存证。
- 验收标准：差异能被自动比对暴露；满足回退条件时可切回旧栈且数据不丢；审计日志不可被改、能自证操作轨迹。
- 参考解法要点：先兼容性与性能评估再灰度；SQL 方言差异列清单适配；合规留痕与账务可追溯同源。
