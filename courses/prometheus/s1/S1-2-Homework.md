# PromQL 与直方图分位计算 · 作业

## 作业 1：rate 家族三剑客对比

**目标**：同一 Counter 上直观对比 rate/irate/increase。

1. 用脚本制造"平稳 10 QPS + 每 2 分钟一次 200 QPS 突刺 3 秒"的流量。
2. Grafana 同屏画 `rate(x[5m])`、`irate(x[5m])`、`increase(x[5m])` 三条曲线，输出三者对同一突刺的响应差异说明。
3. 把 scrape_interval 改 15s、窗口改 `[30s]` → 观察空洞/锯齿（结果验证"窗口≥4 倍抓取间隔"）。
4. 反例：对 JMX 内存 Gauge 使用 rate()，解释为什么曲线毫无业务意义。

## 作业 2：手写 P99 并验证插值误差

**目标**：理解 histogram_quantile 的桶插值本质。

1. 服务暴露自定义桶：`le = 0.05, 0.1, 0.5, 1`，注入固定 120ms 延迟。
2. 查询 `histogram_quantile(0.99, sum by (le)(rate(..._bucket[5m])))`，记录输出值。
3. 把 120ms 真值与输出对比，解释落在 (0.1, 0.5] 桶后的插值计算过程（说明：输出≈0.1+（0.5-0.1)×比例）。
4. 增加 0.15/0.2 两个密桶重测 → 输出精度显著提升，得到"SLO 附近布密桶"的结论。

## 作业 3：错误率告警表达式工程化

**目标**：产出一条可直接上生产的 recording rule + 告警规则。

1. 写 rule：`service:http_error_ratio:5m = 5xx速率/总速率`（两侧 by (service)）。
2. 告警：ratio>0.01 && QPS>10 持续 2m，标签加 severity，annotation 嵌入 `{{ printf "%.2f" $value }}` 输出实时值。
3. 测试三种流量：低峰 2 错误（不该告）、高峰 5% 错误 1 分钟（不该告）、持续 3 分钟（该告），输出每步判断依据。
4. 思考验收：为什么分母不加 code 过滤而分子加？写一句话说明向量匹配如何避免除零。
