# 分布式事务在数据层的落地选型 · 作业

### 作业 1：用拆分键消灭跨库事务

- 目标：通过路由设计把一次交易的多数写落进同一分片。
- 任务：给定订单主表与订单明细，选择 `user_id` 作拆分键做基因法路由，使同一用户的订单与明细落同一库；统计改造前后"跨库事务"占比，对比本地事务与 Seata 的耗时差异。
- 验收标准：多数交易走本地事务即可；残留跨库写才引入分布式事务；能量化吞吐/延迟改善。
- 参考解法要点：拆分键优先覆盖高频共置访问；基因法把 user_id 编进订单号避免二次查询路由。

### 作业 2：Seata AT 热点账户实验

- 目标：复现全局锁串行化对 TPS 的影响并给出缓解方案。
- 任务：对同一账户高并发 `@GlobalTransactional` 转账，观察全局锁等待导致 TPS 下降；改用"余额分桶（把一个账户拆成多子账户分摊）"或 TCC 预留后复测。
- 验收标准：能展示分桶/TCC 后 TPS 回升；说明 AT 与 TCC 在热点下的取舍。
- 参考解法要点：AT 图省事但有全局锁；热点场景要么分桶摊锁、要么改 TCC；资金强一致底线不能松。

### 作业 3：本地消息表 + 幂等消费兜底

- 目标：把"扣款成功后加积分/发通知"实现为最终一致且可靠。
- 任务：扣款本地事务里同时写业务表和消息表；投递方轮询消息表发 MQ，消费端按业务号幂等；加入定时补偿与消息表归档清理。
- 验收标准：消费重复不重复加积分；消息不丢不重；消息表不因不清理而膨胀。
- 参考解法要点：事务消息/本地消息表二选一；关键是消费幂等 + 死信/补偿 + 归档，避免只发不消费或无限堆积。
