# 数据一致性的校验与修复 · 作业

### 作业 1：分片哈希比对发现缓存与 DB 差异

- 目标：用增量水位 + 分片哈希快速定位不一致区间。
- 任务：按 `update_time` 水位把最近 N 分钟数据切片，对每片计算 DB 行集指纹与缓存指纹，指纹不等的分片再逐行取主键比对，输出差异清单。
- 验收标准：只比内容不比行数；差异分片才进入逐行修复；对账走只读副本、错峰、限流。
- 参考解法要点：用 xxHash/MD5 聚合；控制单片规模避免大事务；对账脚本本身加心跳监控防"哑火"。

### 作业 2：幂等修复回源重建

- 目标：把"以真值源为准"的修复做成可重复执行不产生二次不一致。
- 任务：对作业 1 的差异分片，从 DB 带 `version` 回源重建缓存；更新前比较版本号，只有源版本更新才覆盖；同一差异重复执行两次结果一致。
- 验收标准：重复修复不把新值覆盖回旧值；盲目删除缓存导致的穿透被消除；资金/关键字段差异挂账人工。
- 参考解法要点：CAS/版本比较是幂等修复核心；不可自动裁决的差异生成工单而非硬改。

### 作业 3：一致性指标与告警闭环

- 目标：让"最终一致"可度量、可追踪。
- 任务：埋点上报不一致率、发现→修复时延、对账积压差、自动修复成功率；对金额/库存差异突增配置告警；做一个看板确认差异能归零。
- 验收标准：差异长期不归零能触发升级告警；对账任务挂掉能被监控发现而非静默。
- 参考解法要点：把校验—修复—观测连成闭环；用不变量校验作为上游 bug 的早期信号。
