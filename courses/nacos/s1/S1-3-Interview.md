# Nacos 集群运维与鉴权、与 Eureka/Consul 对比（关联） · 面试题

## 题 1：Nacos 集群怎么部署？存储要注意什么？

- 3 节点起步、无状态节点共享同一份外置 MySQL 持久化配置（内嵌 Derby 只适合单机）。
- 真单点其实是那套共享 DB——要给它做主从/高可用，否则 DB 挂了整个集群受累。
- 加分：Nacos 2.x 用 gRPC 长连接，除 8848 还要放行偏移端口（+1000/+1001）。

## 题 2：Nacos 是 AP 还是 CP？

- 双模：临时实例的服务注册走 AP（Distro、最终一致、优先可用），配置与永久实例走 CP（Raft 强一致）。
- 所以不能一句话概括，要按数据类型看；这也是它区别于纯 AP 的 Eureka 的地方。
- 加分：大促时服务发现宁要 AP 的"能用可能略旧"，也不要注册中心整体不可用。

## 题 3：多环境/多租户怎么隔离？

- 用 namespace（dev/test/prod、租户各一个，配置与服务在其中互不可见）+ group 二级细分。
- 客户端配置的 namespace 必须与环境一致，否则会误连。
- 加分：共用 namespace 的经典事故——测试服务被生产订阅、配置跨环境误改。

## 题 4：Nacos 的安全默认配置有什么坑？怎么加固？

- 默认几乎裸奔：无鉴权、默认账号密码 `nacos/nacos`、默认 token 密钥、无 TLS，公网扫到即可改配置/下线服务。
- 加固：`auth.enabled=true`、换默认密码与 secretKey、配用户/角色/权限、前置 HTTPS/TLS、最小权限。
- 加分：区分"控制台登录"与"OpenAPI/gRPC 鉴权"，两者都要覆盖。

## 题 5：把 Nacos、Eureka、Consul 做个选型对比。

- Eureka：纯 AP、只做注册、客户端缓存容错好，但社区停滞、Spring Cloud 2020 起移出默认栈。
- Consul：CP（Raft）、健康检查丰富、多 DC/服务网格、跨语言。
- Nacos：AP+CP 双模、自带配置中心 + 命名空间、与 Spring Cloud Alibaba 深度整合，国内默认。
- 加分：按"是否要配置中心、是否跨语言/多 DC、生态栈"来选，而非泛泛说谁更好。

## 题 6：临时实例和永久实例（ephemeral/persistent）有什么区别？

- 临时实例由客户端心跳维持、走 AP，进程下线即摘除，适合普通微服务实例。
- 永久实例由 Nacos 主动检查、走 CP 强一致，实例不自动摘除，适合数据库等需纳管的外部服务。
- 加分：健康检查方式（客户端上报 vs 服务端探测）与一致性语义随实例类型不同。
