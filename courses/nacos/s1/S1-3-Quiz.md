# Nacos 集群运维与鉴权、与 Eureka/Consul 对比（关联） · 小测

> 本卷满分 100 分：单选 7×6=42，多选 2×9=18，简答 1×40=40。

### 1. Nacos 集群生产部署对存储的推荐做法是（6分）

- A. 用内嵌 Derby 每个节点各自一份
- B. 集群节点共享同一份外置 MySQL（并给 DB 做主从 HA）
- C. 不持久化
- D. 存本地文件

> 答案：B
> 解析：内嵌 Derby 只适合单机；集群要共享外置 MySQL 持久化配置，且单实例 DB 会成为真正单点/瓶颈，须给 DB 高可用。

### 2. Nacos 2.x 除 8848 外还需放行的端口来自（6分）

- A. FTP
- B. gRPC 长连接端口（在 8848 基础上偏移 +1000/+1001）
- C. SMTP
- D. 无需其它端口

> 答案：B
> 解析：2.x 用 gRPC 长连接做推送与心跳，SLB/防火墙要一并放行偏移端口，否则客户端连不上。

### 3. 关于 Nacos 的一致性模型，正确的是（6分）

- A. 纯 AP
- B. 纯 CP
- C. 双模：临时实例注册 AP（Distro），配置/永久实例 CP（Raft）
- D. 最终一致但不分区

> 答案：C
> 解析：按数据类型混用——服务发现优先可用（AP），配置强一致（CP），这是它区别于纯 AP 的 Eureka 的关键。

### 4. 多环境隔离在 Nacos 里主要靠（6分）

- A. 换端口
- B. namespace（+ group 二级细分）
- C. 改机器 hostname
- D. 不同数据库

> 答案：B
> 解析：dev/test/prod、多租户各用独立 namespace，配置与服务在其中互不可见，防止误发现/串环境。

### 5. Nacos 默认配置最大的安全隐患是（6分）

- A. 不支持集群
- B. 无鉴权且默认账号密码 nacos/nacos，暴露即可改配置/下线服务
- C. 不支持 HTTPS
- D. 不支持配置

> 答案：B
> 解析：默认近乎裸奔，生产必须开启鉴权、换默认密码与 token 密钥、前置 HTTPS/TLS。

### 6. 与 Eureka 对比，Nacos 多出来的能力是（6分）

- A. 只是注册中心
- B. 自带配置中心 + 命名空间隔离 + AP/CP 双模
- C. 只能 CP
- D. 无心跳

> 答案：B
> 解析：Eureka 是纯 AP 注册中心且社区停滞；Nacos 兼做注册+配置、支持隔离与双一致性、与 Spring Cloud Alibaba 深度整合。

### 7. Consul 相对 Nacos 的典型特征是（6分）

- A. 纯 AP
- B. CP（Raft）、健康检查丰富、多 DC/服务网格、跨语言
- C. 无强一致
- D. 只支持 Java

> 答案：B
> 解析：Consul 走 Raft 强一致、多数据中心与跨语言生态好；Nacos 更贴国内 Spring Cloud Alibaba 与配置中心场景。

### 8.（多选）以下是 Nacos 生产加固应做的有（9分）

- A. 开启鉴权并修改默认密码/token 密钥
- B. 前置 HTTPS/TLS
- C. 给共享的外置 MySQL 做主从 HA
- D. 把 dev/test/prod 放同一 namespace 图省事

> 答案：A、B、C
> 解析：D 是反例——共用 namespace 会导致测试服务被生产发现、配置串环境。

### 9.（多选）关于 AP/CP 双模的理解，正确的有（9分）

- A. 大促时服务发现宁要"能用可能略旧"(AP)也不要整体不可用
- B. 金融配置变更要 CP 强一致，读到即最新
- C. 临时实例与永久实例行为完全一致
- D. Eureka 是纯 AP、Consul 是纯 CP，Nacos 按数据合一

> 答案：A、B、D
> 解析：C 错——临时实例走 AP(Distro)、永久实例走 CP，健康检查与一致性语义不同。

### 10. 给一家有 开发/测试/生产 三环境、金融合规要求、多业务线的公司设计 Nacos 集群运维方案（拓扑、隔离、安全、一致性）。（40分）

> 参考答案：
- 要点1：拓扑——集群 3 节点起步、共享外置 MySQL 并给 DB 做主从 HA，放行 8848 + gRPC 偏移端口（10分）
- 要点2：隔离——每环境独立 namespace（生产/测试/开发物理隔离），业务线用 group 细分，杜绝跨环境误发现与配置串改（10分）
- 要点3：安全——开启鉴权、换默认账号密码与 token 密钥、配置用户/角色/权限、前置 HTTPS/TLS，公网节点强制 TLS + 最小权限（10分）
- 要点4：一致性——理解双模：服务发现（临时实例 AP）保证大促可用，配置与关键项（CP）保证强一致；据此设监控与告警（10分）
