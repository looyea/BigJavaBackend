# Nacos 集群运维与鉴权、与 Eureka/Consul 对比（关联）

> 本节难度：★★★☆☆
> 重要程度：★★★★☆
> 学习产出：能把 Nacos 从"能跑起来的单机玩具"运维成"生产可用的注册 + 配置中心"，并说清它与 Eureka/Consul 的取舍。集群部署要 **3 节点起步**、共享同一份**外置存储**（配置持久化靠 MySQL；Nacos 2.x 的集群元数据/临时实例用自研协议管理，内嵌 Derby 只适合单机），注意集群仍连"一套 MySQL"时，DB 就成了单点/容量瓶颈，要给它做主从或高可用。端口除 `8848`（HTTP/OpenAPI）外，2.x 引入 gRPC 长连接端口（在 8848 基础上偏移 +1000/+1001），防火墙/SLB 要一并放行，否则客户端连不上。**一致性模型是双模**：**临时实例的服务注册走 AP**（Distro 协议、最终一致、优先可用，网络分区时仍能读写本地，牺牲强一致换服务发现不中断），**配置与永久实例等走 CP**（Raft 类强一致）——按数据类型混用 AP/CP 是 Nacos 区别于纯 AP 的 Eureka 的关键。隔离用 **namespace（命名空间）+ group（分组）**：给 dev/test/prod、多租户分配不同 namespace，配置与服务在其中互不可见，**防止测试环境服务被生产订阅、配置串环境**；group 做二级细分。安全上 Nacos 默认几乎"裸奔"（无鉴权、默认账号密码 `nacos/nacos`），生产必须**开启鉴权**（自定义 token 密钥、用户/角色/权限、改默认密码）、**前置 HTTPS/TLS**（Nginx/网关），否则公网扫到即可改配置、下线服务。生态对比：**Eureka** AP、纯注册中心、客户端缓存容错好但社区停滞（Spring Cloud 2020 起移出默认栈）；**Consul** CP（Raft）、健康检查丰富、多 DC/服务网格、跨语言；**Nacos** AP+CP 双模 + 自带配置中心 + 命名空间 + 与 Spring Cloud Alibaba 深度整合，是国内微服务默认选择。识破"集群共用单实例 MySQL 成瓶颈""不同环境共用 namespace 误发现""默认密码裸奔被刷""把临时实例（AP）和永久实例（CP）行为混为一谈"等坑——电力多环境隔离、金融配置强一致、电商大促服务发现高可用都直接依赖这些设定。

## 一、生产化配置基线

```yaml
# 目的：生产级 Nacos 集群三要素——外置共享存储、鉴权开启、隔离命名空间
spring:
  datasource:
    platform: mysql            # 说明：集群共享同一外置 MySQL 持久化配置, 别用内嵌 Derby(仅适合单机)
nacos:
  core:
    auth:
      enabled: true            # 结果：开启鉴权、关闭匿名; 默认关=裸奔, 公网被刷会直接改配置/下线服务
      token:
        secretKey: ${NACOS_SECRET} # 反例：沿用默认密钥/默认账号 nacos/nacos ❌ 等于没开鉴权 ❌
server:
  port: 8848                   # 说明：gRPC 端口在此基础上偏移(+1000/+1001), 集群与客户端需一并放行
```

## 二、AP/CP 双模：按数据类型选一致性

```text
图目的：Nacos 不是一句"AP"或"CP"能概括, 要分数据看
临时实例注册(ephemeral): AP, Distro 协议, 最终一致 → 网络分区仍可读, 服务发现优先"不断"
配置 / 永久实例: CP, Raft 类强一致 → 金融配置变更要"读到就是最新", 不能脏
对比 Eureka(纯 AP) / Consul(纯 CP Raft): Nacos 把两者按场景合一
运维含义: 大促时宁可短暂看到旧实例列表(AP)也不要注册中心整体不可用
```

## 三、隔离与集群拓扑

```text
图目的：namespace/group 隔离 + 集群存储不是新单点
namespace: dev/test/prod 或 多租户各一个, 配置与服务在其中互不可见(防误发现/串环境)
group: namespace 内的二级分组, 细到业务线/应用
存储: 集群 3 节点共享外置 MySQL —— 若 MySQL 是单实例, 它才是真正单点/瓶颈, 须给 DB 做主从 HA
端口: 8848(HTTP) + gRPC(偏移端口) 都要在 SLB/防火墙放行, 否则客户端连不上
```

## 四、选型与底线

- **默认裸奔必加固**：开 `auth.enabled`、换默认密码与 token 密钥、前置 HTTPS，公网节点尤其。
- **环境隔离用 namespace**：绝不共用，避免测试服务被生产发现、配置跨环境误改。
- **对比着选**：要 CP 强一致+多 DC+跨语言看 Consul；要国内生态/自带配置中心/AP 高可用看 Nacos；Eureka 已基本不选新项目。
