# 服务注册发现与心跳模型 · 小测

### 1. Nacos 临时实例的心跳间隔默认是？（6分）

- A. 1s
- B. 5s
- C. 15s
- D. 30s

> 答案：B
> 解析：客户端每 5s 发一次 beat，Server 15s 不健康/30s 摘除。

### 2. 临时实例采用哪种一致性协议？（6分）

- A. Raft
- B. Paxos
- C. Distro
- D. Zab

> 答案：C
> 解析：临时实例走 Distro（AP 最终一致）；持久实例走 JRaft（CP）。

### 3. 实例被 Nacos 摘除的条件是？（6分）

- A. 15s 未收到心跳
- B. 30s 未收到心跳
- C. 60s 未收到心跳
- D. 手动调用下线接口

> 答案：B
> 解析：15s → 标记不健康（仍在列表但 healthy=false）；30s → 从列表移除。

### 4. Distro 数据分片依据是？（6分）

- A. 轮询
- B. Hash(serviceName + namespace) % 节点数
- C. 随机
- D. 按 IP 段

> 答案：B
> 解析：同一服务的所有实例由固定节点负责，写请求路由到负责节点再异步同步。

### 5. 持久实例不健康时 Nacos 的行为是？（6分）

- A. 立即从列表移除
- B. 只标记 healthy=false，不摘除
- C. 重启实例
- D. 发送告警后移除

> 答案：B
> 解析：持久实例由用户生命周期管理，Nacos 只负责标记健康状态供消费方决策。

### 6. Nacos 2.x 相比 1.x 通信方式的重大变化是？（6分）

- A. 从 HTTP 改为 TCP 长连接（gRPC）
- B. 从 gRPC 改回 HTTP
- C. 增加 WebSocket
- D. 使用 UDP 推送

> 答案：A
> 解析：2.x 引入 gRPC 长连接替代 1.x 的 HTTP 短轮询，配置推送延迟从秒级→毫秒级。

### 7. 消费者本地缓存服务列表的意义是？（6分）

- A. 减少磁盘占用
- B. Nacos Server 全挂时仍可调用已知实例
- C. 加快序列化
- D. 替代健康检查

> 答案：B
> 解析：SDK 将最新服务列表缓存本地（failover），注册中心不可用时降级使用。

### 8. 以下属于 Nacos 健康检查方式的是（多选）？（9分）

- A. 客户端心跳（beat）
- B. 服务端 TCP 探测
- C. 服务端 HTTP 探测
- D. 基于 Prometheus 指标

> 答案：A、B、C
> 解析：D 非 Nacos 原生方式；临时实例=A，持久实例=B/C。

### 9. Distro 协议下某节点宕机，影响是（多选）？（9分）

- A. 该节点负责的服务注册暂时失败
- B. 其他节点自动接管（健康检查摘除死节点）
- C. 所有读请求失败
- D. 已同步的数据仍可从其他节点读取

> 答案：A、B、D
> 解析：C 错——其他节点有异步同步过来的数据副本，读请求不受影响。

### 10. 简答题：描述 Nacos 服务注册→发现→健康摘除→恢复的完整流程。（40分）

- 要点1：注册：客户端 POST /nacos/v1/ns/instance，含 ip/port/ephemeral/metadata
- 要点2：发现：订阅者 GET /nacos/v1/ns/instance/list 拿到全量健康实例列表并本地缓存
- 要点3：摘除：心跳超时 30s → Server 从列表中移除 → UDP/gRPC 推送变更给订阅者
- 要点4：恢复：实例重启后重新注册 → Server 推送新列表 → 订阅者缓存更新
- 要点5：容灾：Nacos 全不可用时，客户端使用本地 failover 缓存继续调用

> 答案：见要点
> 解析：理解完整生命周期是排查"调不到服务"类故障的基础。
