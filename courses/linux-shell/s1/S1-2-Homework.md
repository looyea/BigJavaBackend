# 网络、磁盘与日志定位脚本 · 作业

## 作业 1：连接状态判读（动手题）

**目标**：用 `ss` 读懂 TCP 状态分布，识别泄漏类型。

**任务**：
1. 起一个本地服务并写一个"发起 HTTP 调用但不关连接"的小脚本（或故意不 close 连接池），观察 `ss -tan | grep <port>` 里 **CLOSE-WAIT** 是否堆积；
2. 用 `ss -s` 抓总览，用 `ss -tan state established '( dport = :8080 )' | wc -l` 统计到下游的连接数；
3. 制造 TIME-WAIT 高发（短连接压测），解释它为什么通常出现在主动关闭端、什么时候才需要担心（临时端口耗尽）；
4. 输出"三种异常状态各自的根因方向"小结表。

**验收标准**：CLOSE-WAIT 堆积能被归因到"应用没 close"，TIME-WAIT 能被正确解读为"多半正常"；给出对应到 Java 侧的下一步（查连接池配置/HttpClient 是否复用、是否设 keep-alive）。

**参考解法要点**：CLOSE-WAIT→代码未关连接；SYN-RECV→半连接队列/建连风暴；FIN-WAIT-CLOSE 长期堆积→对端不回 ACK 或网络丢包。

## 作业 2：磁盘"写不进"全排查（工程题）

**目标**：区分容量满 / inode 满 / 已删未回收三种"盘问题"。

**任务**：
1. 分别制造三种场景：`fallocate` 写满容量、`touch` 百万小文件打满 inode、`rm` 一个被 `tail -f` 占用的大文件；
2. 每种场景用 `df -h`、`df -i`、`lsof +L1` 给出诊断证据，说明"为什么这个场景 df -h 会骗人";
3. 写出安全的在线清理方案（`truncate -s 0`、`find ... -print` 预览后再 `-delete`），并解释为什么不能直接 `rm` 正在写的大日志。

**验收标准**：三种场景的诊断命令与结论对应正确；清理方案不中断进程；给出"日志失控"的根因治理（logback 滚动策略 + maxFileSize/maxHistory，而非事后手删）。

## 作业 3：一键现场快照脚本（工程题）

复用本课脚本骨架，写一个 `snapshot.sh`：入参为服务名与端口，自动抓 `ss` 连接分布、`top -bH` 线程 CPU、`jstack`、`df -h/-i`、近 2000 行日志，打包带时间戳落 /tmp。**验收标准**：脚本在 `set -euo pipefail` 下对"命令可能无结果"处正确 `|| true` 不中断；对不存在的进程名有友好报错；能加一段 `find / -xdev -type f -size +500M -print` 揪大文件；附一段"为什么排查脚本要幂等、要防误删、要把证据固化到文件而非只打印到终端"的说明。
