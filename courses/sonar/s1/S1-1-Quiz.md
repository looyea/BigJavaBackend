# 规则集与门禁策略 · 小测

## 一、单项选择题（每题 6 分，共 42 分）

### 1. SonarQube "Clean as You Code" 的核心理念是？（6分）

- A. 一次性清理全仓库所有问题
- B. 质量阈只针对新增/变更代码，存量债单独治理
- C. 关闭所有规则
- D. 只做安全扫描
> 答案：B
> 解析：拿全量红线卡老项目会首扫即红、团队弃用；只卡新代码让质量逐步收敛才可持续。

### 2. Quality Profile 与 Quality Gate 的区别是？（6分）

- A. 同一个东西
- B. Profile 决定"跑哪些规则"，Gate 决定"达到什么指标算通过"
- C. Gate 决定规则，Profile 决定阈值
- D. 都只跟覆盖率有关
> 答案：B
> 解析：Profile=规则集选择，Gate=通过/失败的指标条件，两层职责不同。

### 3. 让 Quality Gate 真正阻断合并，CI 里关键参数是？（6分）

- A. `-Dsonar.verbose`
- B. `-Dsonar.qualitygate.wait=true`
- C. `-DskipTests`
- D. `-Dsonar.offline`
> 答案：B
> 解析：不加 wait 流水线不等 Gate 结果，Gate 沦为事后看板；wait 让 MR 门禁真正生效。

### 4. 关于 Security Hotspot，正确的说法是？（6分）

- A. 自动判定为漏洞直接阻断
- B. 不自动判违规，需人工复核（如随机数当 token 是否可接受）
- C. 与代码无关
- D. 就是覆盖率指标
> 答案：B
> 解析：Hotspot 是"需要人来判断的安全敏感点"，门禁常要求"新热点 100% 复核"，而非机器直接定性。

### 5. Sonar 的行覆盖率数据来源通常是？（6分）

- A. Sonar 自己执行测试
- B. JaCoCo 等工具产出的覆盖率报告被 Sonar 读取
- C. 人工填写
- D. Git 提交数
> 答案：B
> 解析：没先跑测试产出 jacoco 报告就扫描，覆盖率会是 0——扫描阶段只读报告不跑测试。

### 6. 把"函数圈复杂度 < X"设成 Blocking 一刀切的风险是？（6分）

- A. 没有风险
- B. 逼出"把大函数拆成一堆无意义小函数"的应试代码，掩盖真实设计问题
- C. 会提高覆盖率
- D. 会减少漏洞
> 答案：B
> 解析：指标适度使用；为过门禁而做的机械拆分不改善可读性，反而失真。

### 7. 对 Sonar 的误报（假阳性），正确处置是？（6分）

- A. 直接关掉整条规则
- B. 标记 False Positive/Won't Fix 并留 review 记录，不滥标绕过
- C. 忽略不管
- D. 全量禁用门禁
> 答案：B
> 解析：静态推断必有误报，规范标注可沉淀判断依据；关规则/滥用标记会让门禁失去意义。

## 二、多项选择题（每题 9 分，共 18 分）

### 8. （多选）一份健康的增量 Quality Gate 常包含哪些条件？（9分）

- A. 新代码覆盖率低于阈值则失败
- B. 新增 Blocking/Critical 违规数 > 0 则失败
- C. 把全仓库历史问题总数作为红线
- D. 新增安全热点需 100% 复核
> 答案：ABD
> 解析：C 是反模式（存量债不该压每次 PR）；A/B/D 都作用在"新代码"维度，符合 Clean as You Code。

### 9. （多选）关于 Sonar 落地节奏，合理的有？（9分）

- A. 先宽松跑通链路，让团队适应 PR 被拦
- B. 每语言统一 Quality Profile，改规则走评审
- C. 上线第一天就把所有指标设成最严
- D. 存量债按模块建清理冲刺，用 baseline 限制
> 答案：ABD
> 解析：C 会瞬间把项目全判红、引发抵触；渐进收紧 + Profile 统一 + 存量单列才是可持续路径。

## 三、简答题（40 分）（每题 40 分，共 40 分）

### 10. 一个有 20 万历史问题、团队对质量工具抵触的老 Java 项目要引入 SonarQube 做门禁，请给出落地方案。（40分）

> 参考答案：
- 要点1：理念定调——采用 Clean as You Code，Gate 只卡新代码，历史问题不计入合并门禁，先消解抵触；
- 要点2：Profile 治理——基于 Sonar way 统一 Quality Profile，关掉团队公认噪音规则，改规则走评审；
- 要点3：Gate 首版宽松——new_coverage 起步设低（如 60%）、只拦新增 Blocker、链路先跑通；
- 要点4：CI 接线——MR 触发 `mvn verify sonar:sonar -Dsonar.qualitygate.wait=true`，token 走密钥管理，jacoco 先产出报告；
- 要点5：存量债——技术债雷达/看板分模块排清理冲刺，设 baseline 与负责人，而非压在 PR；
- 要点6：逐步收紧 + 度量——覆盖/漏洞/热点复核趋势看板，误报按规范标记留痕，让"质量变好"可见以维持动力。
