# Java 21 LTS：虚拟线程时代 · 小测

> 本卷共 6 题（单选 / 多选 / 判断 / 填空 / 简答），满分 100 分，≥ 60 分过关。

### 1. 虚拟线程的核心价值最准确的描述是？（15分）

- A. 让 CPU 密集计算变快
- B. 让"线程"变得极便宜，从而用同步阻塞写法获得高并发吞吐
- C. 完全取代 OS，不再需要内核线程
- D. 自动消除所有死锁

> 答案：B
> 解析：虚拟线程是 JVM 调度的用户态任务，挂载在少量载体线程上；它解放的是并发规模（每请求一线程），不加速计算，也不消灭死锁。

### 2. 关于虚拟线程的使用，下列做法正确的是？（15分）

- A. 用固定大小的虚拟线程池复用以省内存
- B. 用 `Executors.newVirtualThreadPerTaskExecutor()`，每任务新建、用完即弃
- C. 虚拟线程必须手动设置最大并发数才能运行
- D. CPU 密集任务最适合用虚拟线程

> 答案：B
> 解析：虚拟线程按用完即弃设计、创建极廉，池化会摧毁弹性；其并行度由内部载体线程池决定。CPU 密集不受益。

### 3. 【多选】虚拟线程的已知坑/限制，正确的有哪些？（20分）

- A. 在 `synchronized` 块内阻塞会"钉住（pin）"载体线程，难以卸载
- B. 百万虚拟线程各挂大 ThreadLocal 会造成内存膨胀
- C. 用了虚拟线程就无需再对下游（DB 连接池等）做并发保护
- D. 瓶颈若是 CPU 或下游容量时，加虚拟线程并不会提升吞吐

> 答案：ABD
> 解析：C 错——虚拟线程能开很多并发，反而更容易冲垮 DB/下游，**限流/连接池上限仍需显式做**。A/B/D 正确。

### 4. 判断：分代 ZGC（Java 21）在保持"停顿与堆大小基本无关"的同时，降低了分配停滞和内存占用。（10分）

- A. 正确
- B. 错误

> 答案：A
> 解析：分代 ZGC 引入年轻代快速回收，改善分配停滞（allocation stall）与内存占用，同时维持亚毫秒级停顿；深度调优归 jvm 分区。

### 5. 填空题：虚拟线程阻塞时，JVM 会把它从 ______ 线程上"卸载（unmount）"、栈帧保存到堆；结构化并发中把一组子任务收进同一生命周期、失败即取消其余的 API 叫 ______（类名）。（10分）

> 答案：载体（carrier） / StructuredTaskScope

### 6. 说明虚拟线程为什么能让"同步阻塞代码"获得接近"异步非阻塞"的吞吐，并对比它与 Reactive（WebFlux）路线的取舍。（30分）

> 参考答案：
> - 机制：虚拟线程遇 IO/sleep/锁阻塞时被 unmount 让出载体线程，载体线程立刻去跑别的虚拟线程，阻塞不浪费 OS 线程，故同步写法也能撑极高并发
> - 相较 Reactive：WebFlux 用非阻塞 + 操作符链获得吞吐，但代码是异步风格、调试/线程上下文/阻塞点识别都更难，认知负担高
> - 虚拟线程优势：回到朴素阻塞代码，栈可读、易调试、生态（JDBC 等阻塞库）无需改造
> - Reactive 仍优处：背压（backpressure）语义成熟、流式处理细粒度控制
> - 结论：多数"高并发阻塞 IO"场景虚拟线程更省心；需要严格背压/流式的场景 Reactive 仍有价值
