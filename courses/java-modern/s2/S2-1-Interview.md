# Java 21 LTS：虚拟线程时代 · 面试追问

> 虚拟线程是当下 Java 面试最热话题，几乎必问且层层深入。高分关键：讲清"挂载/卸载"机制、说得出三大坑、能对比 Reactive、并清楚它和传统线程池的分工。

## 题 1：虚拟线程是什么？和平台线程有什么本质区别？

**期望时长**：2.5 分钟

**答题要点**：

- 平台线程 = OS 内核线程 1:1 映射，栈大、创建/切换贵，须池化。
- 虚拟线程 = JVM 调度的用户态任务，N:M 挂到少量"载体线程"上；初始栈小、按用完即弃设计。
- 阻塞时 unmount 栈帧到堆、让出载体线程；恢复时再 mount。

**追问链**：谁调度虚拟线程？→ JVM 内部的 `ForkJoinPool`（载体线程池，默认≈CPU 核数），不是 OS。

## 题 2：虚拟线程适合/不适合什么场景？

**答题要点**：

- 适合：**阻塞 IO 密集**——高并发网关、多下游聚合调用、DB/RPC 读写。
- 不适合：**CPU 密集**（仍受核数限制，加了不涨）、受下游容量约束且未限流的场景。

**追问链**：那线程池还有用吗？→ 有，但语义变了：从"复用昂贵线程"转为"限制对下游的并发冲击"；池化虚拟线程反而错误。

## 题 3：虚拟线程有哪些坑？（几乎必问）

**答题要点**：

- `synchronized` 内阻塞 → **钉住（pinning）**载体线程，热点改 `ReentrantLock`（JDK 24 已基本解决 sync 钉住）。
- **ThreadLocal 膨胀**：海量虚拟线程各挂大对象 → OOM；用无状态/不可变或 Scoped Values。
- 误用于 CPU 密集、或以为并发无限打爆下游。

**追问链**：怎么排查钉住？→ `-Djdk.tracePinnedThreads=full`、JFR `jdk.VirtualThreadPinned` 事件。

## 题 4：虚拟线程和 WebFlux/Reactive 怎么选？

**答题要点**：

- 都解决"阻塞浪费线程"。Reactive 靠非阻塞 + 操作符链，吞吐高但代码异步、调试难、认知负担重、要处理背压。
- 虚拟线程让**朴素同步阻塞代码**直接获得高吞吐，栈可读、生态无需改造。
- 选：一般业务优先虚拟线程（迁移成本低）；需精细背压/流式、已有成熟 Reactive 栈的仍可保留。

**追问链**：能混用吗？→ 能；但通常二选一，虚拟线程下不必再为吞吐而上 Reactive。

## 题 5：结构化并发解决什么问题？

**答题要点**：一个请求 fan-out 多子任务时，"取消传播、别泄漏孤儿线程、异常聚合"手写易错。`StructuredTaskScope` 把子任务收进同一作用域，作用域退出即保证全部完成或被取消，形成"每请求=一任务树"，失败快速收敛。

**追问链**：21 能直接生产用吗？→ 是预览（需 `--enable-preview`），API 在 22/24 仍在调整，落地锁版本查文档。

## 高频速答

- 虚拟线程会取代线程池吗？→ 取代"为复用而池化"，保留"为限流/下游保护"的用途。
- 并行度由什么决定？→ 载体线程数（默认≈核数），不是虚拟线程数量。
- 分代 ZGC 关键指标？→ 亚毫秒停顿、与堆大小基本无关、降分配停滞。
- Spring Boot 怎么开虚拟线程？→ 3.2+ `spring.threads.virtual.enabled=true`。
- MDC/ThreadLocal 上下文怎么办？→ 谨慎，考虑 Scoped Values 或每请求成本评估。
