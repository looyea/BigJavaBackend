# 火焰图、JVM 仪表盘与诊断联动（关联） · 面试题

## 题 1：线上 CPU 飙高，用 Arthas 你怎么排查？

- 先 `dashboard` 定域（确认是 CPU 问题、哪个线程池忙），再 `thread -n 3` 抓最忙线程栈定位方法。
- 需要看热点分布时上 `profiler` 产 CPU 火焰图，宽帧即热点。
- 加分：强调"先定域再下钻、别一上来就 heapdump"，并说明能结合 trace 精确到调用耗时。

## 题 2：Arthas 的 profiler 命令和独立 async-profiler 什么关系？

- profiler 命令内置 async-profiler 引擎，安全点采样、开销极低，可不改代码在线产火焰图。
- 两者同引擎，结论可互相印证；区别是 arthas 里以命令交互、便于联动 dashboard/vmtool。
- 加分：支持 cpu/alloc/lock 多事件，能分别定位 CPU 热点、对象分配、锁竞争。

## 题 3：火焰图怎么读？为什么不能只看最顶上的帧？

- 横轴宽度=采样命中占比，越宽越热；纵轴是调用栈深度，不代表耗时多少。
- 要看某帧"自身+子调用"的总宽，顶部小帧往往是叶子函数，真正的热点在下面汇聚处。
- 加分：指出 JIT/内核编译帧是安全点采样偏差，需剔除后才看业务热点。

## 题 4：heapdump 有什么代价？什么时候才用它？

- dump 全堆需遍历对象、触发长时间 STW，可能拖垮线上。
- 优先用 dashboard/vmtool 等轻量手段缩小范围；确需引用链/支配树分析时再择机 dump，并导到隔离机器用 MAT 看。
- 加分：说明 vmtool 能直接查某类实例数，比 dump 轻，适合先判断"有没有对象堆积"。

## 题 5：vmtool 能做什么？和 ognl 有何配合？

- vmtool 按类查询堆中实例集合与直方图，定位对象堆积与可疑缓存。
- ognl 能调用静态方法/读表达式，两者配合可对可疑对象做进一步取值验证。
- 加分：提醒 vmtool 强转/操作实例要谨慎，别误改线上状态。

## 题 6：说说你心中一条完整的"联动诊断链路"。

- dashboard 定问题域 → thread 定位线程栈 → profiler 火焰图确认热点函数 → vmtool/heapdump 查内存堆积根因。
- 各命令互相印证，遵循"先轻量后重操作"的顺序，控制诊断自身开销。
- 加分：结合 async-profiler 的原理修正采样偏差，并强调 profiler start/stop 成对、低占空比。
