# 方法级观测与调用链耗时 · 作业

## 作业 1：本地复现并观测一条"慢调用链"

- **目标**：把 trace 的条件过滤与逐跳分解练成肌肉记忆。
- **任务**：本地启动任一 Spring Boot 演示应用（attach：`java -jar arthas-boot.jar` 选择目标进程），对一个订单/查询接口执行：
  1. `trace` 全量观测一次，读出每跳耗时结构；
  2. 改用 `'#cost > 10'` 条件 + `-n 3`，在正常流量下确认"过滤生效"；
  3. 对最慢一跳的类再下钻一层 trace。
- **验收标准**：贴出两次 trace 输出对比，说明条件表达式过滤掉了什么、下钻定位到了哪个方法；结束执行 `stop` 并能用 `dashboard` 确认增强已复位。
- **参考解法要点**：慢跳常落在序列化/正则/加签/循环查库；先 sc 确认类命中面，避免通配过宽。

## 作业 2：watch + stack 组合定位"数据异常"

- **目标**：区分"哪跳慢"（trace）与"为什么错"（watch/stack）两类问题的手术路径。
- **任务**：构造一个偶发抛异常的接口（如随机抛 `RuntimeException`），完成：
  1. `watch ... '{params, returnObj, throwExp}' -x 2 'throwExp != null' -n 3`，只在异常时捕获现场；
  2. `stack` 该方法，确认异常由哪个入口线程触发（HTTP 线程 vs 定时任务线程）；
  3. 记录一次 `tt -t -n 5` 索引，只查看（`tt -i`）不回放，写出为什么该接口不允许 `-p` 回放。
- **验收标准**：三条命令的关键输出齐全，对"非幂等禁回放"给出结合业务副作用的解释。
- **参考解法要点**：`-x` 过大会打印整棵对象树；异常条件表达式放在 observe 边界；tt 存储的是现场快照而非重放指令。

## 作业 3：设计"单机 P99 突刺"的排查 SOP（文档题）

- **目标**：把本节命令串成可交接的团队规范。
- **任务**：针对"仅单机 P99 突刺、其余副本正常"场景写一页 SOP：分流（机器层/进程层/方法层）→ 命令序列 → 每步的判断依据 → 收尾复位与留痕要求，并标注哪些步骤在生产高峰禁止执行。
- **验收标准**：SOP 至少覆盖 dashboard、thread -n、trace 条件过滤、watch 限深、sc 双加载检查、stop 复位六要素；每步写明"看到什么输出 → 下一步走哪"。
- **参考解法要点**：可对照 [进程/内存/CPU/IO 四件套与 Top/vmstat](../../linux-shell/s1/S1-1-Lesson.md) 的机器层证据链；归因需要持续采样时衔接 [火焰图怎么看与常见瓶颈](../../async-profiler/s1/S1-1-Lesson.md)。
