# CQRS、事件溯源与架构决策 ADR · 小测验

> 全卷 100 分：单选 5×10 + 多选 2×10 + 判断 1×5 + 简答 15+10。达到 60 分解锁下一节。

### 1. CQRS 三个力度里，成本最低、90% 场景应首选的是（10分）

- A. 读写彻底异构存储 + 事件同步
- B. 只分离读写模型（同一个库，命令走领域模型、查询走轻量 DTO 视图）
- C. 读写独立部署两套服务
- D. 强制所有查询也加载聚合根

> 答案：B
> 解析：第一档"模型分离同库"不引入最终一致与双份运维；异构存储是拿一致性换伸缩，需求不到就是自扰。

### 2. 事件溯源（ES）中，"当前状态"是如何得到的（10分）

- A. 直接读数据库里被 UPDATE 的最新行
- B. 对 append-only 的事件流做重放 fold（通常配合快照）算出来
- C. 存在 Redis 缓存里
- D. 由前端计算

> 答案：B
> 解析：ES 里事件是唯一真相源、不可变，状态 = fold(所有事件)；余额 = Σ(入账-出账)，不是覆盖写的当前值。

### 3. 关于 CQRS 与 ES 的关系，正确的说法是（10分）

- A. 必须捆绑使用，缺一不可
- B. 二者可独立使用：可只用 CQRS 不用 ES，也可只用 ES 不用 CQRS
- C. ES 是 CQRS 的另一种拼写
- D. 用了 CQRS 就不需要读模型

> 答案：B
> 解析：它们常被捆绑（天然契合），但都是独立的重型武器；同时上要有"两者都成立"的理由，别打包硬上。

### 4. 下列哪一项**不是**事件溯源要付的"重账"（10分）

- A. 事件 schema 演进（旧事件要 upcasting 迁移）
- B. 快照管理（否则重放成本失控）
- C. 写后读的投影最终一致（UI 要处理滞后）
- D. 从此不用再写任何业务校验

> 答案：D
> 解析：ES 不减业务校验；四笔重账是 schema 演进/快照/最终一致 UI/存储增长，D 是幻觉。

### 5. ADR（架构决策记录）最核心的价值是（10分）

- A. 记录代码怎么写
- B. 永久留住"当初为什么这么选、放弃了哪些替代方案"，防止决策失忆与反复重开议题
- C. 替代 code review
- D. 生成 API 文档

> 答案：B
> 解析：架构最贵的不是选错而是没人记得为什么；ADR 记背景/决策/后果/替代方案，尤其"放弃了什么、为什么"最值钱。

### 6. 关于 CQRS 的读写两侧职责，下列说法正确的有（多选）（10分）

- A. 命令侧走充血领域模型，负责校验不变式与事务
- B. 查询侧可绕过领域模型，面向视图用轻量 DTO/物化视图自由 JOIN
- C. 把查询也套进聚合、为一个列表页加载 8 个聚合根再 map 是反模式
- D. CQRS 要求读写必须用两种不同的数据库

> 答案：A、B、C
> 解析：D 错——异构存储只是 CQRS 的最高档，不是要求；第一档读写同库不同视图即可。

### 7. 关于事件不可变性与 ADR 纪律，正确的有（多选）（10分）

- A. ES 的历史事件一旦写入就不可 UPDATE/DELETE，否则审计与重放失真
- B. ADR 应轻量（一页纯文本、进代码仓库、跟 PR 走）
- C. 修改架构约束的 PR 必须链接或新增 ADR，评审时即检查——这是"强制"的一面
- D. ADR 只需写结论，背景与替代方案可省略

> 答案：A、B、C
> 解析：D 错——只记结论不记背景/替代方案会让 ADR 退化成没人读的 wiki；"放弃了什么、为什么"才是精髓。

### 8. 判断："对没有真实状态演进的简单字典表，也应当采用事件溯源以获得审计能力。"（5分）

- A. 正确
- B. 错误

> 答案：B
> 解析：字典表无状态演进，上 ES 徒增事件表与投影维护、零收益；ES 用在真正有"事件流即业务真相"价值的聚合上。

### 9. 简答题：分别说明"只用 ES 不用 CQRS"和"只用 CQRS 不用 ES"的合理场景，并解释为什么不该无脑全家桶。（15分）

> 参考答案：
> - 只用 ES 不用 CQRS：需要完整审计/时间旅行/合规留痕的领域（如账户、订单状态流转），读需求并不复杂，事件流提供真相与可重放
> - 只用 CQRS 不用 ES：读写复杂度冲突、列表/报表要多样高性能视图，但不需要历史事件——读写模型分离同库即可
> - 都成立才全家桶：既要事件真相又要异构读写伸缩，两个理由都要各自站得住
> - 不该无脑上：每个都是重型武器，ES 四笔账(schema 演进/快照/最终一致/存储)、CQRS 异构的一致性代价，需求不到就是自找复杂度

### 10. 简答题：写一份合格的 ADR 至少包含哪几段？为什么说它"轻量但强制"？（10分）

> 参考答案：
> - 四段缺一不可：背景（当初的约束与痛点）、决策（做了什么选择）、后果（正负影响）、替代方案（考虑并否决了什么、为什么）
> - 常带状态字段：已采纳/已废弃/被某 ADR 取代，让决策可被后续推翻且留痕
> - 轻量：一页 markdown、纯文本、进代码仓库随 PR 走，不新建流程与工具
> - 强制：改架构约束的 PR 必须挂 ADR、评审即检查，否则目录会退化成无人读的 wiki
> - 加分点：点出 ADR 最值钱的是记录了"放弃了什么、为什么"
