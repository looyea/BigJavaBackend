# 与 ELK 选型对比（关联） · 作业

## 作业 1：日志分类与路由判据（分析题）

**目标**：把"按类别分流"从口号变成可执行的判据表。

**任务**：给你所在系统（或虚构电商）的 8 类日志（下单流水、支付回调、风控命中、K8s 事件、应用 debug、慢 SQL、审计操作、Nginx access），逐类填写：是否需任意词全文检索 / 是否合规留存及期限 / 排障主姿势 / 日增量级 → 得出落点（Loki / ELK / 双写）与保留期。

**验收标准**：至少两类判为"双写"、两类判为"纯 Loki"、两类判为"纯 ELK"；给出每个"合规红线覆盖成本考量"的判断实例；对"审计操作日志"要明确正式记录归属哪一侧。

**参考解法要点**：审计/支付回调偏 ELK（组合全文 + 留存），K8s 事件/debug 偏 Loki（海量翻上下文），慢 SQL/风控命中可能双写（既要全文又要趋势）。

## 作业 2：降本方案设计与成本对比（工程题）

背景：全量 ELK 日增 400GB，SSD + 双副本，保留 30 天，月账单爆表；其中 80% 是平台/debug。

**任务**：
1. 现状账：估算 ES 存储量（含膨胀与副本）与月成本量级；
2. 目标态：80% 转 Loki（对象存储、14 天）、20% 留精简 ELK（ILM 冷热、hot 7d + snapshot）——重算两边容量与总成本；
3. 给出采集端条件路由配置（Logstash if/else 或 Alloy match stage）实现按 level/app 分流双写；
4. 写迁移四步（影子双写→切读→观察→停旧）与回退红线。

**验收标准**：成本对比表能复算且给出"降本比例"区间；路由配置语法正确；明确说明"降本主要来自免全文索引 + 对象存储，而非少存数据"。

## 作业 3：架构评审陈述（文档题）

模拟评审会，回答"为什么不全用 Loki / 不全用 ELK"。**验收标准**：论述必须包含——两栈"复杂度落点"对比、按日志类别分流的边界、一条被明确划给 ELK 的合规需求、一条被明确划给 Loki 的海量需求、以及"如果只能选一个"时的决策依据与代价声明；禁止"因为熟/因为贵"的非原理性理由。
