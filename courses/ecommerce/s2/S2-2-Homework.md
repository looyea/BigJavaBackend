# 购物车、搜索推荐与售后逆向履约 · 作业

### 作业 1：实现购物车合并与结算前实时校验

- 目标：验证"合并不丢 + 结算复核"两道防线。
- 任务：用 Redis Hash 存购物车；实现未登录临时车与登录永久车按 SKU 合并（明确取 max/累加口径）；进入结算时逐项复核库存、价格、上下架、促销，不符则提示并给出可继续项。
- 验收标准：合并不丢件也不重复累加；构造"加购后商品改价/下架"的用例，结算能拦截或重算，不信任前端金额。
- 参考解法要点：合并前拉取两侧分别的 SKU 数量再按口径计算；校验复用促销/库存服务；把"失效商品"从可结算集合剔除。

### 作业 2：给搜索/推荐做降级兜底

- 目标：确认非核心依赖不阻断主交易。
- 任务：为商品列表接入搜索召回与推荐排序；对二者调用加超时 + 熔断，异常/超时返回默认榜单或按上架时间兜底；验证推荐服务宕机时下单不受影响。
- 验收标准：推荐/搜索被人为打挂后，列表页仍能展示兜底结果、下单主链路成功率不降。
- 参考解法要点：搜索深翻页用 search_after 或限深；降级结果可缓存；明确降级开关与恢复条件（呼应高可用降级体系）。

### 作业 3：实现退换货逆向状态机与幂等退款

- 目标：把"先质检后退款、退款不重复"落成状态流转。
- 任务：定义 `申请→审核→寄回→收货质检→退款/拒绝→关闭` 状态机，只允许合法跃迁；退款金额按 SKU 优惠分摊计算；退款异步回执幂等入账；退货库存按"可否二次销售"回补且幂等。模拟重复回调与非法跃迁。
- 验收标准：重复退款回执只退一次；"未质检即退款"的非法跃迁被拒；累计退款不超实付；回补库存不重复。
- 参考解法要点：状态字段做 CAS 乐观锁防并发；退款以退款单号为幂等键；分摊口径取自订单快照，与支付对账联动。
