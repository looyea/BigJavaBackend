# 促销价格计算与优惠券引擎 · 作业

### 作业 1：实现带版本号的优惠计算管线

- 目标：把"到手价 + 每项优惠 + 按 SKU 分摊"算成确定、可重放的结果。
- 任务：按"原价→单品直降→满减→平台券→店铺券→积分抵现"实现规则链，叠加/互斥用配置矩阵；给规则集打版本号，试算与下单结算都用同一版本并对账。
- 验收标准：同一购物车相同版本两次计算字节一致；改一个优惠顺序能观察到最终价差异并解释原因；产出每 SKU 分摊明细。
- 参考解法要点：管线每步产出结构化优惠项并即时分摊到 SKU；版本不存在或不匹配则拒绝结算，防"试算 A 版、结算 B 版"。

### 作业 2：做一个防超发、可回退的优惠券模块

- 目标：券=资金，按总量原子发放、按状态机核销。
- 任务：实现领取（券池 Redis Lua 原子扣 + (user,coupon) 唯一约束限领 + 令牌桶限流）与核销（下单锁券→支付成功置已用→取消/超时回退，幂等）。模拟并发抢券与重复核销。
- 验收标准：并发抢券不超发、不重复领；核销重复请求只扣一次；未支付取消能把券退为可用。
- 参考解法要点：预算扣减与领取记录同事务/可对账；核销以券实例 ID 为幂等键；回退路径覆盖取消、超时、支付失败。

### 作业 3：按优惠分摊实现"不多退"的退款计算

- 目标：让"凑单满减后退主件"薅不到羊毛。
- 任务：基于订单明细里的优惠分摊，计算部分退款时该 SKU 的实付应退额；校验累计退款 ≤ 实付。构造"两商品凑满减、退其一"的用例验证。
- 验收标准：退款按分摊后实付而非原价；多次部分退不超退；对账可还原每单优惠与退款构成。
- 参考解法要点：优惠分摊口径来自下单快照，不随后续活动变化；退款也走独立流水并幂等，与支付对账联动。
