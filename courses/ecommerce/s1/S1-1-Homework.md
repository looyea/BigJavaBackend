# 下单链路与库存扣减 · 作业

### 作业 1：实现"预扣—实扣—回补"三段式库存

- 目标：掌握 Redis 原子预扣与 DB 最终扣减的协同及幂等。
- 任务：用 Redis Lua 实现"库存足够才扣"的原子预扣；支付成功后 DB 实扣；取消/超时/建单失败回补。所有动作以订单号为幂等键。
- 验收标准：并发下不超卖；任一失败路径库存都能正确归还；重复回补不多加库存。
- 参考解法要点：Lua 判 `left>=qty` 再 `DECRBY`；预扣/回补记录状态防重复；建单异常即时归还。

### 作业 2：用延迟消息实现超时未支付自动关单

- 目标：用精确延时替代全表扫描，且处理关单与支付的并发。
- 任务：下单投递"30 分钟后关单"延迟消息，到期检查仍未支付则置为已取消并回补库存；构造"关单瞬间用户支付"的并发场景验证互斥。
- 验收标准：到期能自动关单释放库存；并发下关单与支付只有一个状态跃迁成功，不出现"既取消又支付/重复回补"。
- 参考解法要点：状态机 CAS（待支付→已取消 / 待支付→已支付）；回补也幂等；消息重复投递要能安全重入。

### 作业 3：订单快照与价格二次校验

- 目标：杜绝"改价纠纷"和"前端改金额薅羊毛"。
- 任务：下单时把商品名/规格/成交单价/优惠分摊写入订单明细快照；结算服务端按快照/试算口径重算金额并与前端提交价比对，不符则拒单；商家事后改价验证历史订单不受影响。
- 验收标准：篡改前端金额被服务端校验拦截；改价后历史订单金额、售后退款口径仍按下单快照计算。
- 参考解法要点：优惠按明细分摊留存以支持比例退款；对账/售后一律以快照为准不实时读商品表。
