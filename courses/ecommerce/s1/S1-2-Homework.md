# 支付与对账体系 · 作业

### 作业 1：实现幂等 + 验签的支付回调处理

- 目标：让同一笔回调重复推送也只入账一次。
- 任务：写回调接口：先验签，再按渠道单号定位支付流水；已支付直接返回成功 ACK；金额/状态核对通过才更新订单；状态更新用唯一约束或乐观锁保证幂等。模拟渠道连续推送 3 次同一回调。
- 验收标准：3 次回调只入账一次、只发一次发货事件；伪造签名的回调被拒；每次返回体都是渠道要求的成功 ACK。
- 参考解法要点：以渠道单号 + 状态做幂等键；处理失败返回非 ACK 促重试、成功返回 ACK 停推；更新与事件同事务或走 Outbox。

### 作业 2：主动查单兜底防掉单

- 目标：不依赖回调也能收敛"已付款未记录"的订单。
- 任务：对"处理中"超过 N 分钟的支付流水，定时向渠道查单；查到已成功则走与回调相同的幂等入账路径；与超时关单用状态机互斥。
- 验收标准：人为丢弃回调后，查单任务仍能补记为已支付；查单与关单并发时只发生一次合法状态跃迁。
- 参考解法要点：查单复用回调的入账逻辑（同一幂等入口）；避免与关单竞争，用 CAS 状态机；查单要限频、错峰，别压垮渠道。

### 作业 3：与渠道逐笔对账并处理三类差错

- 目标：把"账实相符"做成可自动化的日常流程。
- 任务：拉渠道 T+1 账单，与本地流水按渠道单号逐笔 diff，分类：我方有渠道无(掉单/短款)、渠道有我方无(长款)、金额不符；对长款自动补单或退款、掉单走告警，全部进差错池留痕。金额统一用整数分。
- 验收标准：能准确产出当日差错清单并区分三类；长款/掉单能自动或半自动闭环；构造"总额相等但两笔对冲差错"的数据时逐笔 diff 仍能发现。
- 参考解法要点：以最小货币单位存金额避免浮点；退款/补单幂等且原路返回；对账任务可重跑不产生重复处理。
