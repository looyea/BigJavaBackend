# 与 Gatling 选型对比（关联） · 作业

## 作业 1：同题双解实验（动手题）

**目标**：同一压测需求分别用两个工具实现，产出第一手的对比数据。

**任务**：
1. 需求统一："2000 虚拟用户、思考 1s、压 GET /items 列表接口 5 分钟，断言业务码 0，报 P99"；
2. JMeter 实现（含 CSV/断言/非 GUI 命令）与 Gatling 实现（simulation DSL）各一份，记录：脚本行数、写出第一版可跑脚本耗时、运行 1500 并发时压力机内存占用；
3. 把两份脚本互换给同事做 5 分钟可维护性评分（能否看懂/敢不敢改）；
4. 汇总成一页选型备忘。

**验收标准**：三项量化数据齐全；备忘含"我们团队该选谁+为什么"的明确结论。

## 作业 2：压力模型纸面推演（工程题）

**目标**：不跑压测也能判断"线程模型够不够用"。

**任务**：估算模拟 50000 虚拟用户（平均 RT 200ms、思考 800ms）时：①JMeter 线程模型的线程数、栈内存（1MB/线程估）、到达率；②Gatling 异步模型以 1 万连接/核的常见容量级需要几台 4C 压力机；③给出"什么量级以后必须换模型/上云"的分界建议。

**验收标准**：三问都有算式与结论；能口述"为什么线程数≠虚拟用户到达能力"。

## 作业 3：双轨共存规范（文档题）

**任务**：为团队起草《压测工具双轨规范》：哪类场景归 JMeter（非开发维护、协议冷门、一次性）、哪类归 Gatling（核心链路、CI 门禁、需版本化）；统一报告模板（口径、分位族、压力机自证清单）；公共资产（造数脚本、环境标签）如何共享避免两套数据腐化。

**验收标准**：每条归属规则可判定（有例子）；包含"同一接口两工具结果打架时的仲裁流程"（以原始样本重算为准）。
