# 组件模型与非 GUI 执行 · 小测

## 一、单项选择题（每题 6 分，共 42 分）

### 1. JMeter 线程组里的"线程"最准确的理解是？（6分）

- A. 操作系统意义上的真实用户浏览器
- B. 一个串行执行元件树的虚拟用户，循环内请求是一个接一个发的
- C. 与服务端一一对应的长连接
- D. Java 虚拟线程
> 答案：B
> 解析：线程=虚拟用户，循环体内串行；所以"100 线程"不等于"100 个并发请求在同一毫秒打出"，配合思考时间才能贴近真实到达率。

### 2. 正式压测为什么要用 `jmeter -n` 非 GUI 模式？（6分）

- A. GUI 不能加断言
- B. GUI 会渲染结果树/消耗大量内存，压力机自身先成瓶颈，测的是笔记本性能
- C. 非 GUI 才支持 CSV
- D. GUI 模式发的请求没有响应时间
> 答案：B
> 解析：GUI 定位为编写与调试计划；`-n -t plan.jmx -l r.jtl -e -o report` 是标准执行式，跑完直接出 HTML 报告。

### 3. 压测运行时监听器（查看结果树等）应如何处置？（6分）

- A. 全部开启方便排错
- B. 全部禁用/不加入运行时计划
- C. 只留图形结果
- D. 换成 JSR223 也一样
> 答案：B
> 解析：结果树类监听器在内存里攒样本，大并发下 OOM 或拖累吞吐；排错用日志与 .jtl 事后分析。

### 4. 业务接口返回 HTTP 200 但 body 里 `{"code":50001}`，聚合报告错误率却是 0%，原因是？（6分）

- A. JMeter 统计 bug
- B. 未配置断言，JMeter 只按 HTTP 层判成功
- C. 线程数太少
- D. 需要开 keep-alive
> 答案：B
> 解析：必须加响应/JSON 断言把业务码纳入判定——"没有断言的绿比红灯更危险"。

### 5. 想让 100 个线程并发争抢同一批订单号来测锁冲突，CSV Data Set Config 应设？（6分）

- A. Current thread 模式每线程一份切片
- B. All threads（shareAll）共享游标
- C. 每个线程复制一份 csv
- D. 改用随机函数即可
> 答案：B
> 解析：shareAll 让多线程从同一游标取数、数据可重叠；切片模式保证"各领各的号"，两种模式对应两类测试目的。

### 6. 要把登录响应里的 token 用于后续请求，标准做法是？（6分）

- A. 手工复制粘贴
- B. JSON 提取器抽取存变量，下游 ${token} 引用
- C. 全局参数即可
- D. 断言里顺便保存
> 答案：B
> 解析：这就是"关联"——提取器作用于本线程后续样本；忘记关联导致下游全 400 是新手第一坑。

### 7. 定时器的作用域是？（6分）

- A. 全局控制整场压测 QPS
- B. 每线程每样本前的等待，不能精确控总吞吐
- C. 只对第一个线程有效
- D. 与线程数无关
> 答案：B
> 解析：要精确控制到达率用吞吐量整形控制器（Precise Throughput Timer）或 Constant Throughput Timer，见下一节。

## 二、多项选择题（每题 9 分，共 18 分）

### 8. （多选）关于 JMeter 执行与配置的说法正确的有？（9分）

- A. `-Jthreads=500` 配合 `${__P(threads,100)}` 可不改计划调整并发
- B. 分布式压测用 `-R host1,host2`，数据 csv 需分发到各 slave
- C. 压测时应在 jmeter.properties 关闭响应体保存以省内存
- D. GUI 模式与非 GUI 模式的并发能力相同，只是看不看得见曲线
> 答案：ABC
> 解析：D 错——GUI 额外渲染开销会明显压低可模拟并发，两者容量不等。

### 9. （多选）以下哪些属于"测的其实是压力机自己"的表现？（9分）

- A. 加压线程数后 TPS 不再上升，且压力机 CPU 长期 >85%
- B. 响应时间里 "Connect Time" 占比暴涨
- C. 服务端监控显示 CPU 空闲、RT 平稳，但 JMeter 报大量超时
- D. HTML 报告正常生成
> 答案：ABC
> 解析：压力机饱和/端口耗尽/GC 停顿都会伪装成"被测系统瓶颈"；结论前先看压力机自身指标是铁律。

## 三、简答题（40 分）（每题 40 分，共 40 分）

### 10. 给出一份"下单接口"JMeter 计划的组装说明：元件清单、参数化与关联设计、断言策略、执行命令与运行纪律。（40分）

> 参考答案：
- 要点1：骨架=线程组（并发/ramp-up/循环或持续时长）+ HTTP 请求默认值 + 头部管理器统一 Content-Type；
- 要点2：业务链路：登录→JSON 提取 token→下单取样器（CSV 注入商品/用户参数）→取消订单；关联变量按线程隔离；
- 要点3：CSV 设计说明共享模式选择理由（幂等测试 shareAll 抢号，链路压测切片避免互踩）；
- 要点4：断言：HTTP 2xx + JSON 断言 code==0 + 关键回写字段存在，错误率以断言后为准；
- 要点5：执行：`jmeter -n -t order.jmx -l r.jtl -e -o report`，JVM_ARGS 堆 4g，监听器全禁、不存响应体；
- 要点6：纪律：先看压力机自身 CPU/网络/端口再下服务端瓶颈结论，必要时分布式并统一时钟。
