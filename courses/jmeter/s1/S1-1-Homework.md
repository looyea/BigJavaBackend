# 组件模型与非 GUI 执行 · 作业

## 作业 1：组装"登录-下单-取消"计划（动手题）

**目标**：从零搭出一份可交付的 .jmx，跑通参数化+关联+断言闭环。

**任务**：
1. 用本地 demo 服务（或用 wiremock/mockserver 桩一个）提供 login/create/cancel 三接口；
2. HTTP 请求默认值统一 host/port；登录响应 JSON 提取 token；用户与商品 id 来自 CSV（切片模式）；
3. 每个取样器挂 JSON 断言 `$.code == 0`；线程组 20 线程 ramp 10s 循环 5 次；
4. 分别以 GUI 与 `-n -e -o report` 跑一次，贴出报告截图与两者最大 TPS 差异。

**验收标准**：报告错误率>0 时能凭 .jtl 定位是断言失败还是 HTTP 失败；解释 GUI/非 GUI 差异来源。

## 作业 2：共享模式对照实验（工程题）

**目标**：证明"CSV 共享模式是测试语义的一部分"。

**任务**：
1. 造 1000 行订单号数据，写一个"按订单号核销"接口（内存 map 即可，重复核销返回 409）；
2. 模式 A（Current thread 切片）200 线程压：错误率应为 0；
3. 模式 B（All threads + recycle）同参数重压：出现大量 409——这就是"抢号并发"的正确打开方式；
4. 结论写成一句可放进测试报告的表述。

**验收标准**：两次错误率对比截图；能说出幂等/锁冲突类测试为何必须 shareAll+循环回收。

## 作业 3：压力机自证清白清单（文档题）

**任务**：编写一页"下瓶颈结论前的压力机体检清单"：CPU/负载（`top`、`vmstat`）、文件描述符与临时端口范围、TIME_WAIT 数量（结合 [Linux 排查](../../linux-shell/s1/S1-2-Lesson.md)）、JMeter 堆与 GC 日志、网卡带宽、与服务端的时钟偏差；每项给出观察命令、健康阈值、越界后对结果的影响形态。

**验收标准**：每个指标都有"它劣化时，报告上表现为哪种假瓶颈"的一一映射；包含至少一条"TPS 平台期先查压力机再查服务端"的判例。
