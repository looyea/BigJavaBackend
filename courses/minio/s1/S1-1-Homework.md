# 课后作业：MinIO 架构与上传下载模式

## 作业 1：纠删码部署与容量规划（35分）

场景：需要存储 500TB 监控视频文件（平均每个文件 2GB），要求容忍单节点故障不丢数据。

要求：
1. 选择合适的纠删码集配置（K/M），计算需要的最少磁盘数与每盘容量。
2. 对比"纠删码 EC(8,4)"与"三副本"在 500TB 有效数据下的总磁盘需求量，说明成本差异。
3. 画出 MinIO 多节点部署架构图（至少 4 节点 × 4 盘），标注网络要求（万兆互联）。
4. 讨论：如果某节点 1 块盘损坏，MinIO 如何自动修复？修复期间读写是否受影响？

## 作业 2：实现文件上传下载服务（35分）

要求：用 Spring Boot + MinIO Java SDK 实现：
1. 后端接口 `POST /api/upload/presign`：校验用户登录态 → 检查文件类型白名单(jpg/png/mp4) → 生成预签名 PUT URL（15 分钟有效），返回 URL + 对象 Key。
2. 后端接口 `POST /api/upload/confirm`：前端上传完成后调用 → HeadObject 确认存在 → 记录到 DB（file_key, user_id, size, upload_time）。
3. 后端接口 `GET /api/download/{key}`：校验用户权限 → 生成预签名 GET URL（1 小时有效）→ 302 重定向。
4. 大文件分片上传：对超过 100MB 的文件，使用 Multipart Upload API，实现断点续传（前端记录已上传 Part 列表）。

## 作业 3：安全与运维（30分）

要求：
1. 设计 MinIO 的访问控制策略：用 Bucket Policy + IAM 用户限制"只能操作自己上传的文件前缀"。
2. 写出防止以下攻击的配置/代码：路径遍历（../）、Content-Type 伪造、DDoS（连接数限制）、预签名 URL 泄露。
3. 设计生命周期规则：30 天前的监控视频自动转为冷存储层（Tier）；180 天后自动删除。
4. 备份方案：使用 `mc mirror` 做跨集群异步复制，写出命令与 crontab 配置。
