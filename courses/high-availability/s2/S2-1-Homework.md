# 冗余、健康检查与故障自动转移 · 作业

### 作业 1：探针分离与防抖配置

- 目标：让实例"该重启的重启、该摘流量的摘流量"，且不被瞬时抖动误杀。
- 任务：为一个 Spring Boot 服务配置 Liveness（仅判进程卡死）与 Readiness（判 DB/缓存/下游就绪）两个端点；在编排层设 `failureThreshold`/`successThreshold` 做防抖。模拟一次下游 5s 抖动，验证只摘流量不触发全量重启。
- 验收标准：依赖抖动时不误重启；进程真卡死能被 Liveness 判并重启；恢复后自动重新接流量。
- 参考解法要点：readiness 不进 liveness；用滑动窗口而非单次判定。

### 作业 2：主从自动转移与 fencing 验证

- 目标：主节点故障时新主接管、旧主被隔离，不出双写。
- 任务：搭一套带 leader 选举的主从（可用 ZK/etcd/哨兵思路），kill 主节点观察新主当选 + 服务注册摘旧重定向；再构造"旧主网络恢复后带着过期 fencing token 尝试写"，验证被拒。
- 验收标准：切换在预期超时内完成；旧主复活不能双写（fencing 生效）；流量正确重定向新主。
- 参考解法要点：奇数节点形成多数派；超时与防抖权衡切换速度与误判。

### 作业 3：脑裂场景演练与自动化边界设定

- 目标：证明分区时不双主，且"该保守时保守"。
- 任务：模拟网络分区把集群切成两半，观察是否只有多数派一侧能选出主、少数派侧降级只读/不可写；再模拟"探测抖动 + 多数派不可达"，验证系统选择保守不切而非乱切。总结有状态 vs 无状态服务的切换激进度差异。
- 验收标准：分区无双主双写；少数派侧不对外提供写；抖动场景不误切；给出"错误切换比不切更致命"的量化取舍说明。
- 参考解法要点：quorum + fencing 是防脑裂双保险；边界在于"不确定就别切"。
