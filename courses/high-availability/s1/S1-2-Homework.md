# 跨技术联动：降级与熔断体系 · 作业

### 作业 1：给一个远程依赖配齐"超时 + 熔断 + 降级"

- 目标：理解熔断依赖超时、降级要分读写边界。
- 任务：选一个 RPC/HTTP 下游，用 Sentinel 配置慢调用比例与异常比例两条熔断规则，分别实现读接口的兜底降级和写接口的"快速失败/转异步补偿"，禁止写接口假装成功。
- 验收标准：模拟下游变慢时能触发熔断走 fallback；读降级返回兜底数据、写降级明确失败或进入补偿队列，不出现"数据没写却返回成功"。
- 参考解法要点：先设调用超时再谈熔断；fallback 区分读(缓存/默认值)与写(拒绝/异步补)；半开探测恢复后自动闭合。

### 作业 2：用线程池/信号量做舱壁隔离

- 目标：亲手验证"一个慢依赖不拖垮全局"。
- 任务：让同一服务的两个下游 A(慢)、B(快) 分别走独立线程池与信号量隔离，压测时把 A 打到很慢；对比"共享一个大池"与"隔离"两种拓扑下 B 的成功率。
- 验收标准：隔离拓扑下 B 基本不受 A 变慢影响；给出隔离池大小随下游 RT×并发 的定容计算，并演示池配小/配大的后果。
- 参考解法要点：隔离粒度=依赖；池大小按压测定；慢且非关键的可配合较短超时 + 快速失败，避免线程被占满。

### 作业 3：编写一份降级预案并接入开关平台

- 目标：把手动止损做成可演练、可灰度、可回滚的开关。
- 任务：为交易链路列一张降级预案表（触发条件→关停/降级的非核心项→负责人→回滚条件），用配置中心（Nacos/Apollo）落地开关，并做一次演练验证开关生效与回滚。
- 验收标准：一键关停非核心后核心交易容量/依赖得到释放；开关可灰度、可回滚；检查并确保开关平台自身不在与业务相同的单点故障域内。
- 参考解法要点：预案书面化 + 平时演练；区分自动(熔断)与手动(开关)触发；特别核查控制面（配置中心/开关）自身的可用性，别让它成为新单点。
