# 单元化与异地多活、容量与演练 · 作业

### 作业 1：为一个业务设计单元化切分方案

- 目标：理解"按用户维度封闭单元"与"全局数据"的处置。
- 任务：给出一个交易系统的单元划分——选路由标（如 userId 取模分 N 段）、画出单元内闭环的组件（接入/应用/存储）、列出必须跨单元或走全局的数据（商品详情、库存全局余量），并说明各自同步方式。
- 验收标准：能论证"绝大多数用户请求在单元内闭环"，指出哪些数据是全局只读、哪些需跨单元协调，并给出对应的单向同步/缓存广播/全局单元方案。
- 参考解法要点：分片维度选能天然收敛写冲突的 userId；全局低频数据单向同步到各单元只读副本；强全局协调项（如全局限流/库存总量）集中处理并容忍延迟。

### 作业 2：设计一次异地多活切流与一致性取舍

- 目标：把"切流=RTO/RPO 权衡"落到具体步骤。
- 任务：为两地部署设计切流预案：正常态数据如何按单元各写、跨地域如何复制；当 A 地单元故障，如何改路由把其用户段切到 B 地、切换期间正在写入的事务怎么处理。
- 验收标准：给出明确的 RTO/RPO 目标与达成手段（同步/异步复制、复制位点校验），说明切换时"未复制完成的写"如何补偿或丢弃，避免脑裂双写。
- 参考解法要点：以单元为单位切、避免同用户两地同时写；切换前校验复制位点；用路由标隔离写域防冲突；回切同理演练。

### 作业 3：搭建全链路压测 + 混沌演练的验证闭环

- 目标：证明容量与预案"平时就灵"，而非纸面数字。
- 任务：设计一个用流量打标 + 影子库的全链路压测方案定出容量水位与限流阈值；再设计三类混沌注入（杀节点、依赖劣化加延迟、整单元切流回切）验证熔断/降级/切流。
- 验收标准：压测不污染生产数据、给出各单元 P99 下的容量与 80% 限流线；演练能实测 RTO 并记录暴露问题→改进项→复测的闭环。
- 参考解法要点：压测流量全链路打标透传到影子表；混沌从小流量/灰度环境起步、设爆炸半径上限与自动中止；复盘产出可验证改进而非检讨。
