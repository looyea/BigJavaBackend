# 分片算法与跨库查询改写 · 作业

## 作业 1：路由命中率审计

**目标**：用真实 SQL 流量验证分片键选择。

1. 采集一周慢日志/网关 SQL，统计 WHERE 含 user_id 的比例。
2. 低于 90% 的查询逐条给出改造方案（冗余索引表 / 改 Hint / 走 ES）（输出：改造清单）。
3. 在测试库开 ShardingSphere 的 SQL 解析日志，确认无广播查询漏网（验收：explain 无 FULL_ROUTE）。

## 作业 2：深分页放大实测

**目标**：量化 offset 分页的代价曲线。

1. 4 分片造数各 100 万行，压测 `LIMIT 0,10 / 10000,10 / 100000,10` 三档 P99 与中间件内存。
2. 改游标分页重测 → 画出两条代价曲线对比（结果：游标恒定 vs 线性恶化）。

## 作业 3：基因法主键设计

**目标**：让按订单号查询命中单分片。

1. 实现 `order_id = snowflake_seq << 4 | user_id % 4`，写入 4 库数据。
2. 按 order_id 查询 → explain 只命中 1 库（输出：路由结果单片）。
3. 故意去掉基因位重测 → 广播 4 库（错误用例对照，感受差距）。
