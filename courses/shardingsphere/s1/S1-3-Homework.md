# 数据脱敏、压测影子库与治理实战（关联） · 作业

### 作业 1：给敏感列配列级脱敏并验证所有出口

- 目标：把手机号、身份证的掩码从业务代码下沉到数据访问层，验证接口/导出/日志都拿不到明文。
- 任务：用 ShardingSphere MASK 规则对 `t_user.phone` 配置 `*` 掩码、`id_card` 配置 MD5；分别通过查询接口、导出报表、打印日志三条路径取数，确认均已被脱敏。再故意把规则关掉，复现"页面手工掩码但导出仍是明文"的泄露，然后恢复。
- 验收标准：规则开启时三条出口都拿不到明文；能说清"展示脱敏≠落盘加密"，并指出落盘敏感字段应走加密+KMS。
- 参考解法要点：MASK 算法类型（CHARACTER 掩码 / MD5 一致性）；强调规则收敛到一处才可审计。

### 作业 2：搭一套影子库跑大促压测

- 目标：用真实分片规则压测下单写链路，且压测数据与生产完全隔离。
- 任务：为 `t_order` 配置影子表 `t_order_shadow`，压测请求带影子标记、正常请求不带；跑一轮写压后统计生产表行数不变、影子表承接全部压测写。随后人为在异步线程里丢掉影子标记，复现"压测写误落生产表"，再修复为全链路透传。
- 验收标准：影子标记正常时生产表零污染；能复现并解释标记丢失导致污染的路径；给出 MQ/线程池处透传标记的做法。
- 参考解法要点：Shadow 算法 + 压测标记判定；跨线程用 TransmittableThreadLocal/消息头携带标记。

### 作业 3：单库→分片库的迁移治理与切流校验

- 目标：安全地把单库数据迁到分片库并在切流前用校验拦下数据缺失。
- 任务：用迁移工具做全量+增量搬迁；切流前执行三查——老库总行数 vs 各分片求和、抽样按分片键路由核对落片是否正确、逐行校验和比对。故意漏迁一个分片，观察校验能否阻断切流，再补齐。
- 验收标准：能给出"行数相同但校验和不符"也应拦截的判据；切流按"灰度切读→观察双写差异→切写"分步执行。
- 参考解法要点：DistSQL 查询治理状态；校验维度要覆盖"数量+内容+路由"三者。
