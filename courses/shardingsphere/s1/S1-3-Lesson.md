# 数据脱敏、压测影子库与治理实战（关联）

> 本节难度：★★★★☆
> 本节重要性：★★★★☆
> 学习产出：能在分库分表中间件（以 ShardingSphere 为例）里把"数据怎么用得安全、压得动、迁得稳"三件事落地。**数据脱敏（MASK）** 用注册脱敏规则，在查询结果返回时按列把手机号/身份证/银行卡等做掩码或哈希，把"脱敏"从业务代码下沉到数据访问层，避免每个 DAO 各写一套、漏写即泄露。**影子库（Shadow）** 为压测流量单独路由到一套影子表/库，与生产数据物理隔离，靠影子逻辑开关识别压测标记，做到"用真实分片规则压测但不污染线上"。**数据治理**涵盖迁移后的元数据一致性校验、分片配置热更、以及和迁移工具（Distball）配合的全量+增量搬迁与切流。要点：脱敏规则要区分"展示掩码"和"存储加密"两个层次，别把可逆脱敏当加密；影子库的标记传递必须全链路贯穿否则漏判；治理校验要能发现分片键变更后新老路由不一致。识破"脱敏规则只挡了查询、导出报表又漏原文""压测流量没带影子标记直接写进生产表""迁移后没做行数/校验和比对就切流导致数据缺失"等坑。

## 一、脱敏规则：把掩码下沉到数据层

```yaml
# 目的：用 SHARDING_SPHERE 的 MASK 规则把手机号在结果返回时自动掩码, 业务层拿不到明文
rules:
  - !MASK
    tables:
      t_user:
        columns:
          phone:
            maskAlgorithm:           # 说明：指定列绑定脱敏算法, 查询命中即自动处理
              type: MASK USING CHARACTER '*' # 结果：手机号中间四位以 * 覆盖, 用于展示脱敏
          id_card:
            maskAlgorithm:
              type: MASK MD5         # 说明：需要"不可还原地一致"时用 MD5, 便于比对但不保留原文
    # 反例：只在页面 if 里 substring 掩码 ❌ 导出/日志/接口仍拿到全量明文, 泄露面没收敛到一处
```

## 二、影子库：用真实分片压测而不污染生产

```text
图目的：影子库如何把"压测流量"和"生产数据"在同套分片规则下物理隔离
生产请求 ──(无影子标记)──▶ 生产表 t_order
压测请求 ──(带影子标记)──▶ 影子表 t_order_shadow(同分片算法、独立存储)
关键: 影子标记必须全链路透传(MQ/线程池/异步都要带上), 否则压测写误落生产表
价值: 压的是真实分片路由/连接池/索引, 结果可信; 数据互不污染
```

## 三、治理与迁移校验

```java
// 目的：分片迁移切流前的"对得上"三查——行数、分片键路由、校验和, 任一不符即拦截切流
long src = count(sourceTable);                 // 说明：老库总行数
long dst = countAllShards(targetLogicTable);   // 结果：新库各分片求和, 两者必须相等, 否则有分片漏迁
// 反例：只比总量不比按分片键的哈希校验 ❌ 行数相同但内容错位/丢列照样发现不了 ❌ 应叠加逐行 checksum
if (src != dst) throw new IllegalStateException("迁移行数不一致, 禁止切流");
```

## 四、坑与底线

- **脱敏分层**：展示掩码（可逆、护隐私观感）与存储加密（不可逆/可解密、护落盘）是两回事，别把 MASK 当加密，落盘敏感字段要另走加密算法与 KMS。
- **影子标记全链路透传**：压测标记一旦在某跳（异步、MQ、线程池）丢失，后续写就打到生产表，污染线上且难以回收。
- **切流前必须治理校验**：迁移后先做行数/分片路由/校验和比对并观察双写差异，再灰度切读、最后切写，杜绝"迁完即全量切"的数据缺失事故。
