# 分布式 ID 方案与取舍 · 作业题

> 本节作业 3 题：发号器压测对比、workerId 租约化改造、一份 ID 规范评审。

## 作业 1：三种发号方案压测横评（动手）

实现或借用现成库跑三套发号：UUIDv4、UUIDv7、雪花（含回拨防护），各 16 线程发 1000 万：

- 记录吞吐、P99、内存分配率；
- 把三套 ID 分别插入同构 MySQL 表（BIGINT 主键 vs CHAR(36)），对比插入 TPS 与页分裂指标（`SHOW ENGINE INNODB STATUS` 的 splits）；
- 输出一张"发号成本 + 落库成本"总账表，验证"UUID 的问题在落库不在发号"。

**验收标准**：数据必须体现 CHAR36 随机主键的插入吞吐显著低于 BIGINT 趋势主键。

## 作业 2：给雪花实现接上"租约化 workerId"（动手）

1. 用 etcd（或 zk）写一个 workerId 分配器：`lease 30s + Put(key=worker/007, lease)`，启动抢注、续约、崩溃自动释放；
2. 起 4 个发号实例循环重启 20 次，断言任何时刻无两实例持有同一 workerId、重启后不发历史号段重复 ID；
3. 注入故障：etcd 全挂时验证存量实例继续发号（运行期弱依赖）、新实例启动失败并报明确错误。

**交付物**：分配器代码 ≤100 行 + 故障矩阵测试结果表。

## 作业 3：ID 规范评审报告（分析）

以下"历史设计"摘自虚构评审单，请指出至少 5 个问题并给出修订版规范：

> 订单号 = 渠道码(2位) + yyyyMMddHHmmss + 用户ID后4位 + 自增序列(4位)；退款单号 = 原订单号 + "-R"；序列由 MySQL 单库自增表直接每次 +1 获取。

**提示检查点**：中心依赖频率、信息泄露（用户号+时间可遍历）、语义入键、变长 ID 的索引代价、跨渠道合并冲突、时钟/序列位数规划。
