# 逻辑时钟、全局有序与幂等去重 · 实际面试题

## 题 1：为什么分布式系统不能直接用机器时间戳排序事件？

**考察点**：对时钟漂移/回拨的认知深度。

**参考答案**：三点：晶振漂移使两台机器秒级偏差常态化；NTP 大纠偏会 step 回拨；崩溃重启使"该节点已发出的未来时间戳"被回退复用。所以跨节点比"谁先"必须靠逻辑构造：Lamport（全序近似）、向量（因果判别）、或干脆单点定序（Leader 发号）。

**追问**：那 Kafka 的 message timestamp 能当顺序用吗？——partition 内顺序由 offset 决定（LogAppendTime/CreateTime 只用于查询过滤），排序真相永远是 Leader/broker 的单调序号。

**加分点**：能说出 HLC 的构造（物理部分+逻辑进位部分）以及它如何在漂移时退化为 Lamport。

## 题 2：Lamport 时钟和向量时钟各解决什么问题？举例说明 Lamport 会"排出假先后"。

**考察点**：两个概念的边界。

**参考答案**：Lamport：便宜的因果保序编号——A→B 必有 LC(A)<LC(B)，用于需要统一回放序的场景；但两个并发事件也会被编号排出先后（假因果）。向量时钟：逐维比较可判"因果/并发"两态，Riak/Cassandra 分叉检测用。工程直觉：只要求"大家看到同一顺序"用 Lamport 或 Leader 序号；要求"识别哪些更新互相冲突需要合并"才上向量。

**追问**：向量时钟的开销问题怎么缓解？——剪枝（只记近期因果）、Dotted VV、或降维成 causal counter 位图。

## 题 3：线上雪花 ID 服务凌晨重启后报主键冲突，怎么定位与根治？

**考察点**：时钟回拨实战。

**参考答案**：定位：查 NTP 纠偏记录/宿主机迁移记录，确认重启前后时钟回拨；冲突=回拨区间与已发号毫秒段重叠。根治分层：① 发号器内单调时钟封装（now 与 last 取 max+1）；② 回拨超阈值快速失败并告警，绝不静默等待超过 RT 预算；③ workerId 从 zk/etcd 租约获取，防止克隆机/快照恢复导致双实例同 ID 段；④ 兜底：数据库唯一约束让冲突可见而不是悄悄覆盖。

**追问**：为什么不直接换 UUID？——UUID v4 无序导致 InnoDB 主键随机插入页分裂；能说出 UUIDv7/有序 UUID 折中方案更佳。

## 题 4：MQ 消费者幂等，你会怎么设计？面试官追问"Redis 去重够了吗"。

**考察点**：三层防线的必要性论证。

**参考答案**：不够，Redis 只能当减震：① SETNX 占位可能因主从丢消息、过期、集群迁移而失效；② "查缓存→执行→写缓存结果"非原子，并发重投会双执行。标准结构是三层：前置 Redis 挡量 → 业务表唯一键（订单号+操作类型）原子兜底 → 状态机条件更新防重复流转；"处理中"要占位并带超时恢复（否则执行失败后重试被占位挡住，需定时把超时占位置为可重试）。

**追问**：消费失败重试 16 次后进死信，人工补单又点了一次，哪层防线生效？——唯一键撞库返回"已处理"；强调幂等键必须业务语义（人工补单是新 messageId 同订单号）。

## 题 5：Spanner 为什么敢用物理时钟实现外部一致？普通公司能复制吗？

**考察点**：TrueTime 原理与成本判断。

**参考答案**：TrueTime 把"不确定区间 [now-ε, now+ε]"作为一等公民 API，ε 由 GPS+原子钟压到 <10ms 且可被监控；事务提交前 commit wait 等区间过去，保证任何观测者看到的提交顺序与真实时间一致。普通公司复制不了硬件栈，等价工程替代：单点定序（Raft Leader）、HLC（接受"逻辑序近似时间"）、或缩小强一致范围（单元化）。

**追问**：commit wait 对延迟的影响量级？——每事务多等 2ε（几十 ms），所以 Spanner 只在跨分片 2PC 用；单机分片走 Paxos 多数派不必等。

## 题 6：设计题：给"每日定时对账文件处理"设计幂等，文件可能被重复推送、处理到一半进程崩溃。

**考察点**：批处理幂等的完整闭环。

**参考答案**：批次键=文件名+内容哈希入 batch 表 UNIQUE；状态机 INIT→RUNNING→DONE 带心跳超时（崩溃的 RUNNING 由接管者按水位线重放）。明细行幂等：每行流水号唯一键 + `ON DUPLICATE KEY` 忽略；重放从"已成功行水位"之后继续，避免全表重跑。关键取舍：行级唯一键 vs 整批删除重插——数据量大且下游只关心终态时用"影子表换名"，天然幂等。

**追问**：文件内容相同但推送了两次，第二次要不要重处理结果？——DONE 态直接返回上次结果快照；这要求结果可回放存储（处理产出落表而非只发内存事件）。
