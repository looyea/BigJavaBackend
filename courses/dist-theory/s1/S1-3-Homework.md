# 逻辑时钟、全局有序与幂等去重 · 作业题

> 本节作业 3 题：一个发号器加固、一场去重竞态实验、一份幂等审计。

## 作业 1：给雪花 ID 加"回拨保险"（动手）

基于任意开源雪花实现（自己写 ≤80 行也可）：

1. 用 `date -s` 或代码模拟时钟回拨 2 秒，复现重复 ID（多线程并发发号断言唯一性失败）；
2. 实现三种策略并对比：回拨 <5ms 自旋等待、5ms~2s 借用上一毫秒序列号扩位、>2s 直接抛异常拒绝发号并告警；
3. 输出压测数据：每种策略下的发号吞吐与 P99。

**验收标准**：断言脚本 0 重复；能解释"为什么等待窗口不能设成任意大"（下游 RT 预算）。

## 作业 2：复现并修复"先查后插"竞态（动手）

1. 建表 `t_dedup(id, biz_no, amount)` **不建唯一索引**，写一个"查不存在则插"的消费方法；
2. 用 200 线程并发消费同一 `biz_no`，统计重复行数（预期 >1）；
3. 加 UNIQUE(biz_no) 后重复实验，改造为 `INSERT ... ON DUPLICATE KEY UPDATE id=id`，统计影响行数=0 的比例即拦截率；
4. 追加方案：Redis SETNX 前置挡重复（减少撞库开销），说明为什么它只能当"减震器"不能当"闸"。

**验收标准**：给出修复前后重复行数据对比 + 三层防线的时序图（谁先谁后、失效顺序）。

## 作业 3：一次真实链路的幂等审计（分析）

挑你系统（或开源项目，如 mall、ruoyi）的一条支付/发货链路：

- 列出所有"可重入点"：HTTP 重试、MQ 重投、定时任务补偿重跑、人工补单；
- 检查每个重入点是否有幂等键、键是否业务语义、兜底是否唯一约束；
- 找出一处缺失并给出补丁（SQL + 代码 diff 描述）；
- 特别检查"处理中"占位是否存在：无占位则并发穿透，写明你选的实现（Redis SETNX 占位 + DB 终态双保险）。

**交付物**：重入点清单表 + 至少一个真实补丁。
