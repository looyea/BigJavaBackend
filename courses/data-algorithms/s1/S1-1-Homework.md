# 作业题 · 复杂度分析与大 O 思维

> 共 3 题，均为"动手能验证"的工程题。做完对照验收标准自检；参考答案思路附在末题之后。

## 作业 1：揪出并修复隐性 O(n²)（必做）

**背景**：营销系统有如下"给一批用户打标 VIP"的代码，用户规模 10 万，VIP 名单 5 万，接口耗时 8s 超时。

```java
Set<Long> vipIds = queryVipIds();          // List<Long>
List<User> users = queryUsers();           // 10 万
for (User u : users) {
    if (vipIds.contains(u.getId())) {      // vipIds 实际是 ArrayList
        u.markVip();
    }
}
```

**要求**：

1. 指出这段代码的复杂度与瓶颈所在。
2. 给出优化后的写法，说明优化后复杂度。
3. 若 VIP 名单不能全量放本地内存（有 5000 万），你会改用什么方案？

**验收标准**：

- 能说清 `ArrayList.contains` 是 O(m)，嵌套循环 → O(n·m)。
- 优化为 `HashSet` 或先排序，降到 O(n+m)。
- 超内存场景给出 Redis `SISMEMBER`/布隆过滤器/分批 的方案与代价。

## 作业 2：容量预算反推（必做）

**背景**：接口 SLA 要求 P99 < 200ms，单机估算每秒可执行约 10⁸ 次基础操作。

**要求**：

1. 一次请求可用的操作预算大约是多少？
2. 据此判断：对 n=10 万 的数据做 O(n²) 双重循环是否可行？O(n log n) 呢？
3. 写出一句话结论：你会把热路径允许的复杂度上限定在哪个量级，为什么。

**验收标准**：给出数量级推导过程（非拍脑袋），并能把结论落到"禁止外部可控的 O(n²)"。

## 作业 3：均摊成本小实验（选做）

用 `new ArrayList<>()` 与 `new ArrayList<>(n)` 分别填充 1000 万元素，记录耗时/内存差异，解释为什么预分配容量更快，以及"2 倍扩容"在其中扮演的角色。

---

### 参考答案（要点）

- **作业 1**：瓶颈是把 O(m) 查找放进 O(n) 循环。改 `Set<Long> vip = new HashSet<>(queryVipIds())` 后 `contains` 均摊 O(1)，整体 O(n+m)。5000 万无法全放本地 → Redis Set `SISMEMBER` 或布隆过滤器（接受极小假阳性挡掉绝大多数非 VIP，命中的再回源确认）。
- **作业 2**：预算约 200ms×10⁸ = 2×10⁷ 次。n=10 万时 O(n²)=10¹⁰ 远超预算不可行；O(n log n)≈1.7×10⁶ 可行。热路径上限应定在 O(n log n)，且 n 需有上界保护（分页/限流）。
- **作业 3**：预分配避免多次 `grow`+数组拷贝；2 倍扩容使总拷贝量收敛为等比数列 < 2n，故 n 次 add 均摊 O(1)。
