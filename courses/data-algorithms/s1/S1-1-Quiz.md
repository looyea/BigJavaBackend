# 小测验 · 复杂度分析与大 O 思维

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分折算百分制，≥ 60 分过关。

### 1. 大 O 记号真正度量的是什么？（15分）

- A. 一段代码在某台机器上运行的绝对毫秒数
- B. 输入规模增长时资源消耗的增长趋势
- C. 代码的行数与圈复杂度
- D. 编译器生成的指令条数

> 答案：B
> 解析：大 O 忽略常数项与低阶项，刻画的是随 n 增大时的增长趋势，而非绝对耗时；同一 O(n) 在不同数据量下耗时差异巨大，但趋势相同。

### 2. 电商接口把 5 万个用户 ID 与黑名单匹配，原代码在 `for` 里对 `List<Long> blacklist` 调用 `contains`。该实现的时间复杂度是？（15分）

- A. O(n)
- B. O(n log n)
- C. O(n·m)，n 为用户数、m 为黑名单规模，是性能地雷
- D. O(1)

> 答案：C
> 解析：`List.contains` 本身是 O(m)，落在 O(n) 循环里 → O(n·m)。把黑名单换成 `HashSet`（或 Redis SISMEMBER）后单次查找降到 O(1)，整体降为 O(n)。

### 3. 【多选】下列关于均摊分析与预分配容量的说法，正确的有哪些？（20分）

- A. ArrayList 单次 add 触发扩容可能是 O(n)，但 n 次 add 均摊为 O(1)
- B. 已知数据规模时，`new ArrayList<>(n)` 可减少反复扩容拷贝
- C. HashMap 采用 2 倍扩容是总拷贝次数收敛到线性级的关键之一
- D. 只要用了哈希表，任何循环内的查找都自动变成 O(1)

> 答案：ABC
> 解析：A/B/C 都体现均摊与预分配思想。D 错——哈希表查找是均摊 O(1)，但严重哈希冲突（尤其恶意 hashCode）会退化到 O(n)，且遍历/排序等操作不因此变 O(1)。

### 4. 判断：在满足 SLA 的前提下，后端热路径上出现 O(n²) 且 n 完全由外部输入控制是可以接受的。（10分）

- A. 正确
- B. 错误

> 答案：B
> 解析：外部可控的 n 会被大流量放大成超时甚至被打崩，正是复杂度审计要消灭的目标；应通过算法降到 O(n log n)/O(n)，或用限流、分页约束 n 的上界。

### 5. 填空题：数据库对查询列建 B+ 树索引，把全表扫描的 O(n) 降到约 O(______)；用 Redis 内存哈希把命中降到接近 O(______)。（10分）

> 答案：log n / 对数 / 1 / 常数

### 6. 某金融对账要处理百万级明细，内存吃紧。请从"时间与空间互换"的角度，说明你会如何在"HashSet 去重加速"与"排序后双指针线性扫描"之间取舍。（30分）

> 参考答案：
> - HashSet 方案：空间 O(n) 换查找 O(1)，总时间约 O(n)，但百万级装内存可能触发 GC 或 OOM
> - 排序+双指针：先 O(n log n) 排序，再 O(n) 线性合并，额外空间可降到 O(1)
> - 判断依据是瓶颈：CPU 富余而内存紧张时优先排序双指针，反之用哈希
> - 数据超单机内存时进一步落盘：外部排序 / 分片归并 / 游标分批处理
> - 结论体现"复杂度与资源预算共同决定选型"，而非一味用空间换时间
