# 小测验 · 哈希表原理与冲突处理

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分，≥ 60 分过关。

### 1. 哈希表能把查找压到接近 O(1)，它付出的核心代价是？（15分）

- A. 必须排序
- B. 彻底放弃有序性，且依赖哈希函数质量
- C. 只能存整数
- D. 必须线程安全

> 答案：B
> 解析：哈希不保序，无法做范围/前后最近查询；一旦哈希冲突严重，O(1) 会退化，所以既牺牲有序又依赖散列均匀。

### 2. JDK HashMap 用 `&(n-1)` 而非 `% n` 定位桶，前提是？（15分）

- A. 容量必须是质数
- B. 容量必须是 2 的幂
- C. key 必须可比较
- D. 负载因子必须为 1

> 答案：B
> 解析：容量为 2 的幂时 `hash & (n-1)` 等价于 `hash % n` 但只需一条位运算；这也让扩容 rehash 只需看新增最高位是 0/1。

### 3. 【多选】关于哈希冲突与退化，正确的有哪些？（20分）

- A. 链地址法把冲突元素挂在桶上的链/树，开放寻址则探测下一个空位
- B. 元素数超过"容量 × 负载因子"会扩容为 2 倍并 rehash
- C. JDK8 中任意一条链长度达到 8 就立刻树化，与表容量无关
- D. 恶意构造大量哈希碰撞的 key 可使链退化到 O(n)，即 HashDoS

> 答案：ABD
> 解析：C 错——树化需同时满足"链≥8 且表容量≥64"，否则只扩容不树化。A/B/D 均为标准结论。

### 4. 判断：需要"按 score 区间查询排名"时，用 HashMap 存 score 是最合适的。（10分）

- A. 正确
- B. 错误

> 答案：B
> 解析：哈希不保序，无法做范围/排名查询；这种"有序 + 范围"需求要用平衡树/跳表（如 Redis ZSet、TreeMap）。

### 5. 填空题：JDK HashMap 的扰动函数是 `h ^ (h >>> 16)`，目的是把高 16 位混入低位以 ______；作键的对象应尽量 ______，否则入表后修改哈希字段会导致 ______。（10分）

> 答案：减少冲突 / 让高位参与定桶 / 不可变 / 保持不变 / 找不到元素 / 定位失效

### 6. 设计"接口防刷：判断某 IP 在 1 分钟内请求是否超过阈值"，说明你用哪些哈希结构、为什么，并指出哈希做不了什么、要补充什么。（30分）

> 参考答案：
> - 用 `HashMap<String, 计数/时间窗口>` 或 `ConcurrentHashMap` 以 IP 为 key O(1) 定位计数
> - 计数去重/存在性判断正是哈希强项（Set 判黑名单、Map 累加次数）
> - 高并发写用 ConcurrentHashMap 的分桶 CAS，避免全表锁
> - 哈希不保序：无法直接"清理过期窗口/按时间范围统计"，需配合滑动窗口队列或定时清空、或用 ZSet 按时间戳排序
> - 需内存上限与过期淘汰（否则不同 IP 无限增长 → OOM），可用带 LRU/TTL 的结构
