# 面试考点 · 排序算法全景与稳定性

> 排序是"看似简单、一问源码就露馅"的典型区。高频：Arrays.sort 底层、快排退化、TimSort 为什么、稳定性何时重要、外部排序。

## 考点 1：Arrays.sort 底层与双轨设计

**起手**：`Arrays.sort` 用的什么排序？为什么基本类型和对象类型不一样？

**追问链**：
1. int[] 用什么？→ 双轴快排 DualPivotQuicksort（原地快、不稳定）。
2. Object[] 用什么？→ TimSort（归并+插入，稳定，利用有序 Run）。
3. 为何不同？→ 对象排序稳定性是刚需（多关键字/保序），值类型不需稳定所以求快省。
4. TimSort 空间代价？→ 最坏 n/2 临时数组，堆内大对象数组排序会短时抬高峰值内存。

## 考点 2：快排的退化与工程防护

**起手**：快排最坏 O(n²) 怎么发生？怎么避免？

**追问链**：
1. 触发条件？→ 已排序/全相同 + 固定端点 pivot → 分区极不均、递归深 n。
2. 避免？→ 随机化/三数取中 pivot、三路划分（荷兰国旗处理重复）、小数组切插入、只递归较短侧限制栈深。
3. 三路划分解决了什么？→ 大量重复键把 =pivot 聚中间不再递归，避免退化。

## 考点 3：稳定性与归并 vs 快排

**起手**：什么时候必须用归并不用快排？

**期望**：
- 需要稳定（多关键字、相等键保原序）→ 归并/TimSort。
- 链表排序、外部排序、要最坏也 O(n log n) 保证且可接受 O(n) 空间 → 归并。
- 内存中可原地、平均最快、缓存友好 → 快排（通用默认）。
- 追问：堆排稳定吗、原地吗？→ 不稳定、原地 O(1)、最坏 O(n log n)，但缓存差少作主力。

## 考点 4：比较下界与非比较排序

**起手**：排序能突破 O(n log n) 吗？

**期望**：
- 比较排序决策树 n! 叶 → 下界 Ω(n log n)，不可破。
- 放弃比较：计数（值域小）、基数（按位）、桶（均匀分布）可达线性，但受数据形态限制。

## 考点 5：外部排序（架构级加分）

**起手**：数据大过内存怎么排？

**期望**：分块内排 → 落盘有序段 → 容量 k 的小顶堆做多路归并流式输出，O(N log k)；块内可并行；这是 Spark/MapReduce/DB 大结果集排序内核。

**追问**：Top-K 与全量排序区别？→ 只要前 K 用堆 O(n log K) 省内存可流式，不必全排（详见 s2-3）。
