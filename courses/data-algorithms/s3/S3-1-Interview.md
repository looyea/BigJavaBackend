# 面试考点 · 图的存储、遍历与经典算法

> 图论题面试重"建模 + 选对遍历/算法"，很少考手写 Floyd。常见套路：把业务关系翻译成图，再问"要最短/要连通/要顺序/要判环"。

## 考点 1：图的表示与遍历选择

**起手**：图怎么存？BFS 和 DFS 分别适合什么？

**追问链**：
1. 邻接矩阵 vs 邻接表？→ 稠密/判边用矩阵，稀疏用表；无向边存两次。
2. BFS 用队列、DFS 用栈/递归，各典型场景？→ BFS：最短跳数、分层、六度；DFS：连通、判环、拓扑、路径枚举。
3. 为什么图遍历必须 visited 而树不用？→ 图有环会无限循环，树无环单向。

## 考点 2：最短路径家族

**起手**：最短路用什么算法？

**追问链**：
1. 无权图？→ BFS。
2. 正权单源？→ Dijkstra + 优先队列，讲清"取最近未定点松弛"的贪心。
3. 有负权？→ Bellman-Ford（可判负环）；多源？→ Floyd（DP）。
4. Dijkstra 为什么不能处理负权？→ 它假设"已定最小点不会再变小"，负边会让更优路径后置。

## 考点 3：拓扑排序与环检测（工程高频）

**起手**：任务有前后依赖，怎么排出可执行顺序？怎么判有没有死循环依赖？

**期望**：
- Kahn：入度 0 入队 → 出队删边 → 后继入度归零再入队；`order.size()<n` 即有环。
- 或 DFS 三色标记（白灰黑），遇到灰点 = 成环。
- 应用：编译/构建顺序、Spring Bean 初始化、课程表、数据血缘。
- 追问：求"最少并行批次"？→ BFS 按层处理，层数即批次数。

## 考点 4：连通性与并查集的取舍

**起手**：判断两点是否连通、统计连通块，用哪种？

**期望**：
- 静态一次性 → BFS/DFS 染色。
- 边动态合并、多次查询 → 并查集（路径压缩 + 按秩，近 O(1)）。
- 追问：什么时候并查集不行？→ 需要具体路径/距离、或要"断开"边时，回到遍历。

## 考点 5：建模能力（拉开差距）

**起手**：把"社交六度人脉 / 网格最短出口 / 单词接龙"抽象成图。

**期望**：能说出"谁是顶点、谁是边、边是否带权、求最短路还是可达"，再选 BFS(无权)/Dijkstra(带权)/DFS(可达/路径)。建模正确即达优秀线。
