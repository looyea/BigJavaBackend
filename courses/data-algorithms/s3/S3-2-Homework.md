# 课后作业 · 排序算法全景与稳定性

> 2 题，一题源码行为辨析，一题外部排序设计，附验收标准与参考答案。

## 作业 1：Arrays.sort 行为辨析（50分）

**要求**：说明下面两段各自走什么算法、是否稳定、为何这样设计；并回答"多线程排上亿 int"用什么 API。

```java
int[] nums = {5, 1, 5, 2};
Arrays.sort(nums);                                              // (1)
Order[] orders = ...;                                           // 含相同 amount
Arrays.sort(orders, Comparator.comparing(o -> o.amount));       // (2)
```

**验收标准**：
- (1) 双轴快排、不稳定；(2) TimSort、稳定。
- 能说清"值类型不需稳定求快省、对象需稳定保多关键字序"。

**参考答案要点**：
- (1) `int[]` → DualPivotQuicksort，原地快、不稳定；值无"身份"，稳定性无意义。
- (2) `Object[]` → TimSort，稳定；"金额相同保持录入先后"正靠它。
- 多核加速大量原始类型：`Arrays.parallelSort(nums)`（ForkJoin 分块排 + 多路归并）。

## 作业 2：外部排序方案设计（50分）

**要求**：500GB 文本日志按时间戳排序，机器内存 8GB。设计流程，估算分块数与归并路数，说明如何用最小堆做 k 路归并、如何控制磁盘读写次数。

**验收标准**：
- 分块大小 ≈ 可用内存 × 安全系数，块数 ≈ 500GB / 块大小。
- k 路归并：堆存 k 个"各路当前头部"，弹最小后从该路补一个；写用顺序追加、读用较大缓冲。

**参考答案要点**：
- 若每块用 ~2GB 内存 → 约 250 块（有序段）；归并路数 k 受文件句柄与内存缓冲限制，可分层归并（每次合并 k 路，多趟）。
- 块内排：外部取数 → 内存 TimSort/快排 → 落盘；归并：小顶堆按时间戳选最小 → 流式写。
- 控 IO：增大每路读缓冲减少 seek、顺序写、用日志本身的时间局部性。
- 引申：这就是 Spark/MapReduce shuffle 排序与 DB 大结果集 order by 的思路。
