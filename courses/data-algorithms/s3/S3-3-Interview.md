# 面试考点 · 查找与二分

> 二分是"人人会写、人人都写错"的题。面试官看边界模板是否清晰、防溢出/防死循环意识、以及能不能识别"二分答案"。

## 考点 1：手写二分与边界

**起手**：手写一个二分，找 target 第一次出现的位置。

**追问链**：
1. `mid` 怎么写？→ `lo + ((hi-lo)>>1)` 防溢出。
2. 循环条件与收缩怎么配？→ 说清不变式：左闭右开 `lo<hi`+命中 `hi=mid` 收敛到 lowerBound；闭区间 `lo<=hi`+`±1` 是另一套，别混。
3. 找区间/最后一个？→ 再写 upperBound，`upper-lower` 即出现次数。
4. 常见 bug？→ 死循环（`lo=mid` 不前进）、漏 ±1、边界数组越界。

## 考点 2：旋转数组二分

**起手**：一个升序数组被旋转，怎么 O(log n) 找 target？

**期望**：
- mid 切两半，必有一半有序：用 `a[lo]<=a[mid]` 判左半有序，再看 target 是否落在有序半区间。
- 追问：有重复元素还能 O(log n) 吗？→ 最坏退化 O(n)（`[1,1,1,0,1]`），`a[lo]==a[mid]` 时 `lo++` 去歧义。

## 考点 3：什么数组"无序也能二分"

**起手**：是不是只有有序数组才能二分？

**期望**：
- 不是。只要存在**单调判定**即可：旋转数组靠半区单调、二分答案靠"答案越大越可行"。
- 本质是"能被折半丢弃一半"的单调性，不是表面有序。

## 考点 4：二分答案（区分度最高）

**起手**：什么是二分答案？举一个。

**期望**：
- 适用：求"最大/最小化某量"，且该量满足单调可行性（跨过阈值后不再反转）。
- 套路：定 lo/hi（值域/参数区间）→ 写 `check(mid)`（多为贪心/模拟/计数）→ 二分找临界。
- 工程例：满足 SLA 的最小线程池/批次大小、限流阈值最小值、Koko 吃香蕉、分割数组最大值——都是"对参数二分 + check 模拟"。

## 考点 5：二分的适用边界

**起手**：什么情况不该用二分？

**期望**：
- 无法随机定位（链表）→ 二分退化，考虑快慢指针或转结构。
- 无序且无单调判定 → 先排序（O(n log n)）或用哈希。
- 要"动态增删 + 有序查找" → 用平衡树（TreeMap 的 floor/ceiling 是树上的二分），不是静态数组二分。
