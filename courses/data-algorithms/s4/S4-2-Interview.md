# 面试考点 · 递归与分治

> 递归/分治是"元能力"。面试官爱问：怎么在分治/DP/回溯/贪心里选、递归的心态、什么情况拒绝递归、分治能否并行。

## 考点 1：范式选择（分治/DP/回溯/贪心）

**起手**：拿到一个问题怎么决定用哪种范式？

**期望**：
- 能切成独立子问题再合并 → 分治。
- 子问题重叠且求最优/计数 → DP。
- 要枚举所有解带约束 → 回溯。
- 每步局部最优且能证明 → 贪心。
- 追问：分治和 DP 一眼怎么分？→ 画递归树看有无重复子问题：无=分治，有=DP。

## 考点 2：递归的正确心态与终止

**起手**：写递归你脑子里在想什么？

**期望**：
- "信任递归"：假设子调用已返回正确结果，只负责组合，别逐层展开。
- 保证 base case 存在且每步规模严格递减，否则不终止/爆栈。
- 追问：什么情况拒绝递归？→ 深度可能 O(n) 的链式结构（深链表/退化树/大图 DFS），生产改迭代 + 显式栈。

## 考点 3：分治经典与复杂度

**起手**：举几个分治的例子，复杂度怎么估？

**期望**：
- 归并排序、快排、最近点对、大整数乘法、`parallelSort`。
- 主定理 `T(n)=aT(n/b)+O(n^d)` 比较 a 与 b^d：归并 a=2,b=2,d=1 → O(n log n)。

## 考点 4：分治与并行（架构加分）

**起手**：分治为什么适合并行？瓶颈在哪？

**期望**：
- 子问题独立 → 可分给多线程/多机（parallelSort/ForkJoin、MapReduce map 分片）。
- 瓶颈常在合并（merge/reduce）：串行或有全局锁会限制加速比（Amdahl）。
- 缓解：让合并也可并行（多路归并/树形合并）、减少合并、调分片粒度。
