# 面试考点 · 堆、优先队列与堆排序

> 堆是"手写 sift 常考 + Top-K 场景题高频"。面试官爱从"PriorityQueue 原理"追到"10 亿取 Top-K"再追到"为什么建堆是 O(n)"。

## 考点 1：堆的本质与数组实现

**起手**：PriorityQueue 底层是什么？

**追问链**：
1. 堆保证什么？→ 只保证堆顶是极值（小顶堆堆顶最小），兄弟无序。
2. 为什么用数组不用指针？→ 完全二叉树可用下标 `2i+1/2i+2/(i-1)/2` 直接映射父子，省指针、缓存友好。
3. 插入/删除怎么做？→ 末尾放入上浮 / 末尾补堆顶下沉，各 O(log n)。
4. `peek` 和 `poll` 区别？→ peek 看堆顶 O(1) 不删，poll 弹出并修复 O(log n)。

## 考点 2：为什么建堆是 O(n)（经典深挖）

**起手**：n 个元素建堆，复杂度是多少？

**期望**：
- 直觉：逐个插入 O(n log n)；正解：自底向上 heapify 是 **O(n)**。
- 原因：底层节点最多但下沉距离最短，\(\sum \lceil n/2^{h+1}\rceil \cdot h = O(n)\)。
- 能写出从 `n/2-1` 倒序 `siftDown` 即可达及格。

## 考点 3：Top-K 全家桶（最高频）

**起手**：10 亿个整数取最大的 100 个，内存放不下，怎么做？

**追问链**：
1. 用什么结构？→ 容量 100 的**小顶堆**，比堆顶大才替换。
2. 为什么是小顶堆不是大顶堆？→ 堆顶是"当前 Top100 里最小的"，新数比它大才有资格进，淘汰最小的。
3. 复杂度？→ O(n log 100)≈O(n)，空间 O(100)，可流式。
4. 数据超单机？→ 分片各取局部 Top100 → 汇总再取 Top100。
5. "前 K 个高频元素"？→ HashMap 计数 + 堆按频次取 Top-K。

## 考点 4：堆排序与"稳定/原地"取舍

**起手**：堆排序什么时候用得上？

**期望**：
- 建大顶堆 → 反复把堆顶换到末尾、缩小堆、下沉；O(n log n)，原地 O(1)，最坏也有保证。
- 缺点：不稳定、缓存跳跃访问差，故很少当主力排序。
- 追问：为什么实际用快排/归并而非堆排？→ 快排缓存友好、归并稳定，堆排常数大（见 s3-2）。

## 考点 5：堆的综合应用

**起手**：堆还能解决什么？

**期望**：
- 合并 K 个有序链表：k 个头入堆，弹最小补下一个，O(N log k)。
- 数据流中位数：大顶堆 + 小顶堆双堆平衡。
- Dijkstra 松弛、任务按优先级调度、延迟队列（DelayQueue）——都建立在优先队列上。
- **对比**：堆 vs TreeSet（都可取极值）→ 堆允许重复、O(1) 拿堆顶但不支持按值定位删除；TreeSet 有序可定位但常数大。
