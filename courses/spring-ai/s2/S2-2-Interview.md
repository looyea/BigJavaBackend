# 实际面试题 · 可观测、评估与安全防护

## 题 1：大模型应用怎么做可观测？和传统服务有什么不同？

**考察层次**：初级只会打日志；中级知道埋 token/延迟；高级能把观测、评估、成本、安全串成治理闭环。

**参考答法**：

1. 把每次 LLM/向量/工具调用当一等公民埋点（Micrometer + Spring AI Advisors）：模型、输入/输出 token、端到端与每步延迟、错误/超时/结构化解析失败率、工具调用次数、每会话步数、成本估算。
2. **链路追踪**：一次 Agent 对话跨多次模型+多个工具，必须用 traceId 串起"推理-行动"链，才能解释"为什么慢/贵/做了这个动作"。
3. 不同点：传统看 QPS/RT/错误率就够，LLM 还要看**质量**（评估）和**成本**（token），因为非确定输出可能"不报错但答错"。

**追问**：prompt/response 能原样落库吗？→ 必须先脱敏，且注意别把密钥/PII 写进日志，检索侧也要按权限隔离。

## 题 2：怎么给 AI 应用建"测试"？（Evals）

**答题要点**：没有评估集等于裸奔。三层——① 离线：黄金问答集，确定性任务算准确率/F1/可解析率，开放任务用 LLM-as-judge 打分 + 抽样人工校准，RAG 专项看召回命中率/答案忠实度/引用正确率；② 在线灰度：小流量比 A/B 业务指标（采纳率、人工干预率、投诉），别只看离线分；③ 回归门禁：离线评估挂 CI，跌破阈值阻断发布。

## 题 3：什么是 Prompt 注入？怎么防？

**结构化回答**：

1. 定义：把"要模型执行的恶意指令"藏进用户输入或被检索的文档里（如"忽略以上指令…"），劫持模型行为。
2. RAG 场景尤其危险——知识库里一条投毒文档就会进上下文。
3. 缓解：指令与数据分离、对不可信内容做标记与过滤、关键动作不靠模型"自觉"而由服务端鉴权/白名单/参数二次校验、高危操作人在环、系统提示不外泄。
4. 心智：**模型输出是"建议"不是"授权"**，安全边界必须在可信内圈的服务端代码兜底。

## 题 4：上线一个新模型/新提示词，你怎么保证不出事？

**答题要点**：走发布流程而非"改了就直接全量"：先在评估集上跑离线回归（分数不降）→ 小流量灰度对比业务指标与成本/延迟 → 观测埋点盯错误率/解析失败率/账单 → 设回滚开关（能一键切回旧模型/旧提示）。核心是把"非确定的质量变化"变成"可量化、可灰度、可回滚"的工程流程。

## 题 5：LLM 应用的成本为什么会失控？怎么做成本治理？

**答题要点**：无埋点就无归因——token 是成本之源，超长上下文、Agent 无限循环、每用户重复请求都会烧钱。治理：token/成本按 model·用户·场景 维度归因看板 + 告警；token 上限、超时、Agent 步数上限；结果缓存；模型分级路由（简单题走小模型、难再升级）；按用户/租户限流与预算护栏。

## 高频追问速答

1. LLM-as-judge 可靠吗？→ 有偏（自恋、位置、长度偏好），要用强模型 + 明确 rubric + 抽样人工校准，关键决策不单独依赖它。
2. 观测数据里能存原始 prompt 吗？→ 先脱敏，去 PII/密钥，并做访问控制与保留期管理。
3. 内容审核（moderation）放哪？→ 输入侧与输出侧都要，双闸门。
4. 灰度看哪些业务指标？→ 采纳率、人工干预/转人工率、投诉率、复问率，比离线分更真实。
5. 什么是一定要人在环的？→ 不可逆或高风险动作：转账、下单、删库、对外发布、医疗/电力操作。
