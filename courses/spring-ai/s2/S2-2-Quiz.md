# 小测验 · 可观测、评估与安全防护

> 共 5 题，合计 100 分，≥ 60 分过关。

### 1. 把 LLM 应用 Demo 推向生产，为什么不能只靠传统单元测试？（20分）

- A. 单测太慢，不适合 CI
- B. LLM 输出非确定、质量是"好坏"连续量、工具调用有真实副作用，需评估+观测+防护三件套
- C. 生产环境不允许跑单测
- D. 模型没有可测接口

> 答案：B
> 解析：传统断言"输入 A→输出 B"失效，必须用评估集治理质量、指标观测运行态、安全防护边界。

### 2.（多选）为一次 Agent 对话做可观测埋点，应当记录哪些维度？（25分）

- A. 输入/输出 token 数与成本估算
- B. 端到端延迟及每步耗时，用 traceId 串起整条推理-行动链
- C. 结构化输出解析失败率、工具调用次数、每会话步数
- D. 模型权重文件本身

> 答案：ABC
> 解析：ABC 是成本/体验/稳定性/Agent 兜圈的观测要点；D 无关，权重不进埋点。

### 3. 关于评估（Evals），下列做法**不正确**的是？（20分）

- A. 建带参考答案的黄金问题集，改提示/换模型后跑回归打分
- B. 开放任务可用 LLM-as-judge 按 rubric 打分并抽样人工校准
- C. 把离线评估挂进 CI，分数跌破阈值阻断发布
- D. 只要离线分够高就能直接全量上线，无需灰度

> 答案：D
> 解析：D 错，离线分高不代表线上好，还需小流量灰度看业务指标（采纳率/人工干预率/投诉）。

### 4. 填空题：防御 Prompt 注入与越权工具调用的核心原则是"永远不要信任模型的输出"——真正的鉴权、参数二次校验、____、限额必须由____侧代码兜底。（15分）

> 答案：幂等 / 服务端
> 解析：模型处于"不可信外圈"只做决策建议，安全边界（鉴权/幂等/限额）放在可信内圈的服务端。

### 5. 简答题：列出 LLM 应用相比传统服务多出来的主要攻击面，并各给一条缓解措施。（20分）

> 参考答案：
> - Prompt 注入：指令与数据分离、对检索/用户内容做不可信标记与过滤
> - 越权工具调用：服务端鉴权 + 参数校验 + 工具白名单 + 高危人在环
> - 数据泄露：出站前 PII 脱敏、私有化模型、检索按权限 ACL 过滤
> - 成本/DoS：token 上限、超时、Agent 步数上限、按用户限流
> - 幻觉/有害输出：强制引用来源、内容审核（moderation）、高风险转人工
