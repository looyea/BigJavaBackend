# 小测验 · Tool/Function Calling 与 Agent 编排

> 共 5 题，合计 100 分，≥ 60 分过关。

### 1. 关于 Function/Tool Calling，下列说法最准确的是？（20分）

- A. 大模型自己执行了工具
- B. 模型只返回"要调用哪个工具+参数"的结构化意图，真正执行发生在你的服务端代码
- C. 工具在浏览器执行
- D. 模型直接把 SQL 跑在数据库

> 答案：B
> 解析：模型产出调用意图，框架在服务端执行并回喂结果——执行权、鉴权、副作用都在你手里。

### 2. ReAct 模式的核心是？（20分）

- A. 一次性回答
- B. 推理(Reason)→行动(Act)→观察(Observed) 循环，让模型多步拆解任务
- C. 只做检索
- D. 只做向量化的模式

> 答案：B
> 解析：Agent 通过 ReAct 循环多轮调用工具直至完成或达终止条件。

### 3.（多选）生产环境编排工具/Agent 必须做的治理包括？（25分）

- A. 最大步数/循环上限，防自循环成本失控
- B. 总超时与每步超时
- C. 写操作幂等 + 高危操作人工确认
- D. 完全信任模型给的参数直接执行

> 答案：ABC
> 解析：D 危险，模型参数可被诱导，服务端必须再校验/鉴权。

### 4. 模型的 tool call 结果通常如何参与最终回答？（15分）

- A. 丢弃
- B. 作为 tool 消息回喂给模型，模型据此生成最终答案或继续调用下一个工具
- C. 直接返回给用户不再处理
- D. 写死进系统提示

> 答案：B
> 解析：执行结果回喂形成闭环，是多轮/Agent 的基础。

### 5. 判断题：工具的 description 与参数命名质量，会直接影响模型选对工具、填对参数的概率。（20分）

- A. 正确
- B. 错误

> 答案：A
> 解析：描述本质是"给模型看的 API 文档"，模糊会导致误选/错填。
