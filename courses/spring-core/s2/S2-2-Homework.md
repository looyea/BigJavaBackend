# 作业题 · 事务传播与失效场景

## 作业 1：回滚规则四象限（必做）

一个事务方法分别构造四种情况，记录每条是否回滚：① 抛 RuntimeException；② 抛 checked 异常且无 rollbackFor；③ 抛 checked 异常且 `rollbackFor=Exception.class`；④ 抛异常但被内部 try/catch 吞掉。

**产出**：回滚真值表，并写出团队规范："业务事务方法默认 `rollbackFor = Exception.class` 且禁止吞异常"。

## 作业 2：三种传播行为对比实验（必做，本节核心）

外层事务方法分别调用传播为 REQUIRED / REQUIRES_NEW / NESTED 的内层方法，构造"内层抛异常被外层 catch、或外层最终回滚"两种剧本，观察内层数据是否落库：

- REQUIRED：与外层同生共死
- REQUIRES_NEW：内层已提交不受外层回滚影响；外层回滚不受内层影响
- NESTED：内层失败回退到保存点，外层可选择继续

**验收标准**：用一张表总结三者"外层回滚时内层结果""内层回滚时外层结果"。

## 作业 3：审计日志专用事务（必做）

给下单主流程加"操作流水"记录，要求主业务无论成功回滚，流水都要留存：

- 流水方法用 `REQUIRES_NEW`
- 验证：主业务最终回滚，流水表仍有记录
- 讨论：REQUIRES_NEW 会占用第二个数据库连接，连接池与死锁风险如何评估

## 作业 4：提交后发消息（必做）

下单事务里需要发 MQ：

1. 先"事务内直接发"，制造回滚，观察发出脏消息
2. 改用 `@TransactionalEventListener(phase=AFTER_COMMIT)` 或 `TransactionSynchronization.afterCommit`，回滚时不再发出
3. 进阶：提交后发送若失败怎么办？引出本地消息表/事务消息（简述思路）

## 作业 5：长事务治理（选做，架构师向）

找出一个"事务方法里同步调用 RPC + 循环写库"的长事务，做改造：

- 把非事务必要操作移出事务边界、缩小事务粒度
- 度量改造前后连接占用时间、连接池峰值占用、死锁概率
- 为金融扣款场景设计"事务内只做必须的 DB 变更、外部调用异步化"的模板
