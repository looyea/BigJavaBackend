# 服务治理：负载均衡、集群容错与流量管控 · 面试题

## 题 1：Dubbo 常用的负载均衡策略有哪些？各适合什么场景？

- random（按权重随机，通用）、roundrobin（轮询，节点均匀时稳）、leastactive（最小活跃，抗节点性能不均）、一致性哈希（同参数落同节点，利本地缓存）。
- 生产读接口偏爱 leastactive，缓存/会话亲和场景用一致性哈希。
- 加分：指出加权 random 与 leastactive 在"机器快慢不一"时后者能自动降权慢节点。

## 题 2：failover 和 failfast 有什么区别？下单该用哪个？

- failover 失败自动重试其他节点（可配 retries），适合幂等读；failfast 只调一次失败即抛，适合非幂等写。
- 下单/扣款这类非幂等写必须 failfast（或 retries=0），否则超时重试会把一次业务变多次造成重复。
- 加分：补充"要做重试先做幂等键"，把 RPC 层重试和业务幂等解耦。

## 题 3：为什么超时不能各层设一样大？重试和超时怎么相互影响？

- 超时预算应入口大、逐层递减，保证上层先于下层止损，避免下游超时倒灌压垮上游。
- 单请求对下游的真实占用/QPS 放大约为 `timeout ×(retries+1)`，重试越多、超时越长，下游压力成倍上升，易雪崩。
- 加分：给出具体链路数值例子并画出时间轴。

## 题 4：灰度发布在 RPC 层怎么落地？

- 通过 version/group/标签路由给新实例打标，消费端按标签只把特定流量切到灰度实例，出问题秒级撤销标签回切。
- 常与网关侧的统一入口打标配合，实现端到端的染色透传。
- 加分：强调"不打标直接放全量"的风险与回切速度是灰度价值所在。

## 题 5：服务下线（优雅停机）的正确姿势？为什么？

- 先从注册中心反注册 → 等待消费端收到推送并刷新本地列表 → 处理完在途请求 → 再关进程。
- 若先停实例再摘注册，正在路由的调用会打到已停机器出现瞬时 5xx。
- 加分：提到消费端刷新存在时间窗口，需要 sleep 一小段或用显式下线通知。

## 题 6：集群容错策略选错会引发什么生产事故？

- 非幂等写误用 failover+retries → 重复下单/重复扣款；弱依赖误用 failfast 且未兜底 → 主流程被拖垮。
- forbidden/failsafe 用错场景会让"该报错的静默、该拒绝的放过"，问题难定位。
- 加分：结合"按接口幂等性与依赖强弱"给一张 cluster 策略选型对照表。
