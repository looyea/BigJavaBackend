# 服务治理：负载均衡、集群容错与流量管控 · 作业

### 作业 1：为写/读接口分别选容错与负载策略

- 目标：验证"非幂等写关重试、读用最小活跃"在压测下的差异。
- 任务：给下单接口配 `failfast + retries=0`、查库存接口配 `leastactive`；用工具把某个库存节点人为拖慢，观察 leastactive 是否自动少分流量给它；再把下单误配成 `failover + retries=3`，构造一次超时，统计下游实际收到的下单次数，证明重复下单。
- 验收标准：能给出"慢节点活跃数高→流量下降"的观测；能复现 failover 重试导致同一下单请求在下游出现多次；改回 failfast 后重复消失。
- 参考解法要点：Dubbo `telnet`/admin 看 invoke 计数；解释 timeout×(retries+1) 的放大来源。

### 作业 2：搭一条"入口→下单→库存"的递减超时预算

- 目标：让上层始终先于下层超时，避免超时倒灌。
- 任务：设网关 5s、下单 3s、库存 1.5s，用延时注入让库存耗时 4s，观察哪层先超时、错误如何向上传播；然后把下单改成 1s（小于库存 1.5s），再观察是否出现"下游还没结束上游已放弃、但下游仍在空跑"的资源浪费。
- 验收标准：能画出各层超时时间轴；能说明预算递减时最先止损的层，以及设反后的错乱表现。
- 参考解法要点：结合链路追踪日志时间戳核对；强调超时预算要为 `retries` 留余量。

### 作业 3：灰度发布 + 优雅停机的无损演练

- 目标：证明"打标路由 + 先摘流再下线"能实现发布零 5xx。
- 任务：给一批实例打 `version=2.0.0/group=gray`，配置只有带灰度标的请求才路由过去；对某实例做下线，一种做法直接 kill、另一种先反注册并等待消费端刷新再 kill，分别用持续压测统计 5xx 数量对比。
- 验收标准：直接 kill 能观测到瞬时 5xx，先摘流后 5xx≈0；灰度流量严格按标签隔离、可秒级回切。
- 参考解法要点：说明注册中心推送与消费端本地缓存刷新的时间窗口；灰度回切即撤销标签。
