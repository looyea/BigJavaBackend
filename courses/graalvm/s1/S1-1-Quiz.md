# 小测验 · 原生镜像原理与限制

> 共 5 题，合计 100 分，≥ 60 分过关。

### 1. 原生镜像的一切限制（反射失灵、资源找不到等）总根源是？（20分）

- A. SubstrateVM 太精简
- B. 封闭世界假设：构建期可达性分析必须确定所有目标，运行期不能出现分析看不见的"新目标"
- C. Graal 编译器不够聪明
- D. Java 语法问题

> 答案：B
> 解析：AOT 在构建期静态推导可达代码并丢弃不可达部分，动态特性打破这一假设，才需补元数据。

### 2. AOT（原生镜像）与 JIT（传统 JVM）的本质差别是？（20分）

- A. 完全一样，只是名字不同
- B. AOT 把编译从运行期搬到构建期，无预热、启动快内存低，但缺运行期 profile 峰值吞吐常略低
- C. AOT 峰值一定高于 JIT
- D. JIT 不需要编译器

> 答案：B
> 解析：JIT 用运行期真实 profile 深度优化热点并可去优化；AOT 用构建期静态分析换来启动/内存收益。

### 3.（多选）下列哪些动态特性在原生镜像里需要 reachability metadata 显式登记？（25分）

- A. 反射 `Class.forName` / `getDeclaredMethod`
- B. JDK 动态代理
- C. `getResourceAsStream` 加载类路径资源
- D. 普通 `new` 一个编译期已可达的类

> 答案：ABC
> 解析：D 静态分析能看到、本就可达，无需登记；ABC 都在构建期"看不见"，要靠 reflect/proxy/resource-config 补。

### 4. 填空题：告诉原生镜像"哪些类/方法/资源必须保留"的配置统称 ____ metadata（如 `reflect-config.json`）；Spring 通过构建期的 ____ 引擎自动生成它，也可实现 `RuntimeHints` 手动补充。（15分）

> 答案：reachability（可达性） / Spring AOT
> 解析：Boot 侧的 process-aot/RuntimeHints 本质就是在给封闭世界补可达性元数据（打包流程见 spring-boot s3-2）。

### 5. 简答题：给出适合与不适合上原生镜像的场景各两类，并说明理由。（20分）

> 参考答案：
> - 适合：Serverless/函数/CLI/需秒级弹性扩容（冷启动毫秒级、内存低）；按量计费/密度敏感容器（省成本）
> - 不适合：长驻高吞吐、JIT 预热后久跑的核心服务（丢峰值性能收益不明显）；重度反射/动态代理且无原生支持的库（metadata 维护成本高于收益）
> - 理由围绕"启动/内存收益 vs 吞吐/构建/维护代价"权衡
