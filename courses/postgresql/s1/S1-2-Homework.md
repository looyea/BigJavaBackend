# 课后作业：扩展生态与选型（PostGIS/pgvector）

## 作业 1：PostGIS 电子围栏系统（35分）

场景：物流调度平台，需要判断配送员当前位置是否在指定配送区域内（区域由不规则多边形定义）。

要求：
1. 设计数据模型：区域表（id, name, boundary GEOMETRY(POLYGON, 4326)）、配送员表（id, name, location GEOGRAPHY(POINT, 4326)）。
2. 写出"查询某配送员在哪个区域内"的 SQL，要求使用空间索引且响应时间 < 5ms（1000 个区域、5000 个配送员）。
3. 设计"区域重叠检测"接口：新建区域时校验是否与已有区域重叠 > 30%，给出 ST_Intersection + ST_Area 的 SQL。
4. 扩展思考：如果区域随时间变化（如高峰临时扩大），如何设计版本化存储与查询？

## 作业 2：pgvector 商品推荐（35分）

场景：电商平台，已用预训练模型把商品标题/图片编码为 256 维向量，需要实现"看了又看"推荐。

要求：
1. 建表并插入模拟数据（至少 10 万条向量），创建 HNSW 索引。
2. 写出"输入一个商品 ID，返回 Top-20 最相似商品"的 SQL。
3. 对比实验：关闭索引（暴力精确检索）vs 开启 HNSW（ef_search=40 vs 200），记录响应时间和 Recall@20。
4. 设计增量更新方案：商品下架时向量如何处理？Embedding 模型升级后如何全量重建而不影响在线查询？

## 作业 3：选型分析报告（30分）

场景：你的团队正在做一个新型 SaaS 平台，数据特征如下：70% 是结构化业务表（CRUD 为主）、20% 是用户行为 JSON 事件、10% 需要地理围栏 + 向量搜索。

要求：
1. 给出数据库选型建议（纯 PG / 纯 MySQL / PG+专用引擎混合），说明理由。
2. 列出三种方案的成本矩阵：运维复杂度、团队学习成本、扩展性、生态工具链。
3. 如果选 PG，给出需要的扩展清单与版本号；如果选 MySQL 为主库，地理/向量需求怎么解决？
4. 写一页决策 ADR（Architecture Decision Record），格式：背景 → 决策 → 后果。
