# CPU/alloc/lock 与 Wall 模式采样 · 作业

### 作业 1：cpu 与 wall 两张图对比同一接口

- 目标：直观体会"算得多"和"等得久"是两回事。
- 任务：写一个接口，内部既有 50ms 的纯计算又有 300ms 的 sleep/IO 模拟等待。分别用 `-e cpu` 和 `-e wall` 各采 30s 出火焰图，对比同一接口在两张图里的"宽度构成"：cpu 图里计算帧宽、等待帧几乎不见；wall 图里等待帧变宽。
- 验收标准：能用两张图解释"为什么 CPU 不高但接口慢时该看 wall"，并指出各自最宽帧分别指向什么。
- 参考解法要点：`asprof -e cpu/-e wall -d 30 -f`；解释采样触发条件差异。

### 作业 2：用 alloc 定位一个"分配型"GC 压力

- 目标：练"分配量≠耗时"的正确解读。
- 任务：造一个循环里频繁 new 大对象/字符串拼接的方法，用 `-e alloc` 采样出火焰图，找出分配最猛的栈；说明它为什么会在 cpu 图里不明显但会推高 Young GC。给出优化（复用缓冲、预分配容量）。
- 验收标准：能从 alloc 图定位到分配热点；能解释宽帧代表"分配量大"而非"占 CPU 久"，并给出降低分配的措施。
- 参考解法要点：alloc 看字节分配量；TLAB 溢出/大对象直接进老年代的后果。

### 作业 3：用 lock 事件找锁竞争瓶颈

- 目标：定位一段高竞争同步代码。
- 任务：写一个多线程抢同一把 `synchronized` 锁的计数方法，压测时用 `-e lock` 采样，找出等锁最久的栈；再用 wall 图（-t 分线程）验证阻塞线程都卡在同一临界区。对比改成细粒度锁/无锁结构（LongAdder）后的图。
- 验收标准：lock 图能指出竞争点；能用 wall 佐证；改造后等锁宽度显著下降。
- 参考解法要点：lock 采的是"等锁时间"；注意小样本噪声，需拉长窗口。
