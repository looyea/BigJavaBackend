# 安全点采样偏差与线上低开销实践 · 作业

### 作业 1：复现并对比 --safe 与 --cstack dwarf 的偏差

- 目标：亲眼看到同一负载下两种栈回溯方式的火焰图差异。
- 任务：写一个含长循环（回边多）+ 一段刚被 JIT 编译的热方法的服务，分别用 `--safe` 和 `--cstack dwarf` 各采 30s。对比两图中"长循环帧/编译线程帧"的宽度变化，判断哪种更接近真实。
- 验收标准：能指出 `--safe` 下回边密集帧被"过度采样"、dwarf 图更均衡；能说明为什么会这样。
- 参考解法要点：安全点分布不均 → 采样扎堆；dwarf 靠帧信息 unwind 不依赖安全点。

### 作业 2：把采样做成"可常驻"的低开销方案

- 目标：设计一套不会拖慢线上的常态诊断参数。
- 任务：为一个接口服务配置采样：设置合理 `-i` 间隔、用 `-d` 短窗口或 `--loop` 自动停止、输出 `-o jfr`；连续观察一天，记录采样对 P99 延迟的影响（应基本无感）。再对比"极小间隔+每秒导出"的反例，展示其落盘开销与文件膨胀。
- 验收标准：给出"间隔/窗口/输出格式"三要素的可复用参数；能证明反例方案明显抬高开销。
- 参考解法要点：async-profiler 开销极低但高频导出会叠加；容器缺 perf 用 itimer。

### 作业 3：读图噪声过滤流程

- 目标：形成"先剔噪声再下结论"的固定动作。
- 任务：拿一张真实的 CPU 火焰图，动手标注并剔除 C1/C2 编译线程帧、内核态帧，找出"虚热"的回边帧；再结合一张 wall 图确认业务真正热点。输出一份"过滤前后结论对比"。
- 验收标准：过滤前误把编译/回边帧当热点、过滤后指向正确的业务方法；能解释每步剔除理由。
- 参考解法要点：多事件（cpu+wall）交叉印证；宽帧不等于真热点，先看是否偏差产物。
