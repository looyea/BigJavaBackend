# 倒排索引与分词器链路 · 作业

## 作业 1：为一个中文商品索引设计 mapping 与分词

- 目标：产出一份可直接 PUT 的索引定义，覆盖全文检索、精确匹配、聚合三类需求。
- 任务：为 `products` 索引设计字段——`title`（text，ik_max_word 索引 / ik_smart 搜索 + raw keyword 子字段）、`brand`（keyword）、`price`（float）、`created_at`（date）；写一条 `match(title)` 查询和一条按 `brand` 聚合的查询验证类型选择正确。
- 验收标准：`match` 能命中分词后的相关商品；`term(title,"完整串")` 演示查不到以印证 text 语义；按 `brand` terms 聚合与 `price` 排序均正常工作。
- 参考解法要点：multi-field 一字段多用途；类型选错只能 reindex，设计期就要区分检索/聚合用途。

## 作业 2：观察并解释一次"搜不到"故障

- 目标：定位 analysis 不对称导致的召回为 0。
- 任务：构造一个索引期用 `standard`、搜索期误用 `ik_smart` 的中文索引，写入若干商品后用中文关键词查询复现"明明有数据却搜不到"；再用 `_analyze` API 分别对索引与搜索 analyzer 分词，对比产出的 term 差异，最后改为两端一致修复。
- 验收标准：能贴出 `_analyze` 两端 token 不一致的证据；修复后同一查询命中；用一段话解释根因。
- 参考解法要点：`_analyze` 是排查分词问题的第一工具；显式非对称（max_word/smart）是设计，误配（standard vs ik）是事故，要能区分。

## 作业 3：给搜索排序加业务权重

- 目标：在 BM25 基础上做相关性微调。
- 任务：同一 `match` 命中集内，用 `function_score` 让"近 30 天上新""高销量""品牌官方店"的商品排得更靠前，并保留原始 BM25 分数参与综合。
- 验收标准：结果按加权分排序且可解释；时间衰减或权重因子有上限不淹没相关性；给出调前/调后对比。
- 参考解法要点：boost 是乘法/加法组合的加权，别把它当过滤条件；相关性(相关)与业务权重(重要)要分开表达。
