# 网关高可用、跨域与灰度发布落地

> 本节难度：★★★★☆
> 本节重要性：★★★★☆
> 学习产出：能把 Spring Cloud Gateway（SCG）从"一条转发规则"运维成"高可用、跨域统一、可灰度可回滚"的流量入口。SCG **无状态、可多实例横向扩展**，前面挂 LB（SLB/Nginx/DNS），但要做**优雅上下线**：实例下线时先从注册中心摘除、LB 健康检查把它移出，再等在途请求处理完才真正关闭——直接 kill 会让正在转发的长连接/在途请求返回 502。SCG 基于 **WebFlux/Netty 响应式**，过滤器里**绝不能做阻塞 IO**（同步 JDBC/`Thread.sleep`/阻塞 HTTP 会占死事件循环线程、拖垮整个网关吞吐）。**CORS 统一处理**放在网关的 `globalcors`，浏览器跨域预检 OPTIONS 由网关应答并下发 `Access-Control-*` 头；关键陷阱是**网关发了、下游服务又发一遍**，浏览器看到多个 `Allow-Origin` 会直接判定非法——CORS 只允许在一处（网关）统一下发。**灰度发布/流量切分**靠 **路由谓词 + 负载均衡权重**：把新版本实例打上 metadata（标签/权重），用 `Weight` 谓词按比例把一部分流量导进灰度池（金丝雀逐步放量、随时回滚），用 `Header`/`Cookie`/`Query` 或自定义谓词按**用户维度**（内部账号、地区、灰度标）定向到新版本，实现"按权重"与"按标签"两种切流叠加。路由 = predicates（命中条件）+ filters（重写/限流/鉴权）+ uri（`lb://service` 走注册中心）。灰度常与 Nacos（动态路由与实例元数据）、Sentinel（网关流控）联动。识破"网关过滤器里做阻塞调用压垮响应式线程""CORS 双发导致多值头被浏览器拒""下线直接 kill 制造 502""灰度只靠 DNS 一刀切、无法按用户维度定向"等坑——电商大促按用户标签灰度、金融按权重金丝度发布、电力多版本并行验证都依赖这套。

## 一、多实例与优雅上下线

```text
图目的：无状态网关扩容易, 下线难——顺序错了就 502
上线: 实例注册到 Nacos → LB/客户端拿到实例列表 → 开始接流
下线(优雅): ①先从注册中心摘除/LB 健康检查判不健康(停止新流量)
            ②等待在途请求处理完(warm-up/shutdown grace) ③再真正关闭进程
反例: 直接 kill -9 → 正在转发的连接被切断, 客户端收到 502/超时
WebFlux/Netty: 事件循环线程不能被阻塞, 过滤器里禁用同步 JDBC/阻塞 HTTP
```

## 二、CORS 与灰度路由的统一落地

```yaml
# 目的：网关侧统一 CORS + 基于权重的灰度路由, 让流量切分可控可回滚
spring:
  cloud:
    gateway:
      globalcors:                       # 说明：CORS 只在网关一处统一下发, 避免与下游重复
        cors-configurations:
          '[/**]':
            allowedOriginPatterns: "*"  # 反例：网关与下游各发一遍 ❌ 浏览器见多个 Allow-Origin 直接拒绝 ❌
      routes:                            # 说明：路由=predicates(命中条件)+filters+uri(目标服务)
        - id: order-v2
          uri: lb://order-service        # 结果：走注册中心负载均衡, 实例带 metadata weight 即按权重分流
          predicates:
            - Weight=order-group, 10     # 说明：10% 流量进 v2 灰度池, 其余走 v1, 改数字即可金丝度放量
            - Header=X-Gray, true        # 结果：命中灰度标签的请求(按 Header/Cookie/用户)定向到新版本
```

## 三、按权重 vs 按标签：两种切流叠加

```text
图目的：灰度不是单一开关, 常见"标签定向 + 权重放量"组合
按标签(定向): Header/Cookie/Query/用户属性 命中 → 精确进新版本(内部同学先试、指定地区先灰)
按权重(放量): Weight 谓词把百分比流量导入灰度池 → 观察指标无异常再逐步提高比例
回滚: 权重调 0 / 摘掉 v2 实例 metadata → 流量秒级全部回到 v1, 无需改代码
```

## 四、坑与底线

- **过滤器非阻塞**：任何鉴权/取数走响应式客户端，阻塞调用会占死 Netty 事件循环、雪崩式降吞吐。
- **CORS 单一出口**：只在网关下发跨域头，下游服务不要再发，杜绝多值头被浏览器拒绝。
- **下线先摘流量再关进程**：配合注册中心摘除 + grace，别用 kill 制造 502。
