# 网关高可用、跨域与灰度发布落地 · 面试题

## 题 1：Spring Cloud Gateway 怎么做高可用？

- 网关无状态，多实例横向扩展 + 前置 LB（SLB/Nginx/DNS）。
- 难点在下线：先摘流量（注册中心摘除/LB 健康检查判不健康）→ 等在途请求处理完 → 再关进程，避免 502。
- 加分：强调 SCG 是 WebFlux/Netty，过滤器里不能做阻塞 IO，否则占死事件循环。

## 题 2：网关实例直接 `kill -9` 会怎样？正确下线姿势？

- 正在转发的连接被硬切，客户端收到 502/超时尖刺。
- 优雅下线：先摘除新流量来源（Nacos deregister / LB 摘除），配置 graceful shutdown grace 让在途请求跑完，再关闭。
- 加分：滚动发布时按"摘→等→关→起→探活→放"的顺序逐台走。

## 题 3：CORS 应该在哪一层处理？为什么不能网关和服务都发？

- 统一在网关（`globalcors`）一处下发 `Access-Control-*` 头、由网关应答预检 OPTIONS。
- 双发会让响应里出现多个 `Allow-Origin`（该头只允许单值），浏览器判定非法直接拒绝跨域。
- 加分：提到 `allowCredentials` 与 `allowedOriginPatterns` 不能用 `*` 的组合限制。

## 题 4：网关层灰度发布怎么落地？

- 新版本实例打 metadata（权重/标签），用 `Weight` 谓词按百分比分流做金丝度放量。
- 用 `Header/Cookie/Query` 或自定义谓词按用户维度定向（内部先试、指定地区先灰）。
- 加分：回滚=权重调 0 或摘 v2 元数据，秒级切回且不发版；灰度可与限流叠加。

## 题 5：按权重和按标签两种切流有什么区别，能否叠加？

- 按权重=随机按比例（金丝度总量控制），按标签=精确命中特定请求（定向人群）。
- 可叠加：先标签定向内部用户，再权重对大盘逐步放量。
- 加分：说明权重依赖负载均衡对实例 metadata 的支持，标签依赖谓词匹配。

## 题 6：为什么 SCG 过滤器里同步调下游是危险的？

- SCG 基于响应式，事件循环线程数量少；一次同步 JDBC/阻塞 HTTP 会把该线程占死、连锁阻塞大量请求。
- 应使用 WebClient/响应式客户端做非阻塞调用。
- 加分：结合网关吞吐模型解释"少量阻塞=全局雪崩"，这也是网关鉴权/取数要走响应式的原因。
