# 网关高可用、跨域与灰度发布落地 · 小测

> 本卷满分 100 分：单选 7×6=42，多选 2×9=18，简答 1×40=40。

### 1. Spring Cloud Gateway 实现高可用的基础是（6分）

- A. 有状态需会话粘滞
- B. 无状态、可多实例横向扩展，前置 LB 分发
- C. 只能单实例
- D. 依赖本地磁盘

> 答案：B
> 解析：网关无状态，多实例 + LB（SLB/Nginx/DNS）即可扩展与容错。

### 2. 网关实例"优雅下线"的正确顺序是（6分）

- A. 直接 `kill -9`
- B. 先从注册中心摘除/停新流量 → 等在途请求处理完 → 再关进程
- C. 先关进程再摘除
- D. 不用管

> 答案：B
> 解析：先摘流量让 LB/客户端不再发新请求，等在途处理完再关，避免切断正在转发的连接造成 502。

### 3. 在 SCG 过滤器里做阻塞 IO（如同步 JDBC）的后果是（6分）

- A. 无影响
- B. 占死 WebFlux/Netty 事件循环线程，拖垮整体吞吐
- C. 只是慢一点
- D. 自动转异步

> 答案：B
> 解析：SCG 基于响应式，事件循环线程被阻塞会连锁影响所有请求，必须走非阻塞客户端。

### 4. CORS 最稳妥的下发位置是（6分）

- A. 每个下游服务各自发
- B. 只在网关统一 `globalcors` 下发
- C. 前端处理
- D. 数据库

> 答案：B
> 解析：跨域头只在一处（网关）统一下发；多处各发一遍浏览器会见到多个 `Allow-Origin` 而拒绝。

### 5. 网关和下游服务都发了 CORS 头，浏览器会（6分）

- A. 正常放行
- B. 因出现多个 `Access-Control-Allow-Origin` 判定非法、拒绝
- C. 自动合并
- D. 忽略其一

> 答案：B
> 解析：允许多值的头不能重复，双发直接触发跨域失败，这是网关+服务双配的典型坑。

### 6. SCG 里做"按权重"灰度放量，通常用（6分）

- A. 静态 DNS
- B. `Weight` 谓词 + 实例 metadata 权重
- C. 重启次数
- D. 日志级别

> 答案：B
> 解析：给新版本实例打权重、`Weight` 谓词按比例把一部分流量导入灰度池，逐步放量、可回滚。

### 7. 要"只让内部账号/指定地区先进新版本"，应采用（6分）

- A. 全量切换
- B. 按 Header/Cookie/Query 或用户标签的定向路由谓词
- C. 随机
- D. 提高权重到 100%

> 答案：B
> 解析：按标签定向可精确控制"谁先灰度"，与按权重放量组合使用。

### 8.（多选）以下属于网关灰度/高可用正确做法的有（9分）

- A. 灰度回滚把权重调 0 或摘掉新版本实例 metadata，秒级切回
- B. 网关统一处理 CORS，下游不再重复发
- C. 下线时先摘流量再等在途请求完成
- D. 在网关过滤器里用同步阻塞 HTTP 调下游

> 答案：A、B、C
> 解析：D 是反例——阻塞调用占死响应式事件循环，是吞吐雪崩的根因。

### 9.（多选）关于 SCG 的路由模型，正确的有（9分）

- A. 一条路由由 predicates + filters + uri 组成
- B. `uri: lb://service` 会走注册中心做负载均衡
- C. predicates 决定请求是否命中该路由
- D. 网关必须单实例部署

> 答案：A、B、C
> 解析：D 错——网关无状态、鼓励多实例 + LB 做高可用。

### 10. 电商大促要为"订单服务新版本"设计一套从灰度到全量、可秒级回滚、且跨域与高可用不踩坑的网关方案。（40分）

> 参考答案：
- 要点1：定向灰度——新版本实例打 metadata 标签/权重，先用 Header/用户标签让内部/指定地区命中 v2，小范围验证（10分）
- 要点2：权重放量——观察指标无异常后用 `Weight` 谓词逐步提高 v2 流量比例，金丝度推进到全量（10分）
- 要点3：秒级回滚——异常时把权重调 0 或摘掉 v2 实例元数据，流量立即全回 v1，不改代码不发版（10分）
- 要点4：高可用与跨域——网关多实例 + LB、下线先摘流量再关进程避免 502；CORS 只在网关统一下发、过滤器全非阻塞（10分）
