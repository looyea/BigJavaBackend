# 网关高可用、跨域与灰度发布落地 · 作业

### 作业 1：验证优雅上下线、复现 502

- 目标：看清"直接 kill"与"先摘流量再关"的差别。
- 任务：部署 2 个 SCG 实例 + LB，持续压测一条稳定路由；一次用 `kill -9` 下线某实例并统计 502/超时，另一次先从注册中心摘除、等在途请求结束再关，对比错误数。
- 验收标准：能复现"粗暴 kill → 502 尖刺"，"优雅下线 → 无 502"；给出网关侧 graceful shutdown 与摘除顺序的配置。
- 参考解法要点：注册中心摘除 + LB 健康检查 + shutdown grace；WebFlux 事件循环不可阻塞。

### 作业 2：CORS 双发踩坑与统一到网关

- 目标：复现"网关 + 下游各发一遍 CORS 头导致跨域失败"，并收敛到网关单点。
- 任务：一个前端跨域调用，先在网关配 `globalcors`、又在下层服务用 `@CrossOrigin` 各发一遍，用浏览器/抓包看响应里出现多个 `Access-Control-Allow-Origin` 被拒；然后删掉下游的 CORS、只留网关，验证恢复。
- 验收标准：双发能复现跨域拒绝；统一到网关后单值头、预检 OPTIONS 由网关正确应答；说清"只在一处发"的原则。
- 参考解法要点：`allowedOriginPatterns`、`allowCredentials`；下游彻底不再发跨域头。

### 作业 3：按标签定向 + 按权重放量的灰度流水线

- 目标：搭一条能定向、能放量、能秒级回滚的灰度路由。
- 任务：为订单服务部署 v1/v2 两组实例并打 metadata；配置 `Header=X-Gray` 定向谓词让带标请求进 v2，再用 `Weight` 谓词从 10% 逐步放量；观察指标正常后升到 100%，模拟异常时把权重调 0 立即回滚。
- 验收标准：带标请求稳定进 v2；权重能按比例分流；调 0 后流量秒级全回 v1 且无需改代码/发版。
- 参考解法要点：实例元数据来自 Nacos；`lb://service` 负载均衡 + 权重谓词；灰度与限流可叠加。
