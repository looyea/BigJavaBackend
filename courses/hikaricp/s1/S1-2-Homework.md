# 连接池参数调优与容量测算 · 作业

### 作业 1：用压测找池大小的拐点

- 目标：验证"大池不等于高吞吐"，找到吞吐-延迟拐点。
- 任务：固定一段代表性 OLTP 负载，把 `maximumPoolSize` 从 5 递增到 200，分别记录 TPS 与 P99 延迟，画出曲线；标出拐点，并据此给出该服务的合理池大小。
- 验收标准：能展示"吞吐先升后平/降、延迟持续上升"的曲线，指出超过 DB 承受力后吞吐下降或延迟陡增的区间，并把池定在拐点左侧。
- 参考解法要点：从"核数×2+磁盘"起点的附近扫参；观察 DB 端锁等待/连接数是否成为瓶颈。

### 作业 2：让 `maxLifetime` 与数据库 `wait_timeout` 对齐

- 目标：消除"取出已被服务端断开的死连接"导致的 `Communications link failure`。
- 任务：查出目标数据库的 `wait_timeout`（及任何代理/防火墙空闲断开时间），据此设置 `maxLifetime`（显著小于并留 30~60s 余量）与 `keepaliveTime`；构造一个把 `maxLifetime` 设得比 `wait_timeout` 长的场景，复现报错，再修正验证。
- 验收标准：能复现"错误配置→取到死连接报错→修正后不再出现"的过程；说明余量的意义。
- 参考解法要点：`maxLifetime` 加随机抖动避免同时到期抖动；云数据库/连接池中间层的空闲断开更隐蔽，需实测。

### 作业 3：固定池 vs 动态池对比实验

- 目标：理解 `minimumIdle` 对建连抖动与资源占用的权衡。
- 任务：分别用固定池（`min=max`）与动态池（压低 `min`）跑同一"空闲一段时间后突发流量"的场景，记录突发首批请求的延迟（是否含建连耗时）与空闲期数据库连接占用数。
- 验收标准：固定池在突发首批无建连延迟、空闲期占用更高；动态池省连接但突发首批延迟上升；能说明各自适用场景。
- 参考解法要点：`connectionTimeout` 与建连耗时叠加会在突发时放大首包延迟；官方更推荐稳定的固定池。
