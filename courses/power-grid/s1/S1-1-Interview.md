# 用电采集与时序数据处理 · 面试题

## 题 1：海量电表采集和普通人业务数据写入有什么不同？

- 写多读少、尖峰型(几十万点同一分钟齐发)、只增不改、按时间范围查、量级巨大。
- 所以要先缓冲削峰、批量入库，并为时间轴优化存储。
- 加分：点出"逐条直连 DB"与"表无限增长"是这类系统的两大命门。

## 题 2：上报洪峰怎么扛？

- 采集网关汇聚 + 边缘缓存/断点续传 → Kafka 按区域/表箱分区缓冲 → 消费端攒批 upsert。
- 削峰填谷，把瞬时尖峰摊平成稳定批量写。
- 加分：MQ 分区并行消费提升写吞吐，边缘续传抗网络抖动不丢数。

## 题 3：补采导致数据乱序到达怎么处理？

- 以(点位,采集时间戳)为幂等键 upsert，把迟到数据落回其原始采集时刻。
- 迟到旧值绝不覆盖更晚时刻的新值；同一时刻重复上报只留一份。
- 加分：区分"同采集时刻重复"与"不同时刻乱序到达"，用 arriveTs 决定同键保留策略。

## 题 4：为什么时序数据常用专用时序库而不是普通表？

- 时序库天然高压缩、按时间分区、TTL 自动过期、支持降采样连续查询。
- 关系库要自建这些(分区 + 定时归档 + 聚合任务)，但可复用事务生态。
- 加分：给出选型判据——量级/查询模式/团队栈/成本综合权衡，不是无脑上时序库。

## 题 5：海量历史数据怎么控存储成本？

- 冷热分离：近期细粒度热存在线，历史多级降采样(秒→分→时→日)后归档便宜存储，配 TTL。
- 加分：降采样要保留聚合口径(求和/均值/峰谷)，保证分析口径一致可追溯。

## 题 6：范围查询(某区域某天曲线)慢，你会怎么排查优化？

- 先看执行计划是否分区裁剪生效——分区键必须是时间，选错会扫全部分区。
- 建(点位,时间)联合索引，查询按分区 + 索引命中。
- 加分：结合冷热分层——老数据查降采样表、热数据查原始表，减少扫描量。
