# 负荷预测、计量计费与政企信创

> 本节难度：★★★★☆
> 本节重要性：★★★☆☆
> 学习产出：能落地电力行业三类核心应用并理解其**政企交付约束**：**负荷预测**——按短期/中期/长期划分，用历史负荷 + 天气 + 节假日 + 经济因子做特征工程，把模型**服务化**(定时批量预测、在线推理、MAPE 等回测误差指标闭环)；**计量计费**——从采集读数算真实电量(读数差 × 倍率 − 损耗分摊)、按**阶梯电价/分时电价分段计价**，构建**可版本化、可审计**的电费计算引擎并出账对账；**政企信创**——理解**私有化/内网离线部署**、**等保合规 + 审计留痕 + 数据不出域**、**国产化栈替代**(芯片/OS/数据库/中间件)与**现场实施、离线升级包、兼容性回归**等交付约束。识破"预测模型只在 notebook 不上线、无回测""阶梯电价跨月周期口径错、计费规则改了无法追溯""信创环境照搬公网 SaaS 依赖、离线装不上"等坑。

## 一、负荷预测：从历史时序到可回测的服务

```text
图目的：预测不是训练完就结束，要能定时出数并自证误差
特征：历史负荷(承采集降采样) + 气温/降雨 + 节假日/工作日 + 经济增长因子
模型：统计(ARIMA/指数平滑)或机器学习(GBDT/LSTM)，按区域/电压等级分层建模
服务化：每日定时批量预测未来 N 天 → 落预测表供调度；用 MAPE/RMSE 回测、误差超阈值告警
```

```java
// 目的：把"训练好的模型"变成每天能出数、能回测的在线能力
ForecastResult predict(Region r, LocalDate day) {
    Features f = featureStore.load(r, day);           // 说明：历史负荷 + 天气 + 日历因子，口径与训练一致
    double yHat = model.infer(f);                      // 结果：推理而非重新训练，特征口径必须和离线对齐
    double mape = backtest.mape(r, day);               // 反例：特征口径漂移(在线缺列/单位不同) ❌ 预测系统性偏差不自知
    if (mape > ALERT) monitor.alert("负荷预测误差超阈值", r, mape); // 异常：误差异常要告警回查，不能闷头发数
    return new ForecastResult(r, day, yHat, mape);
}
// 反例：模型只在 notebook 里跑、没服务化 ❌ 无法定时出数、无法回测迭代
// 反例：预测与实际用不同数据源口径 ❌ 线上线下不一致，误差不可解释
```

## 二、计量计费：真实电量与阶梯/分时电价

```text
图目的：从"表底读数"到"可审计电费"的严谨换算
真实电量 = (本期读数 − 上期读数) × 倍率(CT/PT) − 线路/变损分摊
计价：阶梯电价按档分段、峰谷分时按时间段分别计价，跨月周期口径要明确
引擎：计费规则版本化(改动留痕可追溯)，出账 → 复核 → 对账，异常电量/金额挂人工
```

- 与电商计价引擎同构：都是"多规则叠加 + 版本化 + 可审计"，区别在电力规则由**政策**驱动、口径刚性。

## 三、政企信创与私有化交付约束

```text
图目的：面向电网/政企，"能上线"之外还有强交付硬约束
私有化：内网/离线部署，无公网依赖；升级走离线包，组件要能在隔离网安装
合规：等保测评、审计留痕不可篡改、数据不出域(本地化存储与处理)
信创：国产芯片/OS/数据库/中间件替代 → SQL 方言/驱动/性能落差，需兼容性回归
```

## 四、坑与底线

- **口径刚性**：电量、线损、阶梯/分时口径由政策规定，改动必须版本化留痕、可对账可追溯。
- **离线优先**：设计与选型默认"无公网也能装能跑"，别把强依赖云托管能力写进架构。
