# 用电采集与时序数据处理 · 作业

### 作业 1：攒批 + 幂等的采集入库消费者

- 目标：把逐条高频写改造成批量幂等写，扛住上报尖峰。
- 任务：消费 Kafka 批次(如 500 条或 2s 窗口)，以(点位,采集时间戳)为键去重后 `batchUpsert`；整批写失败要整批重试且幂等。构造"同一时刻重复上报 + 半批失败重跑"两类数据。
- 验收标准：重复上报只落一份；重跑不产生重复点位；吞吐显著高于逐条 insert(给出对比数据)。
- 参考解法要点：去重键=点位+时间戳；批大小与超时窗口权衡延迟/吞吐；写入目标可为时序库或按时间分区的关系表。

### 作业 2：乱序补采的正确合并

- 目标：晚到的旧采集点不破坏时序正确性。
- 任务：实现合并策略——同一(点位,时间戳)迟到数据幂等覆盖为"最新到达的有效值"，不同时间戳各存各的、绝不用迟到旧值覆盖更晚时刻的新值。构造断点续传补采(时间戳乱序到达)的样本。
- 验收标准：补采数据落位到其原始采集时刻、按时间戳排序曲线正确；聚合(如日均)不因乱序失真。
- 参考解法要点：区分"同一采集时刻的重复"与"不同时刻的乱序到达"；用 arriveTs 判定同键保留谁。

### 作业 3：冷热分离与多级降采样

- 目标：在保留趋势可查的前提下压存储成本。
- 任务：设计按时间 RANGE 分区 + TTL 过期；把原始秒/分级数据近 N 天留热存，超期降采样为分钟/小时/日聚合并归档；实现"查某天某区域负荷曲线"验证分区裁剪生效。
- 验收标准：老数据粒度变粗、存储占用下降；范围查询命中对应分区(执行计划无全表扫)；热存窗口内仍可查原始级。
- 参考解法要点：降采样用求和/均值/峰谷等聚合口径并保留口径说明；冷热迁移与过期做成可重跑的定时任务。
