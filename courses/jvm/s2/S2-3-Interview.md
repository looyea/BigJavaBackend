# 实际面试题 · 线上调优方法论

> 收录 2024—2026 国内中大厂 Java 后端真实面试，含追问链。考察的是"你有没有真正在生产上做过调优、有没有方法论"，最怕背参数。

## 题 1：你们线上 JVM 是怎么调优的？说说流程。

**期望时长**：2~3 分钟

**答题要点**：

- 先讲**方法论**不是讲参数：定 SLA（P99 停顿/吞吐/footprint）→ 测**分配速率与晋升速率**做容量规划 → 起手 G1 默认 + `Xms=Xmx` + 开统一 GC 日志与 `HeapDumpOnOutOfMemoryError` → 观测 GC 占比/停顿/老年代趋势 → **单变量**迭代、留基线对照。
- 强调"多数问题在代码不在参数"：无界缓存、海量临时对象、泄漏，先治这些。

**追问链**：

1. 怎么判断要不要动参数？→ 有指标异常 + 能解释因果才动，一次一个，可回滚。
2. 你怎么证明调优有效？→ 同负载同环境前后对比停顿分布与吞吐（GCEasy），不是"感觉顺了"。

## 题 2：频繁 Full GC，你的排查路径？

**答题要点**：

- 先看 GC 日志确认**触发原因**：`System.gc()`/RMI、元空间达上限、晋升失败/to-space exhausted、Heap Dump 触发、`GC overhead limit` 等。
- 关键分叉：**Full GC 后老年代占用降不降**？
  - 不降 → 疑似**内存泄漏** → 落 HeapDump 用 MAT 支配树找泄漏疑犯。
  - 大幅下降 → 不是泄漏，是**分配/晋升太快** → 减少临时对象、给缓存设上限、加大 Young、必要时换收集器。

**追问链**：G1 频繁 Full GC 最常见诱因？→ **to-space exhausted**（没有空 Region 承接晋升），多因堆偏小、IHOP 太高、Mixed 回收不及时；处理是加大堆或下调 IHOP，而非乱调 `MaxGCPauseMillis`。

## 题 3：容器里 JVM 内存怎么配才不被 OOMKilled？

**答题要点**：

- 容器 memory limit 涵盖**堆 + 全部堆外**（Metaspace、线程栈、直接内存、CodeCache、GC 结构）。
- `-Xmx` 顶满 limit 必爆：JVM 自己不报 OutOfMemoryError，而是被 cgroup **OOMKilled（exit 137）**。
- 用 `-XX:MaxRAMPercentage=60` 让堆随规格伸缩，给堆外留 30~40% 余量；`MaxMetaspaceSize/MaxDirectMemorySize` 显式设上界。

**追问链**：为什么 `-Xmx` 没到却 OOMKilled？→ 堆外（尤其 Netty 直接内存、大量线程栈）吃掉了 limit 剩余部分；这些不受 `-Xmx` 管（呼应 s1-1 直接内存）。

## 题 4：`MaxGCPauseMillis` 是不是越小越好？

**答题要点**：

- 它是**软目标**，G1 据此决定本轮回收多少 Region。设太小→只敢收极少 Region→回收跟不上分配→GC 更频繁、堆持续高位→更易触发 Full GC，整体反而更慢、吞吐更差。
- 合理取业务 RT 目标的一半左右，压测验证。

**追问链**：那想要更低停顿该怎么做？→ 与其压软目标，不如**换收集器**（ZGC 亚毫秒）或减小分配速率/加大堆让 Mixed 跟得上。

## 题 5：给三类业务分别选 GC 并说明取舍。

**答题要点**：

- 电商大促（分配高、缓存多）：G1，先治无界缓存与临时对象，加大 Young 稳分配、合理 IHOP。
- 金融撮合/风控（P99/P999 是生命线）：ZGC，宁降吞吐也要压停顿，固定大堆、留足核。
- 电力边缘网关/长周期采集（内存受限、久跑不重启）：小堆 G1 甚至 Parallel，重在**防泄漏**（有界缓存、Metaspace 上界、老年代趋势监控），稳定性优先。

**追问链**：为什么不都上 ZGC？→ 读屏障降吞吐、更吃 CPU 与内存，小堆/成本敏感/吞吐型场景反而不如 G1/Parallel（呼应 s2-2）。
