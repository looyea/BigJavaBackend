# 实际面试题 · 垃圾判定与回收算法

> 收录 2024—2026 国内中大厂 Java 后端真实面试，含追问链。答题要展示"你知道机制的边界"，而不是背名词。

## 题 1：怎么判断一个对象是不是垃圾？为什么不用引用计数？

**期望时长**：90 秒

**答题要点**：

- 可达性分析：从 GC Roots 出发遍历引用边，不可达即垃圾。
- 引用计数能即时回收但**处理不了循环引用**（A↔B 互引，外部无用却计数 >0 永不回收），还有每次赋值都要增减计数的开销。

**追问链**：

1. GC Roots 有哪些？→ 栈局部变量、静态字段、运行时常量、JNI 引用、已加载 Class/类加载器、活跃线程、synchronized 持锁对象。
2. 不可达就一定立刻被回收吗？→ 有 `finalize` 的会经历一次复活窗口（但已废弃）；实际以"本轮是否被收集器处理"为准。

## 题 2：说说强软弱虚四种引用及用途。

**答题要点**：

- 强：绝不回收（宁 OOM）。软：内存不足才回收，做缓存。弱：下次 GC 即回收，`ThreadLocalMap` key/`WeakHashMap`。虚：`get()` 恒 null，配合 `ReferenceQueue`/`Cleaner` 做堆外资源释放。

**追问链**：

1. `ThreadLocal` key 用弱引用是不是就不泄漏了？→ 不是，key 弱引用只是让 key 可回收，**value 仍强引用**，还得 `remove()`（呼应 juc s3-1）。
2. 软引用做缓存要注意什么？→ 被清后 `get()` 返回 null，必须有回源/重建逻辑，否则 NPE 或功能缺失。

## 题 3：标记-清除 / 复制 / 整理各自优缺点，分别用在哪？

**答题要点**：

- 清除：简单但留碎片。复制：无碎片、按存活比例收费（存活少才划算），要预留空间。整理：无碎片但移动 + 更新引用成本高、STW 长。
- 分代：Young 复制、Old 整理。

**追问链**：为什么 Young 用复制？→ 对象朝生夕灭、存活率低，复制少量存活极便宜；Old 存活率高，复制要搬一大批不划算，改用整理。

## 题 4：什么是卡表/写屏障？为什么需要它？

**答题要点**：

- Young GC 要处理"Old→Young"的跨代引用，全扫 Old 太慢。
- 卡表把堆切成固定大小页、用字节数组标"脏卡"（含 Old→Young 引用）；写屏障在引用赋值后把对应卡标脏；Minor GC 只扫脏卡。
- G1 的 RSet（记忆集）是更精细版本，同样靠写屏障维护。

**追问链**：写屏障有代价吗？→ 有，每次引用赋值多一段标脏代码，密集写引用的程序会放大 GC 开销；这也是 ZGC 等着色指针/读屏障方案设计要权衡的点。

## 题 5：什么会导致"明明没人用了却不回收"？怎么定位？

**答题要点**：

- 对象仍挂在通向 GC Root 的引用链上：静态集合/缓存无上限、未清理的 ThreadLocal、监听器/回调注册后不注销、长生命周期线程持有任务上下文。
- 定位：堆 dump + MAT 支配树 / 泄漏疑犯报告（见 s3-2）。

**追问链**：安全点和 STW 有什么关系？→ GC 需所有线程停在安全点才开始；无安全点可达的超长循环会拖住"到达全局安全点"的时间，即使 GC 本身很快，停顿也会变长（用 `-Xlog:safepoint` 排查）。
