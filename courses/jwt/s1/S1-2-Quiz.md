# Claims、刷新与算法攻击防护 · 小测

## 一、单项选择题（每题 6 分，共 42 分）

### 1. 表示令牌过期时间的注册 claim 是？（6分）

- A. iat
- B. nbf
- C. exp
- D. jti

> 答案：C
> 解析：exp 过期、nbf 生效时间、iat 签发时间、jti 唯一标识；exp 是必设项。

### 2. 防重放、可作为黑名单键的 claim 是？（6分）

- A. sub
- B. jti
- C. aud
- D. iss

> 答案：B
> 解析：jti 是令牌唯一 ID，配黑名单/去重时靠它精确定位某一张令牌。

### 3. refresh token 轮换（rotation）的核心动作是？（6分）

- A. 每次刷新返回同一个 refresh 复用
- B. 刷新时发新 refresh 并立即作废旧 refresh
- C. refresh 永不过期
- D. 把 refresh 当 access 发给 RS

> 答案：B
> 解析：一次性轮换 + 旧值作废，配合复用检测能在令牌被窃时及时吊销整族。

### 4. `alg=none` 攻击赌的是服务端哪种缺陷？（6分）

- A. 密钥太短
- B. 信任 token 自报算法且遇 none 跳过验签
- C. 没校验 exp
- D. 没校验 sub

> 答案：B
> 解析：防御是验签入口锁算法白名单，绝不在候选里放 none。

### 5. RS256→HS256 算法混淆攻击里，攻击者拿什么当 HMAC 密钥？（6分）

- A. 服务端私钥
- B. 随机串
- C. 可公开获取的公钥
- D. client_secret

> 答案：C
> 解析：若服务端按 header.alg 选验证方式，会用公钥字符串当 secret 做 HMAC 校验而误通过——根治是服务端钉死算法。

### 6. 关于 `kid` 的处理，安全的做法是？（6分）

- A. 直接拼进文件路径去读密钥
- B. 用它拼 SQL 查 JWKS 表
- C. 仅作受信映射表的键，绝不进路径/SQL/白名单外远程地址
- D. 忽略不填

> 答案：C
> 解析：`kid` 未校验即注入可导致路径穿越或把 JWKS 指向攻击者服务器。

### 7. 私有 claims 命名的注意点是？（6分）

- A. 随意，随便覆盖 iss
- B. 不要与注册 claims 撞名，业务字段自成命名空间
- C. 必须全大写
- D. 只能放一个字段

> 答案：B
> 解析：撞注册名会破坏标准语义；role/tenant_id 这类应作为私有 claim 且避免歧义。

## 二、多项选择题（每题 9 分，共 18 分）

### 8. 一次安全的刷新流程应包含？（多选）（9分）

- A. 校验 refresh 有效且未被动过（一次性）
- B. 签发新 access + 新 refresh 并作废旧 refresh
- C. 检测到旧 refresh 复用时吊销整族并告警
- D. 把新 refresh 直接返回给 Resource Server 缓存

> 答案：A、B、C
> 解析：D 错——refresh 只在 AS token 端点用，绝不发 RS；其余三项构成轮换 + 复用检测闭环。

### 9. 下列属于 JWT 密钥治理要求的有？（多选）（9分）

- A. HS secret 足够长（≥256bit），防暴力枚举
- B. 密钥不硬编码进可反编译的前端
- C. JWKS 轮转时新旧公钥并存、按 kid 平滑过渡
- D. 为方便把私钥下发给所有微服务

> 答案：A、B、C
> 解析：D 是反面——私钥只在签发方，验签方拿公钥；下发私钥等于人人可伪造。

## 三、简答题（40 分）

### 10. 系统用 RS256，安全团队报"存在算法混淆风险"，请给出加固清单。（40分）

> 参考答案：
- 服务端钉死验证算法：只按配置用 RS256 验，绝不按 header.alg 动态选（杜绝 HS/none）。
- 算法白名单：解析入口显式允许集合 = {RS256}（或含 ES256），其余直接拒。
- 拒绝 none：任何声称 none 的 token 一律拒绝。
- 校验 aud/iss：防别的受众/签发方的 token 被拿来用。
- kid 只作查表键：不拼路径、不拼 SQL、JWKS 来源限白名单，防注入与指向攻击者服务器。
- 密钥轮转：JWKS 新旧公钥并存过渡；私钥仅签发方持有，验签方只拿公钥。

> 解析：能抓住"算法由服务端定 + 不信任 token 自报字段"这条主线即达生产水准。
