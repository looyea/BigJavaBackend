# Claims、刷新与算法攻击防护 · 作业

## 作业 1：实现 refresh 轮换 + 复用检测

- **目标**：把"旧 refresh 一次性作废 + 复用即吊销全族"落成代码。
- **任务**：用 `jti` 给每张 refresh 编号，服务端存"已签发未消费"集合；刷新时校验 jti 在集合中→消费（移除）→发新 access+新 refresh；若收到的 jti 不在集合（已被用过）→判定复用→撤销该用户整条令牌家族并写告警日志。
- **验收标准**：正常刷新得到两套新令牌；用旧 refresh 再刷一次触发 `TokenReuseDetectedException` 且该用户后续所有令牌失效。
- **参考解法要点**：家族关系用 `sub` 或根 `jti` 链维护；对照 [课文](S1-2-Lesson.md) 第二节时序图。

## 作业 2：构造并拦截三类攻击（攻防）

- **目标**：亲手复现攻击，再写防御把它挡下。
- **任务**：对一个 RS256 令牌分别构造 ① `alg=none` 去签名 ② `alg=HS256` 且用公钥当 secret 签名 ③ 篡改 payload 不改签名 三种伪造；实现验签入口（锁定 RS256、白名单算法、不信任 header.alg），断言三者全部被拒。
- **验收标准**：三用例均抛验签失败异常；把防御改成"信任 header.alg"后 ①② 能通过（证明攻击真实存在），再改回。
- **参考解法要点**：核心一条——验证算法与密钥由服务端配置决定，与 token 自报字段无关；`kid` 只做映射键。

## 作业 3：claims 设计评审（书面）

- **目标**：为一个多租户 SaaS 定 claims 规范。
- **任务**：评审现有 token 放了"手机号 + 全量权限列表 + 未加命名空间的 role"，指出机密性、权限冻结、命名冲突三处问题，给出精简后的 claims 清单（iss/sub/aud/exp/iat/jti/tenant_id + 粗粒度 scope）与细粒度权限落服务端实时查的方案。
- **验收标准**：能说明"为什么权限别塞进 JWT"（撤销窗口）与"敏感信息别塞"（明文可读）两条理由；jti 与黑名单策略配套。
- **参考解法要点**：撤销与黑名单细节见 [无状态登出、吊销与与 OAuth2 协同（关联）](S1-3-Lesson.md)。
