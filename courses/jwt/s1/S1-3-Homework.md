# 无状态登出、吊销与与 OAuth2 协同（关联） · 作业

## 作业 1：给 RS 加一层 jti 黑名单

- **目标**：让"登出后的 access 即使没过期也不能用"。
- **任务**：登出接口把当前 access 的 `jti` 连同剩余有效期写入 Redis（`SETEX jti 剩余秒数 1`）；验签拦截器在验签通过后加 `if redis.exists(jti) → 401`；断言"登出前 200 / 登出后用同一 access 401"。
- **验收标准**：登出后旧 access 被拒；条目在令牌过期后自动消失（Redis TTL 验证）；伪造令牌（未过验签）不会触达黑名单查询。
- **参考解法要点**：先验签后查黑（见 [课文](S1-3-Lesson.md) 第三节反例）；只存未过期撤销集，规模可控。

## 作业 2：登出的服务端闭环

- **目标**：把"退出"从前端删 token 变成真正的服务端吊销。
- **任务**：实现 `/logout`：① 吊销该用户全部 refresh（从授权库删除/标记）；② 把 access jti 入黑名单；③ 触发 OIDC RP-Initiated 回 AS 结束中心会话。写用例：登出后用 refresh 刷新应失败，旧 access 应 401。
- **验收标准**：refresh 再次使用被拒（断续命）；access 命中黑名单；跨应用经 Back-Channel 各自清本地会话。
- **参考解法要点**：refresh 吊销管"未来续命"、access 黑名单管"当下存量"，两者互补缺一不可；对照 [Claims、刷新与算法攻击防护](S1-2-Lesson.md) 的轮换。

## 作业 3：撤销方案分级设计（书面）

- **目标**：按业务敏感度选撤销强度。
- **任务**：为一个既有普通内容浏览、又有资金操作的系统，划分"哪些接口纯无状态短 TTL 即可、哪些必须 introspection/黑名单"，说明每级理由，并估算 AS 在 introspection 路径下的 QPS 与缓存策略。
- **验收标准**：给出分级表（内容类容忍分钟级窗口 vs 资金类要求秒级）；introspection 引入的 active 缓存 TTL 与撤销实时性的量化权衡。
- **参考解法要点**：核心是"即时性 ↔ 无状态扩展性"光谱按需取点，与 [接口签名、防重放与 KMS](../../data-security/s1/S1-2-Lesson.md) 的集中校验思路相通。
