# JWT 结构与签名验证 · 作业

## 作业 1：徒手拆一个 JWT

- **目标**：坐实"编码不是加密"的直觉。
- **任务**：造一个 HS256 的 JWT，用 Base64URL 解码器分别解出 Header 与 Payload 打印；然后把 Payload 里 `"role":"user"` 改成 `"role":"admin"` 重编码拼回，观察签名段不动时验签是否失败。
- **验收标准**：能贴出解码后的 JSON；篡改后的令牌在验签入口被拒（抛异常），证明签名覆盖了内容。
- **参考解法要点**：注意 Base64URL 与标准 Base64 的字符差异；篡改后必须连签名一起重算才"有效"，而重算需密钥（见 [课文](S1-1-Lesson.md) 第一节）。

## 作业 2：写一个安全的验签工具方法

- **目标**：把"最低正确集合"固化成可复用代码。
- **任务**：实现 `parseAndVerify(token, trustedKeyId)`：① 服务端锁定算法为 RS256（拒绝其他 alg）；② 用 JWKS 公钥按 `kid` 选验签；③ 校验 `iss/aud/exp`；④ 任一步失败抛出自定义异常而非返回 null。写单测：正常令牌通过、过期令牌拒绝、alg 改成 none 拒绝。
- **验收标准**：三个用例断言正确；`exp` 容差不超过 60 秒；代码里无任何"信任 header.alg"的分支。
- **参考解法要点**：`requireIssuer/requireAudience` + 显式允许算法集；`kid` 找不到公钥直接拒（为下节轮转铺垫）。

## 作业 3：算法选型论证（书面）

- **目标**：为一套 8 个微服务共享验签的架构选 HS256 还是 RS256。
- **任务**：说明各服务都需要验签时，HS256 要求每个服务持同一 secret 带来的伪造面扩大问题，论证改用 RS256（私钥仅在签发服务、公钥分发）的理由，并给出公钥分发与轮转思路。
- **验收标准**：结论明确选非对称，理由含"验签方数量 vs 伪造能力"这条轴；提到 JWKS 轮转且新旧公钥并存过渡。
- **参考解法要点**：可延伸对照 [接口签名、防重放与 KMS](../../data-security/s1/S1-2-Lesson.md) 的密钥托管思想。
