# SCA 落地与自建/开源选型边界（关联） · 小测

> 本卷满分 100 分：单选 7×6=42，多选 2×9=18，简答 1×40=40。

### 1. 关于 Spring Cloud Netflix 组件的现状，正确的是（6分）

- A. 都在活跃演进
- B. Hystrix 停维护、Eureka/Ribbon/Zuul 1.x 进维护模式
- C. Zuul 2 已全面替代 Gateway
- D. Eureka 是首选

> 答案：B
> 解析：官方栈转向 Gateway/LoadBalancer/Resilience4j，继续抱旧 Netflix 件等于背技术债。

### 2. 替换 Hystrix 的官方推荐是（6分）

- A. 保留 Hystrix
- B. Spring Cloud CircuitBreaker + Resilience4j
- C. Zuul
- D. Ribbon

> 答案：B
> 解析：Hystrix 停维护后由 CircuitBreaker 抽象 + Resilience4j 实现承担熔断降级。

### 3. 替代 Ribbon 做客户端负载均衡的是（6分）

- A. Spring Cloud LoadBalancer
- B. Eureka
- C. Hystrix
- D. Seata

> 答案：A
> 解析：Ribbon 进维护模式，官方用 Spring Cloud LoadBalancer 接替。

### 4. SCA 落地时避免混合栈冲突的关键做法是（6分）

- A. 各模块各写版本
- B. 用 BOM 把 Boot/Cloud/Alibaba 版本锁在官方兼容矩阵上
- C. 全用 latest
- D. 不锁版本

> 答案：B
> 解析：三套版本必须按兼容矩阵配对，否则 Nacos/Sentinel/Seata starter 运行期类冲突。

### 5. 对多数公司而言，自研注册中心/配置中心的 ROI 通常（6分）

- A. 一定为正
- B. 为负——要养团队、造监控、扛稳定性事故，除非强定制/规模/合规诉求
- C. 与开源完全一样
- D. 总是最省

> 答案：B
> 解析：自建成本高、收益仅在少数强诉求场景才可能为正，多数应选成熟开源。

### 6. SCA 相对国际栈在信创/国产化场景的优势是（6分）

- A. 无优势
- B. Nacos/Sentinel/Seata/Dubbo 源自国内，与国产云/中间件亲和、中文社区与招聘易
- C. 只能海外部署
- D. 不合规

> 答案：B
> 解析：国产栈在合规自主可控、生态适配、团队熟悉度上对信创项目更顺。

### 7. "把选型当技术信仰"的典型危害是（6分）

- A. 更理性
- B. 忽视成本/团队能力/合规，追新或守旧都可能做出与业务不匹配的决定
- C. 省时间
- D. 提升稳定性

> 答案：B
> 解析：选型应是权衡（熟悉度、运维成本、合规、生态），而非站队。

### 8.（多选）从 Netflix 老栈迁移前应当评估（9分）

- A. 改动量与双栈过渡期风险
- B. 团队对新栈的熟悉与招聘难度
- C. 合规/信创诉求
- D. 完全不用评估，直接换

> 答案：A、B、C
> 解析：D 是反例——"为换而换"不核算迁移成本常把选型变成线上事故。

### 9.（多选）关于自建 vs 开源，合理的有（9分）

- A. 自建需专职团队 + 监控告警 + 故障复盘 + 稳定性风险
- B. 开源成熟件胜在生态/社区/可招聘，但要吃透运维
- C. 强定制/极致规模/合规物理隔离才可能让自建 ROI 为正
- D. 小团队也应自研中间件以显技术实力

> 答案：A、B、C
> 解析：D 是反例——小团队硬上自研会拖垮业务迭代，应把精力留给业务护城河。

### 10. 一家政务信创项目 + 一支熟悉阿里系的团队 + 少量已用 Netflix 老栈的历史服务，请给出微服务技术栈选型与迁移建议。（40分）

> 参考答案：
- 要点1：主栈选 SCA——契合信创合规与团队熟悉度（Nacos/Sentinel/Seata/Dubbo 国产、生态与招聘友好）（10分）
- 要点2：版本治理——用 SCA BOM + Boot/Cloud 兼容矩阵锁版本，避免混合栈类冲突（10分）
- 要点3：历史 Netflix 服务——先评估迁移成本，用 Gateway/LoadBalancer/Resilience4j 逐步替换停滞件，允许双栈过渡，不为换而换（10分）
- 要点4：不轻易自建——除非有强定制/合规隔离诉求，不自研中间件，把自研精力留给业务；同时建立鉴权/HA/规则持久化的运维基线（10分）
