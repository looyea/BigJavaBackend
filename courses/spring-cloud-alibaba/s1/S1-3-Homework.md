# SCA 落地与自建/开源选型边界（关联） · 作业

### 作业 1：用 BOM 锁版本并复现混合栈冲突

- 目标：体会"版本不对齐"如何把选型决定变成启动/运行期事故。
- 任务：搭一个 SCA 工程，先故意让 Boot/Cloud/Alibaba 三者版本不在兼容矩阵上（如混搭旧 Cloud + 新 Alibaba），记录启动报错；再引入 SCA BOM + 官方兼容矩阵对齐，验证恢复正常。
- 验收标准：能复现版本错配的类冲突/自动配置报错；对齐后应用正常注册到 Nacos、Sentinel/Seata 生效；说清 BOM 的纳管方式。
- 参考解法要点：查 Boot↔Cloud↔SCA 版本对应表；`dependencyManagement.imports` 引入三个 BOM。

### 作业 2：Netflix 老栈到 SCA/新栈的迁移评估表

- 目标：把"要不要迁、怎么迁"量化成决策文档。
- 任务：对若干使用 Eureka/Ribbon/Hystrix/Zuul 的服务，列出到 Nacos/Gateway/Resilience4j/LoadBalancer 的映射、改动点、双栈过渡方案与回滚预案；估算工作量与风险，给出"迁/留/分阶段"的建议。
- 验收标准：每个停滞件都有替代方案与迁移步骤；含过渡期兼容策略（如 Eureka 与 Nacos 双注册）与回滚点。
- 参考解法要点：先替换风险最低的（LB/CircuitBreaker）、网关与注册最后动；不为换而换。

### 作业 3：自建 vs 开源的 ROI 论证

- 目标：用成本项论证"多数场景应选成熟开源"。
- 任务：选一个组件（如配置中心），列出自建所需的人力、监控告警、故障演练、稳定性 SLA、招聘等成本项，与采用 Nacos 的运维成本对比；给出在何种强诉求（合规物理隔离/极致规模/深度定制）下自建才可能为正 ROI 的边界条件。
- 验收标准：成本项可量化或可解释；结论区分"团队规模/合规/定制"三类边界；避免把选型写成信仰之争。
- 参考解法要点：把"稳定性事故半径"和"持续维护成本"计入自建的隐性成本。
