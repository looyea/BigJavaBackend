# 对称/非对称/哈希与密码存储 · 作业

## 作业 1：把遗留 MD5 口令库升级到 BCrypt

- 目标：在不强依赖用户改密的前提下，把历史 MD5 口令安全迁移到自适应慢哈希。
- 任务：用 Spring Security 的 `BCryptPasswordEncoder(12)` 实现登录校验双通道——先按新哈希 `matches`，命中失败再回退校验旧 MD5，校验成功后透明重写为新哈希（rehash-on-login）；为存量用户加"必须下次登录后失效旧格式"的标记。
- 验收标准：新注册用户只存 BCrypt；老用户首次登录即完成升级；全程不落明文、不把 MD5 摘要当密码直接塞进 BCrypt 二次哈希以外的路径。
- 参考解法要点：登录服务里做"格式判定 + 校验 + 重写 + 失效"四步事务；重写失败不能影响本次登录成功；灰度期保留双读、禁写旧格式。

## 作业 2：身份证字段的信封加密落地

- 目标：为敏感字段实现"可还原机密存储 + 密钥不出 KMS"。
- 任务：用 `AES/GCM/NoPadding` 对身份证号做字段加密，每条记录使用独立随机数据密钥（DEK），DEK 由 KMS 主密钥（KEK）加密后与密文一同落库；IV 每次随机且不与同一 DEK 重用。
- 验收标准：相同身份证号在不同记录产生不同密文；密文被篡改时 GCM 认证标签校验失败并拒绝解密；应用侧永不明文持有 KEK。
- 参考解法要点：区分 DEK/KEK 两层；GCM tag 长度 128bit；解密只在必要出口按需进行，日志/异常严禁打印原文。

## 作业 3：设计一份"口令 / 字段加密 / 展示脱敏"三选一决策规范

- 目标：把本课决策图沉淀为团队可执行规范。
- 任务：针对"登录口令、银行卡号、手机号页面展示、文件完整性校验"四类场景，分别指定算法（BCrypt/AES-GCM/脱敏/SHA-256-HMAC）、密钥管理方式与禁止事项，并说明选错原语会引发的具体安全事故。
- 验收标准：每类场景给出唯一正确原语与理由；明确"Base64≠加密""ECB 禁用""可逆加密存口令=违规"三条红线。
- 参考解法要点：口令只验证→慢哈希；要还原→认证加密+KMS；只展示→不可逆脱敏在出口现算；完整性→HMAC 而非裸哈希。
