# 接口签名、防重放与 KMS · 作业

## 作业 1：实现一个可复现的 HMAC 签名过滤器

- 目标：为内部服务间调用落地稳定的签名串规范。
- 任务：写一个 Spring 拦截器，对请求参数剔除 `sign`、按 key 字典序升序拼接、值统一 URL 编码、约定 null 参与规则、追加 `timestamp` 与 `nonce`，用共享密钥做 HMAC-SHA256 生成 `sign`；服务端用同规则复现并比对。
- 验收标准：同一组参数在客户端与服务端产出的签名串字节级一致；对含中文、空值、嵌套 JSON 参数的用例两侧签名相同；篡改任一参数导致验签失败。
- 参考解法要点：TreeMap 保证排序；把规范写进注释/文档禁止各端各自实现；sign 不参与被签内容。

## 作业 2：加上时间戳窗口 + nonce 的防重放

- 目标：在作业 1 之上补齐新鲜性校验。
- 任务：校验 `|serverNow - timestamp| ≤ 5min`，超窗拒绝；用 Redis `SETNX`（`SET key val NX PX`）以 `nonce` 为键去重，过期时间不小于时间戳窗口，命中已存在则判为重放。
- 验收标准：原样重发同一请求第二次被拒；并发发起两个相同 nonce 请求只有一个放行（无竞态双放）；时钟偏差 3 分钟内仍可通过。
- 参考解法要点：切勿先 GET 再 SET；nonce 键加业务/调用方前缀隔离；窗口与过期时间联动设置。

## 作业 3：把密钥接入 KMS 并演示轮转

- 目标：消除"密钥写死配置"这一红线。
- 任务：把签名密钥/字段加密主密钥迁移到 KMS，使用信封加密生成数据密钥（DEK），库中只存密文 DEK；模拟一次主密钥（KEK）轮转，仅重包 DEK 而不重新加密业务密文，并给出每业务独立 CMK、最小权限与调用审计。
- 验收标准：应用进程内存外任何持久化位置都不出现明文主密钥；轮转前后能用新 KEK 解出旧 DEK 进而解出数据；密钥使用有可追溯日志。
- 参考解法要点：区分 DEK/KEK 两层；`kms:Decrypt` 权限收敛到具体密钥；轮转是"重包"不是"重加密海量数据"。
