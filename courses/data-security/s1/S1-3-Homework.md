# HTTPS/TLS、脱敏与合规落地（关联） · 作业

### 作业 1：把服务强制到强 TLS 并验证握手

- 目标：落实传输层控制，剔除弱协议。
- 任务：配置服务器只启用 TLS1.2/1.3、绑定有效证书链，明文 HTTP 301 跳转 HTTPS 并加 HSTS。用工具尝试以 TLS1.0 握手，观察被拒；检查证书链是否完整可验证（缺中间证书会导致部分客户端报错）。再说明为何内部服务间也应上 mTLS。
- 验收标准：弱协议握手失败、强协议正常；证书链可被信任库验证；能解释内部 mTLS 与仅保护边界的差异。
- 参考解法要点：`enabled-protocols` 与密码套件收敛；证书链/到期监控。

### 作业 2：给敏感字段做"落盘加密 + 展示掩码"双层

- 目标：体会"加密≠脱敏"、两层都要有。
- 任务：对卡号列实现 JPA `AttributeConverter`，入库前用 AES-GCM 加密、密钥从 KMS/环境变量获取（不硬编码），库里看到的是密文；查询返回给前端时掩码成"前6后4"。随后把登录口令改用 bcrypt 存储，并对比"用 AES 可逆加密存口令"的错误后果。
- 验收标准：库中卡号为密文、页面为掩码；口令为不可逆哈希且不可还原；能说明密钥与数据分离、可轮换的意义。
- 参考解法要点：AES-GCM 带 IV/认证标签；bcrypt 工作因子可调；展示脱敏覆盖导出/日志。

### 作业 3：把一条 GDPR"被遗忘权"做成可验证流程

- 目标：证明删除权落到"真删/不可逆匿名"。
- 任务：为某用户发起删除请求，梳理其数据在主表、备份、日志、缓存、数仓中的分布；实现"物理删除或不可逆匿名化"，并写一个"删除后无法再关联回该自然人"的验证（如软删除被判定不合格）。输出一份删除范围清单与审计记录。
- 验收标准：能给出跨存储的删除清单与验证证据；明确软删/仅前端隐藏为何不达标；有操作审计留痕。
- 参考解法要点：最小化与去标识；密钥级"加密即删"（销毁密钥）也是一种不可逆手段。
