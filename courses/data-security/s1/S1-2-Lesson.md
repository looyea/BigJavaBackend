# 接口签名、防重放与 KMS

> 本节难度：★★★★☆
> 本节重要性：★★★★★
> 学习产出：能制定稳定的签名串规范（参数排序、拼接、编码约定），用"时间戳 + nonce + 签名"三件套防篡改与重放，讲清 HMAC 与公私钥签名各自的适用边界；理解密钥为什么必须进 KMS 托管、如何做轮转与信封加密，并识别"签名串不含时间戳""nonce 不去重""密钥写死配置"等高频事故。

## 一、接口签名到底在防什么

签名同时解决三件事，缺一件就留一个洞：

```text
图目的：把"签名/防篡改/防重放"三目标拆开看
防篡改：改动任一参数都会使验签失败——覆盖参数、金额、角色字段
防冒充：没有密钥就无法伪造合法签名，调用方身份得以确认
防重放：合法签名被原样截获再发一次——需时间戳窗口 + nonce 唯一性兜底
关键认知：签名本身不防重放，一段固定请求签名永远合法；必须叠加时效与去重。
```

## 二、签名串规范：稳定、可复现、无歧义

验签方要能字节级复现签名串，所以规范必须消除一切歧义：

```java
// 目的：给出一个可复现的签名串构造流程（HMAC-SHA256 示例）
// 1) 剔除 sign 字段；2) 其余参数按 key 字典序升序排序；
// 3) 拼成 k1=v1&k2=v2...（值统一 URL 编码、null 参与或不参与要有明文约定）；
// 4) 追加 timestamp 与 nonce；5) 用密钥做 HMAC-SHA256，结果 hex/base64 即 sign。
String base = sortedParams + "&timestamp=" + ts + "&nonce=" + nonce; // 目的：串必须两端同规则
String sign = HmacUtils.hmacSha256Hex(secret, base);                 // 结果：sign 参与传输但不参与 base
// 反例：参数用 HashMap 遍历顺序拼接 ❌ 顺序不定→两端签名不一致，偶发验签失败
// 反例：空值/嵌套对象编码规则没约定 ❌ JSON 空格、中文转义差异导致签名对不上
// 反例：secret 拼进 base 又参与排序 ❌ 规则含混，攻击者可探测拼接方式
```

## 三、防重放：时间戳窗口 + nonce 去重

```text
图目的：两层防线各司其职，组合才闭环
时间戳：|serverNow - ts| ≤ 窗口(如5min) → 挡掉过期报文，缩小重放可用时间
nonce：窗口内每个随机串只能用一次，存 Redis SETNX + 过期=窗口时长 → 挡掉窗口内重放
为何要 SETNX 而非先 GET 再 SET ❌ 并发下两请求同时 GET 到"不存在"会双双放行（竞态）
nonce 过期时间 ≥ 时间戳窗口，否则 nonce 先失效会留下重放空隙
```

## 四、HMAC 还是公私钥签名？

```text
图目的：按"是否双方共享密钥"选签名算法
HMAC-SHA256：对称，快，密钥双方共享 → 适合内部服务间、App/网关与后端
RSA/ECDSA(非对称)：私钥签、公钥验，验证方拿不到私钥 → 适合开放平台给第三方、验签方众多
国密场景对应 SM3-HMAC / SM2 签名，选型逻辑同上（见上节 SM 系列）
```

## 五、KMS：密钥为什么不能躺在配置里

密钥一旦进代码/配置文件/日志，就等于把锁和钥匙钉在一起挂门口。KMS（密钥托管服务/加密机）负责密钥的**生成、存储、使用、轮转、销毁**全生命周期，明文密钥永不出信任边界：

```java
// 目的：信封加密 + KMS，应用只拿到临时明文 DEK，用完即焚
EncryptResult r = kms.generateDataKey("AES_256");   // KMS 返回明文 DEK + 被主密钥加密的密文 DEK
byte[] ct = aesGcm.encrypt(plaintext, r.getPlaintext()); // 结果：数据用 DEK 本地加密，快
save(r.getCiphertextBlob());                          // 说明：库只存密文 DEK，明文 DEK 不落盘
// 轮转：主密钥(KEK)轮转时用新 KEK 重包 DEK(ciphertextBlob) 即可，海量密文数据无需重算
// 反例：把主密钥写进 application.yml 提交进 Git ❌ 一次泄露全线失守，且难以审计与轮转
// 反例：所有租户/所有表共用一把写死的 key ❌ 爆炸半径=全库，无法按域隔离与独立轮转
```

- 最小权限：每个业务/环境独立 CMK，应用只有 `kms:Decrypt` 到具体密钥，不能导出明文密钥。
- 审计：每次用密钥都留 CloudTrail/操作日志，密钥使用可追溯是合规硬要求。
