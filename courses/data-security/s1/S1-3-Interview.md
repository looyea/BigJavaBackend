# HTTPS/TLS、脱敏与合规落地（关联） · 面试题

## 题 1：HTTPS 上了是不是就数据安全了？

- 不是。TLS 只保护"传输中"的链路，管不了"落盘""日志""导出""展示"。
- 完整要分三层：传输(TLS)、存储(字段加密)、使用(脱敏/去标识)，缺一层就有对应攻击面。
- 加分：举"HTTPS 但库里卡号明文，拖库仍裸奔"的例子。

## 题 2：展示脱敏和字段加密有什么区别？能互相替代吗？

- 展示脱敏是给人看时掩码，不改变库里明文；字段加密是落盘即密文，防拖库/备份泄露。
- 不能互替：只 mask 不加密，数据仍明文可被窃取；只加密不 mask，界面/日志可能泄露明文。
- 加分：区分掩码/哈希/加密三用途，说明各自适用场景。

## 题 3：登录口令怎么存？为什么不能用可逆加密？

- 用不可逆强哈希 bcrypt/scrypt/Argon2，带盐、可调工作因子。
- 可逆加密一旦密钥泄露即可还原明文，而口令本不需要还原，加密反而多一个泄露点。
- 加分：解释加盐防彩虹表、工作因子抗暴破。

## 题 4：PCI-DSS / GDPR / 等保分别大致约束什么？怎么落到技术？

- PCI：卡号 PAN 存储加密+展示截断+传输 TLS+访问审计。GDPR：数据最小化、被遗忘权(真删/不可逆匿名)、去标识、跨境合规。等保：分等级保护、传输与存储加密、审计留痕、密钥集中管控。
- 落地就是把每条翻译成控制点：强 TLS、字段加密、掩码覆盖所有出口、审计日志、KMS。
- 加分：强调"上一个 HTTPS 就宣称合规"是常见误区。

## 题 5：字段加密的密钥怎么管？

- 交给 KMS 托管，密钥与数据分离存放、定期轮换、访问留痕，绝不硬编码/随数据同库同备份。
- 可用信封加密：数据密钥加密数据、主密钥(KMS)加密数据密钥。
- 加分："加密即删"——销毁密钥可作为一种不可逆删除手段满足删除权。

## 题 6：内部服务之间有必要也加密吗？

- 有。只保护边界，内网被打通或存在横向移动时明文流转同样泄露；合规（等保/零信任）也要求。
- 用 mTLS 做服务间双向认证 + 传输加密。
- 加分：结合证书轮换与服务身份，说明 mTLS 也顺带解决"谁在调用"的问题。
