# 对称/非对称/哈希与密码存储

> 本节难度：★★★★☆
> 重要程度：★★★★★
> 学习产出：按"要不要密钥分发、要不要可逆、要不要定长摘要"三个问题正确选用 AES（对称）、RSA/ECC（非对称）、BCrypt/Argon2（哈希）；落地密码存储与字段级加密/脱敏，理解国密 SM 系列的合规场景，并识破"MD5 存密码""ECB 模式""可逆加密存口令"三大高频错误。

## 一、三件套各管什么：一张决策图

```text
图目的：按需求选原语，别用错工具
要机密且两端能安全共享一把密钥 → 对称 AES（快、批量数据、字段加密、TLS 会话密钥）
要机密但无法预共享密钥/要签名验签 → 非对称 RSA/ECC（公钥加密私钥解、私钥签公钥验）
只要"验证不还原"（口令、完整性） → 哈希 MD5/SHA-2（摘要）/ BCrypt/Argon2（口令自适应）
混合：非对称只加密一把临时对称密钥（信封），批量数据用对称——TLS/字段加密都这么干。
```

## 二、密码存储：只用自适应慢哈希，绝不"加密"

密码是"验证时比对、永不还原"，所以用**单向哈希**，且必须是**带盐 + 可调代价的慢哈希**。

```java
// 目的：口令存储的正确姿势——BCrypt 自带盐、可调 work factor
BCryptPasswordEncoder enc = new BCryptPasswordEncoder(12);   // cost 12 ≈ 2^12 轮，抗 GPU 暴力
String stored = enc.encode(rawPwd);                          // 结果：$2a$12$<salt><hash> 内含随机盐
boolean ok = enc.matches(input, stored);                     // 说明：无"解密"，只重算比对
// 反例：MD5(password) / SHA1(password) 存库 ❌ 快哈希 + 无盐 → 彩虹表/GPU 秒破
// 反例：用 AES "可逆加密"存密码 ❌ 密钥一旦泄露全部口令裸奔；密码本就不该可还原
// 反例：全局固定盐或不加盐 ❌ 同口令同摘要，一次泄露批量撞库
```

- Argon2id（内存硬）是新推荐，抗 GPU/ASIC 更强；资源受限时 BCrypt 仍足够。
- 迁移老 MD5 库：登录成功时用新哈希透明重写（rehash-on-login），配合强制改密策略收敛。

## 三、字段级加密与脱敏：区分"要还原"和"要展示"

```text
图目的：敏感字段的两类处理别混为一谈
加密（可逆，需还原原文）  身份证/银行卡 → AES-GCM 存密文，密钥进 KMS；查询按需解密
脱敏（不可逆，只为展示）  手机号 138****8000、姓名 张* → 展示层掩码，原文不必存明文、掩码在出口处现算
```

```java
// 目的：字段加密选 AES/GCM（认证加密），而不是会被检出模式的 ECB
Cipher c = Cipher.getInstance("AES/GCM/NoPadding");         // GCM 提供机密 + 完整性（防篡改）
c.init(ENCRYPT_MODE, key, new GCMParameterSpec(128, iv));   // iv 每次随机、不重用
byte[] ct = c.doFinal(idCard.getBytes(UTF_8));              // 结果：密文 + 认证标签一起存
// 反例：AES/ECB ❌ 相同明文块→相同密文块，图案泄露，数据块可被重排（经典"企鹅图"事故）
// 反例：一个密钥加密所有行且写死代码里 ❌ 应每记录数据密钥 + KMS 主密钥信封（下节）
```

## 四、国密 SM 系列：合规场景的必选项

金融、政务、电力等关基/等保场景常要求国密算法，选型并非"更强"而是"合规 + 自主可控"：

```text
图目的：国密与国际算法的对应与替换点
SM2  ↔ 非对称（ECC 类比）：数字签名、密钥交换、小数据加解密
SM3  ↔ 哈希（SHA-256 类比）：摘要、签名前置哈希
SM4  ↔ 对称（AES 类比）：分组加密，字段/通道数据机密性
落地：证书链、HSM/加密机、TLS 国密改造（GM/T 0024），别只换名字不换合规链路。
```
