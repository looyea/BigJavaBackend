# 幂等键设计与分布式去重 · 作业

### 作业 1：为无天然业务键的接口设计幂等键

- 目标：确定稳定、唯一、可覆盖窗口的幂等键，杜绝"每次不同"的伪键。
- 任务：给一个"用户领取优惠券"接口（无天然唯一业务键），设计客户端 `Idempotency-Key`（UUID）方案：键如何生成、如何在重试时保持同一 key、服务端如何按 key 去重。构造"用户手抖点两次、网关又重试一次"场景，验证只生效一次。
- 验收标准：同一次领取的多路径请求归一到同一 key、只发一张券；用时间戳/随机数当键的反例能复现重复发放。
- 参考解法要点：键粒度对齐"一次领取意图（用户+活动）"；键要稳定携带于重试。

### 作业 2：原子去重 + 失败可重来

- 目标：去重"检查-占位"原子化，且区分"已受理/已完成"。
- 任务：用 Redis `SETNX + TTL` 实现原子占位，成功写结果、重复请求回放首次结果；处理失败时删除占位允许重试。对比"先 get 再 set"两步在并发下的双执行 bug，并复现修复。给去重记录设合理 TTL（覆盖最大重试窗口）。
- 验收标准：并发同键只有一个执行；失败能重来不被永久判重；重复请求拿到一致响应；记录不无限膨胀。
- 参考解法要点：也可用 DB 唯一索引 insert 捕获冲突做占位。

### 作业 3：跨请求/跨消息的一致去重

- 目标：让同一逻辑操作经请求重试与 MQ 重投两条路都只生效一次。
- 任务：设计一张共享去重表（唯一键约束），下单成功后发消息，消费端与接口端都以同一业务键（订单号）去重；模拟"接口重试 + 消息 at-least-once 重投 + 多实例并发消费"，验证去重存储共享、进程内存去重会失效。
- 验收标准：三条重复路径都被同一键拦住；去重在集群下生效（共享存储）；说明键选择如何穿透不同物理来源。
- 参考解法要点：与"消息消费幂等""乐观锁/状态机"两节联动，形成端到端一致。
