# 乐观锁、CAS 与状态机幂等 · 小测

> 本卷满分 100 分：单选 7×6=42，多选 2×9=18，简答 1×40=40。

### 1. 乐观锁/CAS 实现幂等的机制是（6分）

- A. 每次都加全局锁
- B. 更新带上"读到的 version"作条件，版本不匹配则影响 0 行，重复写自然失效
- C. 靠 sleep 错开
- D. 更新前先查询打印

> 答案：B
> 解析：`WHERE id=? AND version=?` 由数据库原子判定，后到的相同更新因版本已变而不生效，等价执行一次。

### 2. 状态机能天然幂等的关键设计是（6分）

- A. 状态随便跳
- B. 状态只沿合法方向单向流转，更新写 `WHERE status=前置状态`，终态不可被覆盖
- C. 每次重置为初始
- D. 不记录状态

> 答案：B
> 解析：重复/乱序消息因前置状态不符而更新 0 行；终态不可逆，非法/重复跃迁被条件拒掉。

### 3. CAS 为什么用单调 version 而不是直接比较 value？（6分）

- A. version 更省空间
- B. 只比 value 会中 ABA（值绕回原样但中间变过），单调 version 能识别"确实变过"
- C. value 不能比
- D. 无所谓

> 答案：B
> 解析：扣了又加回可能让 value 相同却语义已变；version 只增不减，能可靠判定"是否我的那次更新"。

### 4. "更新影响 0 行"最恰当的理解是（6分）

- A. 一定是失败要报错
- B. 可能是幂等重放(已生效过，应返回成功/原结果)，也可能是并发冲突(需重读再决定)
- C. 一定要无限重试
- D. 表示数据库坏了

> 答案：B
> 解析：一刀切吞掉会掩盖错误、一刀切重试会制造重复；须结合幂等键/是否已达终态辨析语义。

### 5. 相比外部去重表，"CAS + 状态机"幂等的优势是（6分）

- A. 不用写代码
- B. 去重内聚到数据本身、原子更新，不存在去重表与业务数据不一致的窗口
- C. 一定更快
- D. 不需要主键

> 答案：B
> 解析：条件更新由 DB 原子保证，判定与写入合一，比"先查去重表再操作"更少不一致缝隙。

### 6. 悲观锁 `SELECT FOR UPDATE` 在高并发下的主要代价是（6分）

- A. 更安全但完全没用
- B. 持锁串行、吞吐受限，热点行易成瓶颈，不如乐观 CAS 适合"冲突少"场景
- C. 一定比乐观慢
- D. 无法回滚

> 答案：B
> 解析：冲突不高时乐观锁避免长期持锁、吞吐更好；冲突极激烈时乐观会频繁重试，需权衡。

### 7. "状态倒流"数据损坏通常由什么引起？（6分）

- A. 加了前置状态条件
- B. 更新不校验前置状态，迟到的旧消息把已推进的状态改回早期值
- C. 用了 version
- D. 设了终态

> 答案：B
> 解析：不带 `WHERE status=前置` 的裸 set 会让乱序消息倒改状态；单向流转条件正是防护。

### 8.（多选）用乐观锁 CAS 正确落地需注意（9分）

- A. 更新条件带 version（或状态前置）
- B. 影响 0 行时区分"幂等重放"与"并发冲突"
- C. 用单调递增 version 防 ABA
- D. 一律 while 重试到成功

> 答案：A、B、C
> 解析：D 危险——若是重复提交，重试到底会制造第二次扣款。

### 9.（多选）状态机设计保证幂等应做到（9分）

- A. 只允许合法方向的单向跃迁
- B. 终态不可被后续重复/乱序消息覆盖
- C. 更新用 `WHERE status=前置状态` 做原子判定
- D. 任何状态都能互相跳

> 答案：A、B、C
> 解析：D 会让非法/重复消息随意改状态、破坏一致性。

### 10. 为一个"库存扣减 + 订单状态推进"设计基于乐观锁与状态机的幂等方案，要求防超卖、防重复扣减、防状态倒流。请给出方案。（40分）

> 参考答案：
- 要点1：库存 CAS——扣减用 `UPDATE stock SET qty=qty-? WHERE id=? AND qty>=?`（条件更新原子防超卖），或 version CAS 拒重复扣减，影响 0 行据语义判重复/冲突（10分）
- 要点2：订单状态机——`待支付→已支付→已发货→完成` 单向流转，更新带 `WHERE status=前置`，重复支付回调因 status 已变而 0 行、天然幂等（10分）
- 要点3：防 ABA 与倒流——用单调 version 而非裸值比较；严禁无前置条件的裸 set，终态不可被覆盖（10分）
- 要点4：0 行辨析——结合幂等键/是否已达终态判定"重放(返成功)"vs"并发冲突(重读重试)"，不一刀切吞错也不无限重试（10分）
