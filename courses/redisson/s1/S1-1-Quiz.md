# 小测验 · RLock 可重入锁与看门狗续期

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分折算百分制，≥ 60 分过关。

### 1. Redisson RLock 在 Redis 里用什么数据结构存储锁与重入次数？（15分）

- A. String，value 存重入次数
- B. Hash，field=`uuid:threadId`、value=重入次数
- C. Set，成员是线程 ID
- D. ZSet，score 是时间戳

> 答案：B
> 解析：Hash 才能同时记录"哪个线程持有 + 重入了几次"——field 精确到线程实现可重入与按持有者释放，String 只能存一个值无法表达多信息。

### 2. 看门狗（watchdog）在什么条件下才会自动续期？（15分）

- A. 任何时候都会
- B. 只有调用不带 leaseTime 的 `lock()` 时；显式传 leaseTime 则不续
- C. 只有 `tryLock` 时
- D. 只有 Redis 集群模式下

> 答案：B
> 解析：无参 `lock()` → 锁默认 TTL 30s、每约 10s 续一次；`lock(leaseTime, unit)` 表示你自担过期时间，看门狗关闭，到点无条件释放。

### 3. 【多选】关于 `RLock` 可重入与释放，正确的有？（20分）

- A. 同一线程重复 `lock()` 计数 +1，不会自死锁
- B. `unlock()` 计数 -1，减到 0 才真正删锁并发解锁通知
- C. 任何线程都可以替持锁线程 `unlock()`
- D. 持锁进程宕机后，锁靠 TTL 到期自动释放（看门狗不再续）

> 答案：ABD
> 解析：C 错——Redisson 校验解锁者身份，非持有线程 unlock 抛 `IllegalMonitorStateException`，这是防误放的正当保护。ABD 描述可重入语义与宕机自释，均正确。

### 4. 判断：`lock(5, TimeUnit.SECONDS)` 后若业务实际跑了 8 秒，最坏情况是锁在第 5 秒被自动释放、另一线程并发进入临界区。（10分）

- A. 正确
- B. 错误

> 答案：A
> 解析：显式 leaseTime 关闭看门狗，5s 到点无条件释放；业务未完即失锁 → 互斥被破坏。这是分布式锁第一大坑"锁提前失效"。

### 5. 填空题：Redisson 加锁用 ______ 脚本把"判归属/增减重入计数/设过期"合成一次原子操作；线程等锁时不是裸轮询，而是依赖 Redis 的 ______ 机制在被释放时唤醒。（20分）

> 答案：Lua（EVAL） / 发布订阅（Pub/Sub）

### 6. 持锁业务耗时不可预测（要调下游），你选 `lock()` 还是 `lock(leaseTime)`？说明理由与前提。（20分）

> 参考答案：
> - 选无参 `lock()`，交给看门狗续期——避免"leaseTime < 业务耗时"导致锁提前失效、并发进入
> - 前提认知：看门狗依赖客户端进程存活，进程不挂就一直续、挂了则最多 30s 自动释放（不会死锁）
> - 反向：只有当持锁时长可预估、且能保证远小于所选 leaseTime 时，才用带参 lock，换取"不依赖 watchdog"的确定性
> - 补一句：真正长任务还应缩小临界区 / 改用异步或幂等，别拿分布式锁硬扛分钟级操作
