# 小测验 · RedLock 争议与读写锁/信号量/闭锁

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分折算百分制，≥ 60 分过关。

### 1. RedLock 主要想解决单主 Redisson 锁的什么问题？（15分）

- A. 锁不可重入
- B. 主从异步复制下 master 宕机切主导致"锁丢失、两个客户端同时持锁"
- C. 加锁太慢
- D. 看门狗不续期

> 答案：B
> 解析：锁写到主未同步到从、主崩溃升主 → 新主无此锁 → 互斥被破。红锁用 N 个独立节点过半加锁，把"丢锁"门槛提高到"多数派同时失效"。

### 2. Martin Kleppmann 质疑 RedLock 的核心论点是？（15分）

- A. Redis 太慢
- B. 红锁依赖时间做安全，GC 停顿/时钟漂移会让过期持锁者仍以为持有，且缺 fencing token，互斥仍可能被破
- C. 红锁不支持集群
- D. Lua 脚本有 bug

> 答案：B
> 解析：这是论战命门——凡"用超时判断持有"又无单调递增栅栏令牌，恶劣故障下都不能保证互斥。antirez 承认需时钟/进程大致正常。

### 3. 【多选】关于 Redisson 同步器，用法正确的有？（20分）

- A. `RReadWriteLock`：读读共享、写独占，适合配置类读多写少
- B. `RSemaphore`：设置 permits 限制全集群同时执行的任务数
- C. `RCountDownLatch`：等 N 个分片任务全部 countDown 后主线程 await 返回
- D. 用完 `RSemaphore.tryAcquire` 后不必 release，靠过期自动回收

> 答案：ABC
> 解析：D 错——信号量许可必须显式 `release` 归还（异常路径更要），漏还等于许可只减不增，最终全集群被堵死；这是"获取必归还"铁律的分布式版。

### 4. 判断：对金钱、不可回滚这类"绝不允许两个同时进"的正确性锁场景，最稳妥是直接依赖 Redis RedLock。（10分）

- A. 正确
- B. 错误

> 答案：B
> 解析：红锁只降低概率、非绝对互斥。正确性锁应用基于共识的 CP 系统（ZooKeeper/etcd）+ fencing token，或数据库唯一约束/串行化事务。

### 5. 填空题：RedLock 要求 N 个 Redis 实例彼此 ______（填"主从复制"或"独立部署"）；持锁成功的两个条件是"过半加锁成功"和"总耗时小于 ______"。（20分）

> 答案：独立部署 / leaseTime（锁的有效期）

### 6. 一句话分别说明"效率锁 vs 正确性锁"你各选什么方案，并给 RedLock 一个合理定位。（20分）

> 参考答案：
> - 效率锁（防常见并发、容极小概率失效，绝大多数业务）：单主 Redisson RLock + 幂等/重试即可，红锁的延迟与运维成本不划算
> - 正确性锁（金钱/不可回滚）：CP 系统（etcd/ZK）+ fencing token 或 DB 约束，不指望 Redis
> - RedLock 定位：介于二者之间的加固选项——比单主更抗主从丢锁，但受时钟/GC 质疑，适合"想提高可用性又暂时不便引入 ZK"的中间地带，且务必保证节点真正独立
