# 分布式对象与远程服务 · 小测

> 本卷满分 100 分：单选 7×6=42，多选 2×9=18，简答 1×40=40。

### 1. Redisson 分布式集合（如 RMap）的正确心智是（6分）

- A. 就是本地 HashMap，随便遍历
- B. API 像集合，底层是 Redis + 网络往返，遍历/全量操作代价高
- C. 无网络开销
- D. 存多少数据都不怕

> 答案：B
> 解析：size()/entrySet()/遍历可能触发全量拉取或多命令，不能按本地内存心智滥用。

### 2. 用 RMapCache 而非裸 RMap 的典型理由是（6分）

- A. 支持条目级 TTL 与淘汰，适合做共享缓存
- B. 更快
- C. 不占内存
- D. 无需序列化

> 答案：A
> 解析：RMapCache 提供 per-entry 过期与惰性/定时清理，避免把 RMap 当无界哈希导致膨胀。

### 3. RLocalCachedMap 的"短暂不一致"来自（6分）

- A. Redis 不持久化
- B. 本地副本失效靠 RTopic 广播，其它节点收到前有窗口期
- C. 网络一定丢包
- D. 序列化错误

> 答案：B
> 解析：两级缓存写后经广播清本地副本，广播到达存在延迟窗口，故只适合容忍毫秒级最终一致的热点读。

### 4. 关于 RemoteService/RRemoteCallable，正确的定位是（6分）

- A. 可替代线程池跑海量重任务
- B. 把一次性调用/异步任务下发到注册服务的另一 JVM，需序列化且两端类一致
- C. 完全本地执行
- D. 不需要编码

> 答案：B
> 解析：它经 Redis 投递调用，参数须可序列化、版本一致；海量/弹性任务该用真正 MQ 或调度。

### 5. 把百万级明细塞进一个 RMap 的问题是（6分）

- A. 更安全
- B. 形成大 key，违反 Redis 大 key 纪律，迁移/删除/访问都卡
- C. 更快
- D. 无影响

> 答案：B
> 解析：Redis 只适合放热数据、原子小操作；海量数据应落 DB，大 key 会带来一系列运维与性能灾难。

### 6. Codec（序列化）为什么是"一等地基"（6分）

- A. 无关紧要
- B. 默认 JSON codec 有性能与跨版本兼容代价，改类结构可能导致反序列化失败/行为漂移
- C. 只影响美观
- D. 永远不用管

> 答案：B
> 解析：分布式对象把数据/调用序列化过网，codec 关系性能与前后兼容，热点场景要评估更省的编码。

### 7. 需要跨多个 JVM 做"缓存失效通知/广播"，应选（6分）

- A. RTopic 发布订阅
- B. RAtomicLong
- C. 本地 synchronized
- D. 轮询数据库

> 答案：A
> 解析：RTopic 是 Redis pub/sub 封装，天然用于跨进程广播与失效通知，也是 RLocalCachedMap 的失效通道。

### 8.（多选）下列关于分布式集合使用纪律正确的有（9分）

- A. 避免对大 key 做 entrySet()/全量遍历
- B. 需要过期用 RMapCache 而非裸 RMap
- C. 海量持久数据放 Redis 集合即可
- D. 单命令操作优先，跨命令原子性靠底层 Lua

> 答案：A、B、D
> 解析：C 错，海量数据应落 DB，Redis 只放热数据；A/B/D 是避免大 key、正确选型与理解原子性的纪律。

### 9.（多选）RLocalCachedMap 适合的场景特征有（9分）

- A. 读多写少
- B. 能容忍毫秒级最终一致
- C. 要求写后立刻全局强一致读
- D. 热点数据反复访问

> 答案：A、B、D
> 解析：两级缓存以本地纳秒级读换一致性窗口，C 的强一致读诉求不适合用本地缓存。

### 10. 为一个读多写少的电商商品详情设计基于 Redisson 的缓存方案，要求热点读极快、跨节点失效可控、且不踩大 key/强一致的坑。请给出选型、数据结构与注意点。（40分）

> 参考答案：
- 要点1：用 RLocalCachedMap 两级缓存——本地纳秒级读热点，写经 Redis 并由 RTopic 广播失效，接受毫秒级最终一致（10分）
- 要点2：条目用 RMapCache 带 TTL 与淘汰，防止无界膨胀；按 sku 细粒度 key，避免把整店明细塞一个大 key（10分）
- 要点3：跨节点失效用 RTopic/Invalidation 策略，监控命中率与失效延迟；强一致读诉求单独走 DB 不入本地缓存（10分）
- 要点4：Codec 选型考虑性能与前后兼容，改类结构评估反序列化；海量数据落 DB，Redis 只放热数据（10分）
