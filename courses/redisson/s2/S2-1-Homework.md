# 分布式对象与远程服务 · 作业

### 作业 1：用 RMapCache 建共享商品缓存

- 目标：把热点商品详情放 Redisson 共享缓存，避免无界膨胀。
- 任务：用 `getMapCache("product")` 写入带 30 分钟 TTL 的条目；按 `sku:{id}` 细粒度 key；分别对比裸 `RMap` 与 `RMapCache` 在过期行为上的差异；模拟把整店明细塞一个大 key 观察问题。
- 验收标准：条目到期自动清理；不出现单个大 key；不对集合做全量 `entrySet()` 过滤。
- 参考解法要点：理解 RMapCache 的惰性 + 定时清理；强调"Redis 只放热数据、海量落 DB"。

### 作业 2：RLocalCachedMap 两级缓存与失效广播

- 目标：热点读走本地、写跨节点失效，量化一致性窗口。
- 任务：配置 `RLocalCachedMap`（Invalidation 策略），两个进程实例并发读写同一 key；测"写后本地副本被清除"的传播延迟，并统计命中率提升。
- 验收标准：能观测到其它节点的失效广播窗口；本地命中显著降低 Redis 往返；强一致读走 DB 不入本地缓存。
- 参考解法要点：两级缓存换性能必然引入窗口期；对读写一致性敏感的业务要评估是否适用。

### 作业 3：RemoteService 下发一次性任务

- 目标：体验把调用经 Redis 投递到另一 JVM 执行及其边界。
- 任务：用 `RemoteService` 注册一个 `EmailApi` 提供方，消费方 `get()` 后调用 `sendAsync`；再故意传入一个两端类结构不一致的对象，观察反序列化异常。
- 验收标准：正常下发执行成功；能复现 codec/版本不一致导致的失败并说明原因。
- 参考解法要点：RemoteService 不是线程池/MQ；海量弹性任务应交给真正的消息队列或调度框架。
