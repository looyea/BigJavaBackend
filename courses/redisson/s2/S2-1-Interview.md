# 分布式对象与远程服务 · 面试题

## 题 1：Redisson 只有分布式锁吗？它还擅长什么？

- 它是"分布式数据结构框架"：RMap/RSet/RQueue/RSortedSet/RBlockingQueue/RTopic/RAtomicLong/RBitSet 等把 Redis 封装成 Java 集合语义。
- 还有 RLocalCachedMap 两级缓存、RemoteService 远程调用/异步执行。
- 加分：强调"语义像集合、成本像网络"，用之前要算清往返与大 key 代价。

## 题 2：RMap 和本地 HashMap 用法的最大区别是什么？

- RMap 每次操作都可能一次网络往返，`size()`/`entrySet()`/遍历会退化成全量拉取或多命令。
- 不能按本地内存心智随便遍历大集合，否则 OOM + 拖慢 Redis。
- 加分：需要过期用 RMapCache（per-entry TTL + 清理），避免无界膨胀。

## 题 3：RLocalCachedMap 为什么会"短暂不一致"？适合什么场景？

- 本地副本靠 RTopic 广播失效，其它节点收到前有窗口期。
- 适合读多写少、能容忍毫秒级最终一致的热点（商品详情、配置）。
- 加分：写后立刻全局强一致读的诉求不该用本地缓存，应单独走 DB。

## 题 4：RemoteService/RRemoteCallable 能替代线程池或 MQ 吗？

- 不能。它把一次性调用/任务经 Redis 序列化投递到注册的提供方 JVM 执行。
- 没有弹性扩缩、失败重试、削峰，海量任务该用真正的 MQ 或调度框架。
- 加分：参数必须可序列化且两端类版本一致，否则 codec 反序列化失败/行为漂移。

## 题 5：为什么说 Codec 是"一等地基"？

- 分布式对象把数据和调用序列化过网络，codec 直接决定性能与前后兼容。
- 默认 JSON codec 有开销；改类结构跨版本可能导致反序列化失败。
- 加分：热点集合考虑更省的编码方案，变更前评估兼容性。

## 题 6：能用 Redisson 集合存百万级数据吗？

- 不建议。Redis 只适合放热数据、做原子小操作，海量数据应落 DB。
- 塞成一个大 key 会违反大 key 纪律，迁移/删除/访问都卡，还挤占内存。
- 加分：把"共享 + 小原子操作"当分布式对象的正确边界，容量型存储交给数据库。
