# 小测验 · 缓存穿透/击穿/雪崩

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分折算百分制，≥ 60 分过关。

### 1. 某接口被爬虫用 `skuId=-1、-2…` 高频调用，缓存永不命中、DB 每次都查——这属于？（15分）

- A. 缓存击穿，因为都打在同一个 SQL 上
- B. 缓存穿透，因为查询的数据在 DB 中根本不存在，缓存无法回填
- C. 缓存雪崩，因为量大
- D. 缓存不一致

> 答案：B
> 解析：穿透的定义就是"查不存在的数"——miss 后 DB 也查不到，缓存层永远帮不上忙。对策：短 TTL 空值 + 布隆过滤器前置拦截。

### 2. 关于"逻辑过期"治击穿，正确的说法是？（15分）

- A. Redis 设置很短的 TTL，过期即刻通知后台
- B. value 内嵌 expireAt、Redis 层不设 TTL；发现逻辑过期由后台异步重建，当前请求直接返回旧值
- C. 用互斥锁让所有请求等待新值
- D. 彻底取消缓存过期

> 答案：B
> 解析：逻辑过期以"可能读到旧数据"换"永不阻塞"，可用性极高但不保证新鲜——秒杀价格/库存等强准确场景禁用；要求一致就用互斥重建。

### 3. 【多选】预防缓存雪崩，有效的措施有哪些？（20分）

- A. 批量写入时 TTL 加随机抖动，避免同批 key 同一秒集体过期
- B. DB 回源路径加限流与兜底数据，超容量请求宁读旧值不打死 DB
- C. 本地缓存（Caffeine）+ Redis 多级架构，Redis 整体故障时本地仍能扛读尖峰
- D. 把缓存 TTL 全部设成永不过期，一劳永逸

> 答案：ABC
> 解析：D 是错误方向——永不过期等于放弃新鲜度，且内存只增不减；正确姿势是"打散 + 限流 + 多级 + 高可用/预热"。雪崩的另一半原因是 Redis 集群宕机，靠 s1-2 的高可用兜底。

### 4. 判断：布隆过滤器判"存在"的结果可以直接信任，判"不存在"才有误判可能。（10分）

- A. 正确
- B. 错误

> 答案：B
> 解析：说反了。布隆**判"不存在"绝对可信**（没置位的 bit 不会被漏写），**判"存在"可能假阳性**（别人的哈希撞了位）——所以它能省掉大部分穿透查询，但要配空值缓存兜住假阳性。

### 5. 填空题：互斥重建的锁必须用 `SET key uuid ______ ______` 一次性获取（防死锁），释放时要用 Lua ______ 删除（防误删他人锁）；未抢到锁的应自旋等待并设 ______，超限走降级。（20分）

> 答案：NX / PX（带过期毫秒）/ 比对 value 等于自己 uuid 才 / 上限（超时后降级读旧值或兜底页）

### 6. 大促开始前，列出你对缓存三大问题的完整预案（每问至少一条措施 + 一条监控指标）。（20分）

> 参考答案：
> - 穿透：空值缓存（短 TTL）+ 布隆前置；监控"DB 中按不存在 id 查询的 QPS"
> - 击穿：热点 key 互斥重建或逻辑过期（按业务容忍度选）；监控"单条 SQL 的并发尖刺/缓存重建锁等待数"
> - 雪崩：TTL 抖动 + 预热 + 回源限流 + 多级缓存 + 高可用演练；监控"缓存命中率、回源 QPS 曲线"
> - 额外：所有方案上线前压测验证（模拟 key 集体过期场景）
