# 作业题 · 缓存穿透/击穿/雪崩

> 作业不判分，做完对照参考答案自查。需要本地 Redis + 任意压测工具（JMeter/wrk/自写脚本）。

## 作业 1：三问三判确诊（必做）

写三个小脚本分别制造：① 1000 QPS 查询不存在的 `sku=-N`；② 一个热 key TTL 到期瞬间 500 并发；③ 10 万 key 同秒过期。记录各自在 DB 侧的表现形态（QPS 曲线形状、慢日志特征）。

注释说明：三种事故在"DB 收到的请求"上的本质区别（不存在的 id / 同一行热 SQL / 一大片不同 SQL）。

## 作业 2：空值缓存 + 布隆双保险（必做）

```java
// 例子目的：给作业 1① 的穿透流量加上两层防护并量化效果
// 第一层：查 DB 无结果时 redis.set(key, "NULL", 60, SECONDS)     // 60s 空值（正确：短 TTL；错误用法：空值给 24h → 新品上架一天不可见）
// 第二层：启动时按 DB 全量 skuId 构建 Guava BloomFilter(funnel, expectedInsertions=1e7, fpp=0.01)
//         mightContain=false 直接返回"商品不存在"，不再查任何存储   // 判"不存在"绝对可信（正确使用结果：DB QPS 归零）
// 验证：三档（无防护/仅空值/空值+布隆）各压测 30s，记录 DB QPS 与接口 P99
```

**参考答案要点**：仅空值档 DB QPS ≈ 不同伪造 id 数/60s；加布隆后 ≈ 假阳性率 × 流量；体会"fpp 0.01 vs 0.1"的差距。

## 作业 3：互斥重建完整实现（必做）

实现课文第三节的锁重建：`SET lockKey uuid NX PX 3000` + Lua 按值释放 + 等待方自旋（上限 200ms 后读旧值降级）。用 500 并发打过期热点 key，断言 `db.load` 只被调用 1 次（加计数器）。

注释记录：把锁释放改成"直接 DEL"后再压一次，观察什么场景会误删他人锁（重建耗时 > 锁 TTL 时）。

## 作业 4：逻辑过期 vs 互斥重建对比（选做）

同一热点场景分别用两种策略压测，输出 QPS、P99、"读到旧值的比例"三指标。

**参考答案要点**：逻辑过期无等待（P99 平坦）但窗口内全读旧值；互斥重建等待者 P99 出现尖刺但零旧读——按业务选（详情页可旧，库存不可）。

## 作业 5：雪崩演练（选做）

给 1 万 key 设统一 30s TTL，到点压测观察回源尖刺；再改为 `30+rand(0..6)s` 复测，贴两张回源 QPS 曲线。

注释说明：为什么"批量导入"场景最容易埋雪崩雷；预热脚本如何与 TTL 打散配合。
