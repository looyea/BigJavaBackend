# 实际面试题 · 缓存穿透/击穿/雪崩

> 收录 2024—2026 国内中大厂 Java 后端真实面试，含追问链。考"三大问题怎么区分、你们线上怎么防、出过事故吗"。

## 题 1：一句话区分穿透、击穿、雪崩，并各给一个方案。

**期望时长**：60 秒

**答题要点**：

- **穿透**：查**不存在**的数据，缓存永不回填 → 每次都到 DB。方案：空值缓存 / 布隆过滤器。
- **击穿**：**单个热 key** 过期瞬间高并发同时 miss → 压力集中在一条 SQL。方案：互斥重建 / 逻辑过期。
- **雪崩**：**大批 key 同时过期**或 Redis 集群宕机 → 全量回源打垮 DB。方案：TTL 抖动、回源限流、多级缓存、高可用+预热。

**追问链**：怎么快速确诊线上是哪种？→ 看 DB 侧：不存在的 id 变多=穿透；同一行 SQL 并发尖刺=击穿；命中率断崖且所有 SQL 都慢=雪崩。

## 题 2：布隆过滤器防穿透，有什么坑？

**答题要点**：

- **假阳性**：判"存在"可能错 → 挡不掉全部穿透，需再叠一层空值缓存兜底。
- **不支持删除**：数据下架后仍在集合 → 用周期重建（全量新建+原子换）或 Cuckoo/Counting Bloom。
- **新品误杀**：先落库、后重建；重建窗口内靠空值短 TTL 放行——不能把新品挡在门外。
- 参数：expectedInsertions 与 fpp 决定位数组大小，拍脑袋配置会导致误判率失控。

**追问链**：Redisson 的 RBloomFilter 和 Guava 的区别？→ 持久化在 Redis 共享（多实例一致）、加桶扩容（误判率上升不换层）；Guava 是本机的、重启重建。

## 题 3：互斥重建和逻辑过期怎么选？

**答题要点**：

- 互斥重建：只放一个请求回源，其余等待/降级 → **数据一致性好**，代价是延迟尖刺、吞吐降。
- 逻辑过期：永不阻塞、总返回旧值后台刷新 → **可用性/延迟最优**，代价是旧读窗口。
- 选择口径：**不允许旧值的（库存、价格、风控额度）用互斥**；可容忍秒级旧的（详情页、配置）用逻辑过期或"永不过期+定时刷新"。

**追问链**：互斥锁没设过期会怎样？→ 持有者宕机则死锁，key 永远建不起来；所以必须 SET NX PX，释放用 Lua 比对 uuid 防误删他人锁。

## 题 4：Redis 集群整个挂掉，你的系统会发生什么？怎么自救？

**答题要点**：

- 一切读全 miss → 回源风暴打 DB（最坏：DB 挂→服务雪崩）；写全失败。
- 自救分层：① 高可用让"整个挂"概率低（哨兵/Cluster 多副本）；② **本地缓存**扛读尖峰（Caffeine 短 TTL 兜一层）；③ 回源**限流+熔断+静态兜底页**（宁可读旧不可打死）；④ 恢复后**预热**再放流量。
- 平时演练：混沌工程里拔过 Redis 才有资格谈预案。

**追问链**：多级缓存的失效怎么办？→ 本地缓存 TTL 要短（秒级），一致性事件用 Pub/Sub/MQ 广播失效（s2-2 讨论的近似性在此同样适用）。

## 题 5：你们大促怎么准备缓存？说说完整 checklist。

**答题要点**：

- 预热：热点商品/页面提前灌入（按榜单跑批 + TTL 打散）。
- 防穿透：全量 id 布隆上线、空值缓存策略确认；防刷子接口在网关先限。
- 防击穿：核心 key 互斥重建或改"逻辑过期+后台刷新"；锁与降级参数压测过。
- 防雪崩：审 TTL 分布（无整点集体过期）、回源限流阈值=DB 容量、DB 侧只读账号+慢 SQL 熔断。
- 观测：命中率/回源 QPS/单 SQL 并发三告警就位；演练"拔 Redis"预案。

**追问链**：缓存命中率突然从 99% 掉到 60%，你怎么排查？→ 先看是否有大面积 key 过期/被驱逐（maxmemory+淘汰策略，s2-3），再看是否新上线代码改错 key 拼法、或数据版本切换导致 key 前缀变更。
