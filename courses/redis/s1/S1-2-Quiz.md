# 小测验 · 持久化与高可用架构

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分折算百分制，≥ 60 分过关。

### 1. BGSAVE 期间官方警告可能造成内存接近 2 倍占用，原因是？（15分）

- A. 快照文件会同时保存在内存和磁盘双份
- B. fork 子进程与父进程共享内存页，之后父进程的每次写触发写时复制（COW）产生页副本，写越忙副本越多
- C. RDB 文件解压需要双倍缓冲
- D. 子进程会复制一份 AOF

> 答案：B
> 解析：fork 瞬间只复制页表；随后被修改的页才各自复制一份。大实例 + 高写入 + maxmemory 贴顶时，COW 洪峰可致 OOM。

### 2. `appendfsync everysec` 的含义是？（15分）

- A. 每个命令都 fsync，绝不丢数据
- B. 每秒由后台线程 fsync 一次，宕机最多丢约 1 秒写入
- C. 每 1000 个命令 fsync 一次
- D. 由操作系统决定刷盘时机

> 答案：B
> 解析：everysec 是默认折中档（A=always，D=no）。命令先写入内核页缓存，每秒落盘一次——进程崩溃不丢（页缓存还在），整机断电才丢 1 秒。

### 3. 【多选】关于主从复制与 Sentinel，正确的有哪些？（20分）

- A. 从库断线重连时，若缺失部分仍在主库 backlog 内则做部分重同步，否则退化为全量
- B. Sentinel 判主"客观下线"需要达到 quorum 数量的哨兵同意，防单机网络抖动误杀
- C. 故障转移由被选为 leader 的哨兵执行：选复制进度最新的从升主，其余改指向
- D. 主从复制自带数据分片，单 key 容量超限会自动切到其它节点

> 答案：ABC
> 解析：D 错——主从每个节点都是全量数据，分片是 Cluster 的职责。A/B/C 覆盖断线续传与哨兵判定/切换机制。

### 4. 判断：Redis Cluster 中两个不同槽的 key 可以直接放进同一条 MGET 或多 key 事务。（10分）

- A. 正确
- B. 错误

> 答案：B
> 解析：Cluster 限制所有 key 必须同槽（CROSSSLOT 报错）；可用 `{hash tag}` 强制同槽，但滥用 tag 会造成单节点热点。

### 5. 填空题：7.x 混合持久化指 AOF rewrite 时文件头部以 ______ 格式存储当前数据集、尾部继续追加增量 ______ 命令，兼得加载速度与数据安全；Cluster 共 ______ 个槽，key 定位公式是 ______ mod 槽数。（20分）

> 答案：RDB / AOF / 16384 / CRC16(key)

### 6. 生产上"要不要给缓存开持久化"常有争论。给出你支持开启（至少 everysec AOF）的三条理由，及一条"可以不开"的成立前提。（20分）

> 参考答案：
> - 宕机重启缓存空城 → 全部请求回源 DB，等于人造缓存雪崩（s2-1），大促时是秒级雪崩
> - 分布式锁/计数器/令牌桶等语义依赖 Redis 状态，丢失后正确性受损（锁全失效、限流放行超量）
> - 持久化 + 主从 + 混合 RDB 可把恢复时间与丢数据窗口都压到可接受，成本很低
> - "可以不开"的前提：确证数据 100% 可从 DB/上游重建、且有重建限速与预热机制、回源风暴可承受——三者缺一就应该开
