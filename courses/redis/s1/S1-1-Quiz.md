# 小测验 · 五大类型与底层编码

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分折算百分制，≥ 60 分过关。

### 1. zset 底层用跳表而不是红黑树，最核心的原因是？（15分）

- A. 跳表查找一定比红黑树快
- B. 范围查询（排行榜取第 N~M 名）在跳表上找到起点后顺链表顺序走即可，且实现简单、平均 O(log n) 同级
- C. 跳表省内存
- D. 红黑树不支持删除

> 答案：B
> 解析：跳表与红黑树平均复杂度同级，但范围遍历"顺带完成"、代码实现与调试成本低。A/C 均不成立（多层索引也耗内存、常数上未必更快）。

### 2. 关于渐进式 rehash，正确的描述是？（15分）

- A. 后台新开线程慢慢把旧表数据搬到新表
- B. dict 持两张表，之后每个访问 dict 的请求顺手搬一个桶（rehashidx 记进度），把 O(n) 搬迁摊进多次请求
- C. rehash 期间一次性锁表搬完再放行请求
- D. 新数据同时写入两张表

> 答案：B
> 解析：Redis 主线程单线程模型，rehash 借每次请求/定时任务推进一小步；期间查询要两张表都找，**写只写 ht[1]**（D 双写错误）。A 违背单线程前提。

### 3. 【多选】关于 Redis 编码升级，正确的有哪些？（20分）

- A. String 超过 44 字节由 embstr 转 raw，且 APPEND 后不会转回
- B. Hash 域数超 `hash-max-listpack-entries`(默认 512) 或任一值超 64B，整个 key 升级 hashtable
- C. 编码可以随数据删除自动降级回紧凑形态，节省内存
- D. listpack 取代 ziplist 的关键是每项只存自身长度，消灭了"连锁更新"

> 答案：ABD
> 解析：C 错——现代 Redis 编码**只升不降**（ziplist 时代允许的降级早已废除）。A/B/D 是三条真实的升级线与替代动机。

### 4. 判断：SDS 相比 C 字符串能 O(1) 取长度，并且二进制安全（可存含 `\0` 的内容）。（10分）

- A. 正确
- B. 错误

> 答案：A
> 解析：SDS 头部记录 len，定长不靠 `\0` 结束符，因此取长 O(1)、可存任意字节流，还带预分配减少 realloc。

### 5. 填空题：List 的编码 quicklist 是"双向链表 + 节点内 ______"的组合；Set 在全整数且元素很少时用 ______（有序整数数组）；Zset 大编码是 skiplist + ______ 双结构，后者保证按成员 O(1) 查分数。（20分）

> 答案：listpack / intset / dict

### 6. 为什么"用 Hash 存小对象"比"每个字段一个 String key"省内存？给出一条编码视角的理由与一条工程收益。（20分）

> 参考答案：
> - 编码理由：每个顶层 key 都要付出 dictEntry+SDS+过期元数据等约 60B 固定开销；小字段聚进一个 listpack 编码的 Hash 只付一次 key 开销，官方实测省一个数量级
> - 工程收益：可单字段读写（HGET/HSET）、可字段级并发更新；对比大 JSON String 改一字段要整体读写
> - 补充：注意单值超 64B 会让整个 Hash 升级 hashtable，混存大值反而亏
