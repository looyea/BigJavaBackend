# 小测验 · 多级缓存与一致性广播

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分折算百分制，≥ 60 分过关。

### 1. 在 Redis 之上再加一层 Caffeine（L1）的核心收益是？（15分）

- A. 容量更大
- B. 把最热读拦在进程内省掉网络 RTT，并给 Redis 挡热点
- C. 一致性更好
- D. 支持持久化

> 答案：B
> 解析：L1 在进程内、纳秒级、无网络往返，能分摊热 key 对 Redis 单分片的压力；代价恰恰是一致性更难（每 JVM 一份），不是更好。

### 2. 数据变更后，让所有节点的本地 L1 失效的标准做法是？（15分）

- A. 每个节点定时全量重载
- B. 变更节点删 L2 并发失效广播，各订阅节点清自己 L1 的该 key
- C. 直接清 Redis 就行，L1 会自动感知
- D. 重启所有节点

> 答案：B
> 解析：L1 各进程独立、不会自动感知 L2 变化，必须靠 Pub/Sub 或 MQ 广播"该 key 失效"，各节点收到后 invalidate 本地。A/C/D 都不现实。

### 3. 【多选】关于失效广播，正确的有？（20分）

- A. 广播"失效"比广播"新值"更简单正确（避免各节点写入顺序/旧值覆盖问题）
- B. Redis Pub/Sub 是"至多一次"，节点宕机可能漏收失效
- C. 因为可能漏广播，L1 必须配一个可容忍脏读窗口的较短 TTL 作安全阀
- D. 只要有了失效广播，L1 就可以不设过期时间

> 答案：ABC
> 解析：D 错——广播只保证"尽快一致"、不保证"必达"（Pub/Sub 会漏），TTL 才保证"迟早一致"，两者叠加缺一不可。ABC 正确。

### 4. 判断：账户余额、库存扣减终值这类强一致数据最适合放 L1 本地缓存。（10分）

- A. 正确
- B. 错误

> 答案：B
> 解析：L1 各节点独立、失效有延迟/漏广播，只能做到秒级最终一致；强一致数据不该放 L1（或只放极短 TTL），应留在能共享、较好一致的 Redis/DB 层。

### 5. 填空题：多级读链路一般是 L1(Caffeine) → ______ → DB，逐层 ______；写/失效链路遵循 Cache Aside：更新 DB → 删 ______ → 广播失效清 ______。（20分）

> 答案：L2(Redis) / 回填 / L2(Redis 缓存) / L1(本地缓存)

### 6. 某节点漏收了一次失效广播，会不会永久读到脏数据？为什么？（20分）

> 参考答案：
> - 不会永久——只要 L1 配了 expireAfterWrite/refreshAfterWrite，旧值最多存活到该条目 TTL 到期，届时回源拿到新值（自愈）
> - 所以"最坏脏读窗口 = L1 的 TTL 长度"，设计时按业务可容忍度设短（如 30s~2min）
> - 若既漏广播又不设 TTL → 才会长期脏读，这正是"广播保尽快、TTL 保必达"双保险的原因
> - 要更低丢失率：把 Pub/Sub 换成持久化 MQ 广播，或用 Canal 订阅 binlog 统一发失效
