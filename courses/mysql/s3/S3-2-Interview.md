# 实际面试题 · 主从复制、高可用与冷热备份

> 收录 2024—2026 国内中大厂 Java 后端真实面试，含追问链。考"你搭过主从吗、延迟怎么处理、误删怎么恢复"。

## 题 1：MySQL 主从复制的完整流程？

**期望时长**：90 秒

**答题要点**：

- 主库事务提交写 **binlog**；**binlog dump 线程**把事件推给从库。
- 从库 **IO 线程**接收写 **relay log**；**SQL 线程**回放 relay log 落数据。
- 监控看 `Retrieved_Gtid_Set`（已收）与 `Executed_Gtid_Set`（已回放）落差 = 延迟。

**追问链**：GTID 有什么用？→ 全局唯一事务号，搭建/切换自动定位（`AUTO_POSITION=1`），不用手算 file+position，级联/找回更安全。

## 题 2：异步、半同步、MGR 怎么选？

**答题要点**：

- **异步**：主不等从，最快，主宕可能丢"已提交未复制"事务。
- **lossless 半同步（AFTER_SYNC）**：等至少一从 ACK 收到 binlog 才返回提交成功，不丢、略慢。
- **MGR**：多数派认证才提交，自动选主，写放大大。

**追问链**：金融核心怎么选？→ **lossless 半同步 + 双一**，主库彻底损坏也不丢已提交；电商读多可异步 + 快速故障切换。

## 题 3：读写分离下用户"下单成功却查不到订单"，为什么？怎么解？

**答题要点**：

- 根因是 **主从延迟**：写主、读从，从库还没回放到那条写。
- 解法：① **读己之写**——写后短时间该会话强制走主，或带 GTID 等从库追平再读；② 支付结果页/对账等关键读直接走主；③ 缓存记最近写时间戳，落后则回源主库。

**追问链**：`Seconds_Behind_Source` 能当精确延迟吗？→ 不能，它偏 IO 侧，回放延迟要配 `pt-heartbeat`。

## 题 4：冷备/热备、逻辑/物理备份的区别？

**答题要点**：

- **冷备**停库拷文件；**热备**运行中备（InnoDB / XtraBackup）。
- **逻辑** `mysqldump` 导出 SQL：跨版本/迁移灵活、恢复慢、适合小库。
- **物理** `XtraBackup` 拷数据文件 + apply redo：大库快、需同版本。

**追问链**：大库（几百 G）你选哪个？→ 物理 XtraBackup（快），配合 binlog 做 PITR。

## 题 5：线上有人误删了一张表，怎么恢复？

**答题要点**：

- **PITR**：还原最近全量备份 → 用 `mysqlbinlog --stop-datetime` 把备份点之后的 binlog **重放到误删前一刻** → 校验后放开写。
- 前提：binlog=ROW、保留期足够、双一（保证已提交的都记全了）。
- 紧急时也可用 ROW binlog **生成反向 SQL 闪回**（呼应 s3-1）。

**追问链**：只有昨晚全量、没留 binlog 会怎样？→ 只能恢复到昨晚，白天数据全丢——这正是"备份三铁律：全量+足够 binlog、定期演练、异地留存"的意义。
