# 小测验 · 事务隔离与 MVCC

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分折算百分制，≥ 60 分过关。

### 1. MySQL InnoDB 默认的隔离级别是？（15分）

- A. 读未提交 RU
- B. 读已提交 RC
- C. 可重复读 RR
- D. 串行化 Serializable

> 答案：C
> 解析：InnoDB 默认 RR（可重复读），并通过 MVCC + next-key lock 在很大程度上解决幻读。注意 SQL 标准里 RR 是防不住幻读的，MySQL 做了增强。

### 2. RC 与 RR 行为差异的根本来源是？（15分）

- A. RR 比 RC 加了更多的锁
- B. ReadView 的生成时机不同：RC 每条 SELECT 重建，RR 只在事务首次快照读时生成一次
- C. RC 没有 undo log
- D. RR 不支持更新操作

> 答案：B
> 解析：两者快照读机制相同，唯一差别是 ReadView 生成频率。RC 每次读都拿新快照，故能看到别事务新提交（不可重复读）；RR 复用首次快照，整事务看到同一时刻的世界。

### 3. 【多选】关于 MVCC 与版本链，正确的有哪些？（20分）

- A. 每行隐藏列 `DB_TRX_ID` 记录最近修改它的事务版本
- B. `DB_ROLL_PTR` 指向 undo log 中的上一版本，多次修改串成版本链
- C. 快照读会沿版本链找到对当前 ReadView 可见的第一个版本
- D. undo log 只用于事务回滚，与多版本无关

> 答案：ABC
> 解析：D 错——undo log 一物两用：既供回滚，又供 MVCC 多版本快照读沿链回溯。A/B/C 准确描述了隐藏列 + 版本链 + 可见性查找。

### 4. 判断：在 RR 下，普通 SELECT（快照读）能防住一切幻读场景。（10分）

- A. 正确
- B. 错误

> 答案：B
> 解析：快照读靠 MVCC、当前读靠 next-key lock 各自防幻读，但**两者混用会破功**——A 快照读后 B 插入提交，A 若用当前读 UPDATE 命中新行，再快照读就会看到该行。强一致需全程当前读或串行化。

### 5. 填空题：脏读指读到别事务 ______ 的数据；不可重复读针对同一 ______ 值变化；幻读针对同一 ______ 行数变化。（20分）

> 答案：未提交 / 行 / 范围

### 6. 说明 ReadView 判断某版本是否可见的四条规则，并解释为什么"先查后改"的扣库存会更新丢失、如何修复。（20分）

> 参考答案：
> - `trx_id == create_id`（自己改的）可见；`< min_trx_id`（快照前已提交）可见；`>= max_trx_id`（快照后开启）不可见；介于其间则看是否在 m_ids——在（当时未提交）不可见，不在可见；沿版本链往旧找首个可见
> - "先查后改"：A、B 都普通 SELECT 读到旧值各自计算再写回，两次扣减只生效一次（更新丢失），MVCC 不保护这种读-改-写
> - 修复：单条原子 `UPDATE ... SET stock=stock-1 WHERE id=1 AND stock>=1`（下推判断+行锁），或先 `SELECT ... FOR UPDATE` 当前读加锁，或乐观锁 version
