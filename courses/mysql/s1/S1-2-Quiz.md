# 小测验 · B+ 树索引与执行计划

> 本卷共 6 题，混合单选 / 多选 / 判断 / 填空 / 简答，满分 100 分折算百分制，≥ 60 分过关。

### 1. InnoDB 二级索引查询需要"回表"，根本原因是？（15分）

- A. 二级索引太慢
- B. 二级索引叶子只存"索引列 + 主键"，不含整行，取其余列须回聚簇索引
- C. 聚簇索引被锁住
- D. 缓冲池太小

> 答案：B
> 解析：二级索引叶子存的是索引列值加主键，命中后拿到主键，再回聚簇索引取整行，即"回表"。若查询列全在索引里则覆盖索引免回表。

### 2. 下列哪条 SQL 最可能让 `idx(create_time)` 失效？（15分）

- A. `WHERE create_time >= '2026-01-01'`
- B. `WHERE create_time BETWEEN '2026-01-01' AND '2026-01-02'`
- C. `WHERE DATE(create_time) = '2026-01-01'`
- D. `WHERE create_time < '2026-06-01'`

> 答案：C
> 解析：在索引列上套函数 `DATE(...)` 破坏了 B+ 树的有序比较，索引失效；应改写成区间 `>= 当天 AND < 次日`。A/B/D 都是对裸列的范围条件，能走索引。

### 3. 【多选】关于联合索引 `idx(a,b,c)` 与最左前缀，正确的有哪些？（20分）

- A. `WHERE a=? AND b=?` 能用上最左两列
- B. `WHERE b=? AND c=?` 因缺最左列 a，通常用不上该索引
- C. 范围条件列之后的索引列无法再用于有序查找，故等值列应放前、范围列放最后
- D. 只要建了 `idx(a,b,c)`，单独 `WHERE c=?` 一定能高效走索引

> 答案：ABC
> 解析：D 错——最左前缀要求从 a 开始的连续列，单查 c 不满足（除 MySQL 8 skip scan 等特例，不可依赖）。A/B/C 是最左前缀与列序的正确结论。

### 4. 判断：主键用无序 UUID 比自增 BIGINT 更利于 InnoDB 插入性能。（10分）

- A. 正确
- B. 错误

> 答案：B
> 解析：随机 UUID 主键插入落在 B+ 树任意位置，频繁触发页分裂、写放大与碎片；自增/趋势递增（如雪花 ID）顺序追加，插入更高效，且主键越短二级索引越省空间。

### 5. 填空题：`EXPLAIN` 中 ______ 字段为 NULL 表示没走索引；`Extra` 出现 ______ 表示查询列全在索引内、无需回表；出现 ______ 表示需额外排序。（20分）

> 答案：key / Using index / Using filesort

### 6. 解释聚簇索引与二级索引的区别，说明回表与覆盖索引，并给出“主键要短且递增”的两条理由。（20分）

> 参考答案：
> - 聚簇索引叶子存整行、表即按主键组织的 B+ 树；二级索引叶子存"索引列 + 主键"
> - 回表：二级索引定位主键后回聚簇索引取整行，两次树查找；覆盖索引：查询列全在二级索引内，直接返回、省回表 I/O
> - 主键要短：每个二级索引叶子都冗余存主键，主键越长索引越臃肿
> - 主键要递增：随机主键插入导致页分裂、写放大、碎片；顺序追加更高效
