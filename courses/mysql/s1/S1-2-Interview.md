# 实际面试题 · B+ 树索引与执行计划

> 收录 2024—2026 国内中大厂 Java 后端真实面试，含追问链。索引是数据库面试的"必考区"，答要落到 B+ 树结构与 EXPLAIN 证据。

## 题 1：InnoDB 为什么用 B+ 树而不是哈希 / B 树 / 二叉树？

**期望时长**：90 秒

**答题要点**：

- B+ 树**非叶子只存键 + 指针**（更矮胖、一页放更多分支），3~4 层撑千万行，磁盘 I/O 少。
- **叶子双向链表** → 范围查询/排序顺链表扫，不用回根。
- 哈希等值快但**不支持范围与排序**；二叉/红黑太高、I/O 多；B 树非叶子也存数据 → 没 B+ 矮。

**追问链**：主键随机（UUID）插入有什么问题？→ 落点随机导致**页分裂**、写放大、碎片；故主键宜短且**趋势递增**（雪花 ID）。

## 题 2：什么是回表？怎么避免？

**答题要点**：

- 二级索引叶子只存"索引列 + 主键"，命中后须拿主键**回聚簇索引取整行** = 回表，两次树查找。
- 避免：**覆盖索引**——让 `SELECT` 的列全部包含在二级索引里，`Extra` 显示 `Using index` 即免回表。

**追问链**：为什么不直接推荐 `SELECT *`？→ `SELECT *` 取所有列，几乎必然回表；列越多覆盖索引越难命中。

## 题 3：联合索引 `(a,b,c)`，`WHERE a=? AND c=?` 能用上吗？

**答题要点**：

- 走**最左连续前缀**：能用上 a 列定位，但中间的 b 缺失，c **无法作为有序查找条件**（顶多 ICP 在索引里过滤，扫的行仍多）。
- 列序原则：**等值列放前、范围列放最后**（范围列之后的列不再有序）。

**追问链**：`WHERE b=? AND a=?` 呢？→ 优化器会重排条件顺序，只要覆盖最左列集合（a、b）就能用上前两列。

## 题 4：建了索引却不走，列举原因。

**答题要点**：

- 索引列上做**运算**、被**函数包裹**（`DATE(col)`）。
- **隐式类型转换**（列 BIGINT 传字符串）——相当于对列套函数。
- **前导 `%` 的 LIKE**、`!=`/`NOT IN` 选择性差、`OR` 连非索引列。
- 缺最左列；或优化器估算走索引不如全表扫（回表太多）。

**追问链**：怎么确认？→ `EXPLAIN` 看 `key=NULL`、`type=ALL`；改写法后复测。别盲目加索引。

## 题 5：EXPLAIN 你重点看哪几个字段？

**答题要点**：

- `type`：`ALL`（全表）/`index`（扫全索引）是红线，争取 `ref`/`range` 及以上。
- `key`：实际用的索引，NULL = 没走。
- `rows`：预估扫描行数，虚高 = 白扫。
- `Extra`：`Using filesort`/`Using temporary` 是慢因；`Using index`（覆盖，好）、`Using index condition`（ICP，好）。

**追问链**：`Using filesort` 一定慢吗？→ 结果集小、能在排序缓冲区完成就还好；大结果集落盘排序才致命，尤其深分页（见 s3-3）。
