# JMM、happens-before 与三大特性 · 面试追问

> JMM 是并发面试的"地基题"，几乎必问且能探出深浅。高分答法：不背概念，而是用"happens-before 是判定同步与否的因果律"这条主线，把 volatile/锁/重排串起来。

## 题 1：为什么要学 JMM？它到底解决了什么问题？

**期望时长**：2 分钟

**答题要点**：

- 现代硬件多级缓存 + 乱序执行 + 编译器重排，使"代码顺序 ≠ 执行顺序 ≠ 他线程观察顺序"。
- JMM 是一份跨平台内存访问契约：规定哪些重排合法、共享变量何时可见，给并发程序一个可推理的语义。
- 用 happens-before 统一"可见性 + 有序性"判定。

**追问链**：JMM 和"主内存/工作内存"抽象有关吗？→ 那是描述模型（线程有私有工作内存），本质在讲"没有同步就看不到别人的写"。

## 题 2：说说 happens-before，能举几条规则吗？

**答题要点**：A hb B ⇒ A 结果对 B 可见且排在 B 前。规则：程序顺序、监视器锁（unlock hb 后续 lock）、volatile（写 hb 后续读）、thread start、thread join 终止、传递性。

**追问链**：怎么用工程判断？→ 找两个相关操作能否用上述规则连成 hb 链；连不上就是数据竞争，需要加 volatile/锁/并发容器闭合。

## 题 3：volatile 能保证原子性吗？为什么 `i++` 用了 volatile 还错？

**答题要点**：volatile 只保证可见性 + 有序性（单次读/写各自原子），不保证复合操作原子。`i++`=读-改-写三步，两个线程可能都读到同值各自 +1 → 丢更新。要原子得用 synchronized 或 Atomic*（CAS）。

**追问链**：那 volatile 适合啥？→ 状态标志位、一次性安全发布（配合 hb）、DCL 禁重排；"读多写少且写不依赖旧值"。

## 题 4：i++ 丢更新是哪种特性问题？怎么修？

**答题要点**：原子性问题。修法：`synchronized`、`AtomicInteger.incrementAndGet()`（CAS）、高并发计数用 `LongAdder`（分段累加减少 CAS 冲突）。

**追问链**：LongAdder 为什么比 AtomicInteger 快？→ 高竞争时把热点拆到多个 Cell 分散 CAS 失败、sum 时汇总，以空间换吞吐（详见 s1-2）。

## 题 5：DCL 单例为什么必须加 volatile？

**答题要点**：`instance = new Instance()` 三步（分配/初始化/赋引用）中后两步可能被重排；不加 volatile，另一线程在锁外判非 null 后可能拿到"未初始化完成"的对象。volatile 禁该重排并保证可见。

**追问链**：两次 null 判各干什么？→ 锁外判为性能（已创建就不进锁）、锁内判为正确性（进锁后再确认只创建一次）。

## 高频速答

- 三大特性？→ 原子性、可见性、有序性。
- 数据竞争定义？→ 无 happens-before 关系的并发读写（至少一个是写）。
- volatile 底层？→ 内存屏障 + 缓存一致性（MESI），建立写→读 hb。
- final 可见性前提？→ 构造内不外泄 this（安全发布）。
- 忙等不退出根因？→ 缺可见性（无 hb），加 volatile 修。
