# Feed 流推拉结合与热 Key · 作业

### 作业 1：推拉结合的发布分发

- 目标：小 V 写扩散、大 V 走拉，发布不被百万粉拖垮。
- 任务：实现 `publish`——作者粉丝数低于阈值则投 MQ 异步分批写扩散(幂等)，超阈值只落作者时间线待拉；实现 `read`——把用户收件箱(推来的)与其关注的大 V 时间线(拉来的)按时间戳归并去重。构造一个百万粉大 V 发布，观察其不触发全量扩散。
- 验收标准：大 V 发布低延迟、不写爆收件箱；小 V 读能直接命中收件箱；重投扩散不产生重复条目。
- 参考解法要点：扩散异步 + 幂等 + 分批；阈值按粉丝量级设定；归并要处理时间戳乱序。

### 作业 2：ZSet 收件箱 + 稳定游标分页

- 目标：做到翻页期间有增删也不重复、不漏项。
- 任务：用 Redis ZSet(member=postId,score=时间戳)存近期收件箱，按 score 区间倒序取一页；游标用"最后一条时间戳 + postId"；实现内容撤回时从各收件箱 `ZREM` 清引用。模拟"翻页中途来了新帖/删了一帖"。
- 验收标准：连续翻页无重复无漏项；撤回后不再返回死链；收件箱裁剪只留近期 N 条。
- 参考解法要点：稳定排序键防 offset 漂移；冷数据回源重建；撤回同步清理。

### 作业 3：热 Key 打散与本地缓存兜底

- 目标：让爆款 Feed 不把单分片读爆。
- 任务：对识别出的热点 key 复制 N 份加随机后缀、读时随机选一份(打散摊薄)；叠加应用进程本地缓存(极短 TTL)挡重复读；实现"热点探测 → 自动打散/降级"的开关。压测同一热 key 高并发读，对比打散前后单分片 QPS。
- 验收标准：打散后单分片压力显著下降、无局部雪崩；本地缓存命中降低回源；探测到热点能自动开启打散。
- 参考解法要点：TTL 要短防不一致、可配合主动失效；打散份数与一致性权衡；与缓存击穿防护协同。
