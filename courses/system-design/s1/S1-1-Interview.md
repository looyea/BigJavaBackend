# 系统设计答题框架 · 实际面试题

## 题 1：给我一个万能的结构化答题框架，能应对几乎所有系统设计题。

**考察点**：这题本身就是"元问题"——考你有没有把开放问题工程化的方法论。

**参考答案**：我用七段骨架，配时间盒（40 分钟版）：**① 澄清需求（3~5min）** 把开放题收敛成 functional/非功能/规模三组明确约束，并主动给假设请面试官确认（"我按 DAU 1 亿、读写 100:1 做，对吗？"）；**② 顶层估算（3~5min）** QPS/存储/带宽数量级，用来倒推"要不要缓存/分片/CDN"——让每个组件都有存在理由；**③ API 设计（2~3min）** 定核心读写接口和数据契约，暴露系统边界；**④ 数据模型（3~5min）** 关键实体、存储选型、索引与分片键雏形；**⑤ 高层架构（5~8min）** 一张从客户端到持久化、数据流走通的图；**⑥ 深挖组件（8~10min）** 主动请命挑 1~2 个高区分度点（热点、一致性、分片、削峰）钻到底；**⑦ 权衡收尾（3~5min）** 谈瓶颈/单点/失败恢复，并回答"量翻 10 倍怎么演进"。核心节奏是**先广度求链路通、再深度显纵深、全程讲 trade-off、结尾给演进**。

**追问**：
- 时间不够怎么办？——七段是骨架不是教条，砍⑥深挖数量、压缩③④到口头带过，但①②⑦绝不能省（澄清、估算、权衡是评分关键）。
- 为什么把估算放在架构前面？——因为架构组件要由估算倒推，先画架构再编理由是"背题"特征。

**加分点**：点出"系统设计面试是对话不是报告"——边讲边读面试官信号动态调整，比一口气背完更能体现协作式工程能力。

## 题 2：面试官全程不怎么说话，你怎么知道自己做得好不好？

**考察点**：主导性与自我校验能力，而不是等喂题。

**参考答案**：面试官沉默通常有两种：链路在推进他不想打断，或者你有断点他在观察你会不会自己发现。我会**主动制造检查点**而不是闷头画：每完成一段就用一句话收口并向外确认——"高层数据流到这就闭环了，我打算接着深挖热点 key，您觉得这个方向值得展开吗？"。这样把沉默转成对话。同时自查三条挂科红线：① 我有没有一上来就画（缺澄清/估算）；② 我有没有只报组件不给取舍；③ 我的图是不是静态的、没谈单点和失败。如果面试官突然给新约束（"现在要支持多地域"），那不是推翻重来，是在考演进能力——我会在数据/部署层面增量响应，展示系统的可生长性。

**追问**：
- 面试官问"这里能多说点吗"是什么信号？——命中高区分度考点，是深挖加分的黄金机会，要往下钻到算法/存储结构级别，别停在"加个缓存"。
- 你猜错了面试官想深挖的点怎么办？——先讲一句概括再问"您更关心可用性还是成本？"，快速校准，不硬撑。

**加分点**：主动承认"我不知道你的侧重，所以先给假设再请你打断"——这种透明化假设 + 邀请纠偏的姿态，正是 senior 候选人和背题候选人的分水岭。

## 题 3：同样是"设计一个短链系统"，怎么答才能和别的候选人拉开差距？

**考察点**：能不能把框架用到深处，而不只是复述骨架。

**参考答案**：大多数人能画出"生成短码→存 KV→301/302 跳转"，拉差距要靠框架里的②估算和⑥深挖。先用估算定调：读写比若 100:1，就明确"这是读密集系统，成败在缓存与分片，不在生成算法"；量级若日增 1 亿条、留 3 年就是几十 TB，逼出哈希分片和冷热分离。然后挑一个真正有纵深的点钻到底——比如**热点 key**：某个链接被疯狂点击会打爆单个分片，解法是本地缓存 + 多副本读 + 热点探测自动加盐扩散；再比如**短码生成**：自增 ID + base62 编码能保证短且无冲突但需集中发号（接 Leaf/号段），哈希去重有碰撞要处理。最后收尾给演进：从单库到分片、从同步写统计到异步 MQ。拉开差距的本质是——**别人给一张图，你给一条"估算→取舍→纵深→演进"的论证链**。

**追问**：
- 301 还是 302？——301 永久重定向可被浏览器/CDN 缓存、省一跳但拿不到点击统计；302 临时每次回源、便于统计和改向。按需求（要不要统计）选，这本身就是"讲取舍"。
- 要不要上数据库自增主键？——集中式自增是写瓶颈和单点，高并发写用号段/Leaf 或 UUID+分片，取决于估算。

**加分点**：主动说出"我不用把每个组件都讲到实现级，挑一个证明我钻得下去就行"——展示的是对框架的驾驭和取舍判断，比面面俱到更显资深。
