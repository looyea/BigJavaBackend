# 秒杀 / 短链 / Feed 流 · 小测验

> 全卷 100 分：单选 5×10 + 多选 2×10 + 判断 1×5 + 简答 15+10。达到 60 分解锁下一节。

### 1. 秒杀防超卖的关键是库存扣减必须（10分）

- A. 先 get 判断再 decr（两步分开）
- B. 原子执行（Redis Lua / 单线程），把"判断+扣减"合成不可分割操作
- C. 用普通 SELECT 加应用层 if
- D. 交给前端计数

> 答案：B
> 解析：get 再 decr 会被并发撕裂导致超卖；Lua 保证判断与扣减原子。反例：直接 `update ... set n=n-1 where n>0` 顶洪峰 → 行锁排队、连接池耗尽雪崩。

### 2. 秒杀链路里"Redis 扣减 + MQ 异步落库"的主要目的是（10分）

- A. 让数据库扛瞬时写洪峰
- B. Redis 抗读抗扣减、MQ 把瞬时写摊平成 DB 平稳消费，落库慢不阻塞用户"抢购成功"感知
- C. 保证强一致事务
- D. 省去幂等

> 答案：B
> 解析：这是最终一致换吞吐——秒杀落库慢不影响用户体验，MQ 削峰保护 DB（接 dist-theory）。

### 3. 短链生成方案里，工程上最平衡的是（10分）

- A. MD5 取前 6 位直接返回
- B. 随机生成 + 每次查重试
- C. 中心发号器自增 ID + base62 编码
- D. 用 UUID 截断

> 答案：C
> 解析：发号器天然唯一无冲突、码短长度可预估；MD5 有碰撞、随机查重高冲突时重试风暴写放大。

### 4. 短链跳转要用 302 而非 301 的典型原因是（10分）

- A. 302 更省带宽
- B. 需要统计点击次数 / 动态改向，302 每次回源便于埋点
- C. 301 不能跳转
- D. 302 会被浏览器永久缓存

> 答案：B
> 解析：301 永久重定向被缓存、省一跳但统计不到访问也无法改向；要统计用 302（可 +异步写点击日志）。

### 5. Feed 流"推拉结合"解决的核心矛盾是（10分）

- A. 缓存与数据库一致性
- B. 纯 push 大 V 写放大、纯 pull 读时归并爆炸——按粉丝数量级分治两头都砍
- C. 长短链转换
- D. ID 唯一性

> 答案：B
> 解析：普通人发→推（粉丝少写得起），大 V 发→只存自己时间线供拉取归并；用粉丝数量级决定推拉（分层分治思想）。

### 6. 秒杀入口层常用的削峰/防护手段，正确的有（多选）（10分）

- A. 网关/IP/用户维度限流（令牌桶，超阈值 429 或排队页）
- B. 页面静态化 + 答题/验证码削掉脚本与无效请求
- C. 库存预热到 Redis + "售罄"标记，售罄直接本地拦不再打下游
- D. 让所有请求直达 MySQL 扣减以保证强一致

> 答案：A、B、C
> 解析：D 与漏斗思想相反——直达 DB 顶洪峰会行锁排队、连接池耗尽、雪崩，正是秒杀要避免的。

### 7. 关于 Feed 流读扩散与写扩散，下列说法正确的有（多选）（10分）

- A. 读扩散（pull）发时不分发、看时实时归并 N 路时间线，省写但大 V 多则读慢
- B. 写扩散（push）发时写进所有粉丝收件箱，读极快但大 V 一条要写百万收件箱 = 写放大
- C. 时间线增量拉取用 (maxId/时间戳+id) 游标，避免 offset 深分页
- D. 写扩散永远不会造成洪峰

> 答案：A、B、C
> 解析：D 错——写扩散在大 V 发帖瞬间正是写洪峰来源；深分页坑接 mybatis offset 问题。

### 8. 判断："秒杀系统设计里，三道题都需要强一致性来保证不超卖/不丢链接。"（5分）

- A. 正确
- B. 错误

> 答案：B
> 解析：秒杀/短链/Feed 都不需要强一致，用"最终一致 + 幂等 + 状态机"换吞吐；超卖靠原子扣减 + 预扣/回补状态机而非分布式强一致事务。

### 9. 简答题：完整讲一遍秒杀请求从入口到落库的漏斗链路，并说明每一层拦掉了什么。（15分）

> 参考答案：
> - 入口限流：网关/IP/用户令牌桶，超阈值 429/排队，拦掉超额并发
> - 削无效流量：页面静态化 + 答题/验证码，挡掉机器脚本与无效点击
> - 售罄本地拦：库存预热到 Redis + 售罄标记，库存=0 直接本地返回，不再打下游
> - 原子扣减：Redis Lua 把判断+扣减合一，防并发超卖
> - 异步落库：扣减成功发 MQ，DB 按平稳速度消费落库（削写峰，最终一致）
> - 幂等防刷：reqId 幂等键去重、一人一单、热点 sku 本地缓存挡读
> - 加分点：补"预扣→支付确认→回补"状态机解决扣了没买的库存回补

### 10. 简答题：短链系统为什么读多写少？据此给出存储与跳转层的三个设计决策。（10分）

> 参考答案：
> - 一条短链生成后被点击成千上万次，写一次读多次 → 读写比极端偏读
> - 存储：按短码哈希分片 KV/HBase，热点链上 Redis 缓存挡读
> - 跳转：先查缓存、未命中回源 KV，减少存储压力；配合 CDN/多级缓存
> - 生成：中心发号 + base62 保证唯一且短，避免哈希碰撞/随机重试
> - 加分点：301/302 按"要不要统计点击/改向"选择，统计就用 302
