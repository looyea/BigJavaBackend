# 限流器 / 排行榜 / 附近的人 · 小测验

> 全卷 100 分：单选 5×10 + 多选 2×10 + 判断 1×5 + 简答 15+10。达到 60 分解锁下一节。

### 1. 四种限流算法中，允许有限突发且最常用的是（10分）

- A. 计数窗口
- B. 漏桶
- C. 令牌桶
- D. 滑动日志

> 答案：C
> 解析：令牌桶攒令牌 → 允许桶容量以内的突发；漏桶恒定速率输出不允许任何突发；计数窗口有边界 2 倍突发问题。

### 2. Redis ZSet 做排行榜更新分数时，"同一个 member 再次写入"的行为是（10分）

- A. 报错 key 冲突
- B. 覆盖旧 score，原子更新，无需先删后加
- C. 插入一条新记录
- D. 追加到队尾

> 答案：B
> 解析：ZADD 对同 member 覆盖旧分，天然适合排行榜写入洪峰；若需"增量"用 ZINCRBY 保原子。

### 3. "附近的人"用 GeoHash 的核心价值是（10分）

- A. 加密经纬度
- B. 把 2D 坐标降维成 1D 可排序编码，前缀相同=地理相近，实现快速分桶
- C. 精确计算距离
- D. 压缩存储

> 答案：B
> 解析：暴力算距离 O(N) 不可行，GeoHash 降维让"谁在附近"变成字符串前缀匹配 + 候选集精算。

### 4. GeoHash 分桶查询的"边界问题"是（10分）

- A. GeoHash 字符串太长查不到
- B. 分桶是矩形，目标在桶边缘时真实圆跨相邻桶，只查当前桶会漏
- C. Redis 不支持 GEO
- D. 精度不够因为位数太少

> 答案：B
> 解析：正解取中心桶 + 相邻 8 桶（九宫格）候选集再精算；Redis GEORADIUS 帮你封装了这步。

### 5. 分布式限流"Redis 挂了"最安全的降级是（10分）

- A. 直接放行全部请求
- B. 快速失败（限死）或退化为本地限流（阈值缩到约 1/N）
- C. 重启 Redis 期间不处理请求
- D. 改成漏桶

> 答案：B
> 解析：宁可限死不可放穿——后端在 Redis 失联期间最脆弱，必须保守；本地限流兜底但阈值要缩。

### 6. 排行榜"同分排序"的常用解法，正确的有（多选）（10分）

- A. ZSet 默认 score 相同按 member 字典序（lex）排序
- B. 把 score 编码成"分值 + (大数 - 首次到达时间戳)"使先到者排前
- C. 用双排序字段（主分 + 时间副键）
- D. 只能让 DB 重排

> 答案：A、B、C
> 解析：D 错——排行榜选 ZSet 就是为了在 Redis 侧 O(logN) 搞定，不必回 DB；编码 score 是主流技巧。

### 7. 限流与"排队"的区别，正确的有（多选）（10分）

- A. 限流=超阈值直接拒绝(429)，适合 API 保护
- B. 排队=超阈值等待(不丢请求)，适合秒杀排队页
- C. 两者场景不同，算法选型也不同
- D. 限流就是排队只是换了个说法

> 答案：A、B、C
> 解析：D 错——限流拒、排队等，本质不同；秒杀用排队不丢用户、API 网关用快速 429 保后端。

### 8. 判断："附近的人用 Redis GEO 方案，活跃点规模到百亿级仍是最优选择。"（5分）

- A. 正确
- B. 错误

> 答案：B
> 解析：Redis GEO 全内存 ZSet，适合几千万级活跃点；百亿级冷数据应用 PostGIS/ES Geo/H3 做持久化空间索引。

### 9. 简答题：令牌桶为什么用"惰性计算"而不是真起线程放令牌？给出核心公式和两个好处。（15分）

> 参考答案：
> - 核心公式：tokens = min(capacity, tokens + elapsed × rate)，elapsed = 当前时间 - 上次请求时间
> - 好处一 无后台线程/定时器：省去线程调度开销与定时器精度问题（Java Timer 高并发会飘）
> - 好处二 无空跑浪费：没有请求就不补令牌，不耗 CPU 也不打 Redis
> - 好处三 实现极简：每次请求只做一次算术判断，延迟确定
> - 加分点：指出"1ms 定时器往 Redis 塞令牌"在高并发下精度+写压力双杀

### 10. 简答题：Redis ZSet 排行榜的"日榜过期清理"怎么做？为什么不能用一个 key 存全部历史？（10分）

> 参考答案：
> - 日榜按日拆 key（rank:daily:20260927），用 Redis EXPIRE 设 TTL 自动清理过期日榜
> - 一个 key 存全部历史：内存无限膨胀 + 无法按日查 + 热 key 单分片打满
> - 周榜/月榜/总榜：可定时从日榜聚合生成（异步离线 or 懒生成），避免实时归并成本
> - 加分点：大排名分页用 zrevrank 取位置再二次 zrevrange 取前后若干名，避免 offset 深分页
