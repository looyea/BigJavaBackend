# 小测验：API 网关 / Web 爬虫 / 支付对账系统

### 1. API 网关的核心职责不包括以下哪项？（10分）
- A. 路由转发与协议转换
- B. 业务逻辑编排
- C. 统一认证鉴权
- D. 限流与熔断
> 答案：B
> 解析：网关做流量管控与通用横切关注点（认证、限流、日志），业务逻辑编排属于应用服务层职责。

### 2. 爬虫系统中用布隆过滤器做 URL 去重的关键限制是？（10分）
- A. 查询速度慢
- B. 不支持删除元素
- C. 无法处理 URL 超过 255 字符
- D. 必须依赖数据库
> 答案：B
> 解析：布隆过滤器只支持添加和查询，不支持删除。一旦 URL 加入，永远判"可能存在"。

### 3. 支付对账中"我方有、渠道无"的异常通常意味着？（10分）
- A. 重复扣款
- B. 掉单（渠道未入账或回调未到）
- C. 金额篡改
- D. 正常无需处理
> 答案：B
> 解析：我方流水有记录但渠道账单无对应交易，说明支付可能未完成或回调丢失，需要主动查单确认。

### 4. 以下哪些属于 API 网关限流的正确实践？（多选，10分）
- A. 使用 Redis + Lua 实现分布式计数器
- B. 按用户 ID 维度限流防止单用户刷接口
- C. 限流阈值配置在代码硬编码中
- D. 全局限流防止后端集群过载
> 答案：A、B、D
> 解析：限流阈值应配置化（Nacos/Apollo 动态推送），不应硬编码。

### 5. 分布式爬虫中 Master-Worker 架构的 Master 节点主要职责是？（10分）
- A. 实际下载网页
- B. HTML 解析
- C. URL 调度与任务分发
- D. 存储抓取结果
> 答案：C
> 解析：Master 负责种子管理、URL 去重、优先级排序与向 Worker 分发任务；Worker 做实际下载。

### 6. 关于对账系统，以下说法正确的有？（多选，10分）
- A. 对账需要双向核对：正向（我方→渠道）和反向（渠道→我方）
- B. 对账任务设计应支持幂等可重跑
- C. 金额比对应使用 == 精确匹配浮点数
- D. 跨日交易需统一时区后比对
> 答案：A、B、D
> 解析：C 错误——浮点数比较应用差值 < 阈值（如 0.01），不能用 == 直接比较。

### 7. Spring Cloud Gateway 中 StripPrefix=1 过滤器的作用是？（10分）
- A. 添加一级路径前缀
- B. 去掉路径的第一段再转发给后端
- C. 记录访问日志
- D. 校验 JWT Token
> 答案：B
> 解析：StripPrefix=1 去掉路径第一段（如 /api/order → /order），让后端服务不必感知网关前缀。

### 8. 判断："爬虫的 robots.txt 仅用于提高抓取效率，不遵守也不会违规。"（5分）
- A. 正确
- B. 错误
> 答案：B
> 解析：robots.txt 是网站对爬虫的访问规则声明，不遵守可能违反服务条款或法律法规（如 GDPR）。

### 9. 简答题：设计 API 网关的灰度发布功能，说明路由规则与流量切分策略。（15分）
> 参考答案：
> - 路由规则：按 Header/Cookie/用户ID 取模匹配灰度标签，命中则转发到灰度服务实例组
> - 流量比例：配置化权重（如 5%→20%→50%→100%），网关层按权重随机分流
> - 回滚机制：异常比例超阈值自动 100% 回切稳定版，秒级生效无需重启
> - 可观测：灰度标记透传到链路追踪，监控面板按灰度/稳定分组对比 RT 和错误率

### 10. 简答题：支付对账发现差异后如何处理？给出差错分类与对应修复策略。（10分）
> 参考答案：
> - 掉单（我方有渠道无）：调用渠道查单接口二次确认，已支付则补单；未支付则关闭
> - 漏单（渠道有我方无）：核实是否本地写库失败，确认后补入账并触发业务回调
> - 金额不一致：生成差错工单，冻结相关资金，财务人工复核后手动调整
> - 重复扣款：发起自动退款流程，同时记录资损事件上报风控
