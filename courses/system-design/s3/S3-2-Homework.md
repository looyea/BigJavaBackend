# 课后作业：API 网关 / Web 爬虫 / 支付对账系统

## 作业 1：设计高可用 API 网关方案（35分）

场景：日均 1 亿请求的电商平台，有 50+ 微服务，要求网关 SLA 99.99%。

要求：
1. 画出网关架构部署图（含 LB、网关集群、配置中心、Redis 限流集群），标注每层的高可用策略。
2. 设计一套 JWT 鉴权过滤器：校验签名 → 检查黑名单 → 解析用户信息透传到下游 Header。写伪代码。
3. 限流规则：按 API 维度 + 用户维度双层限流，突发流量 5 倍于平均 QPS，选型令牌桶还是滑动窗口？说明理由。
4. 灰度发布：设计基于 Header 标签的路由规则，实现 5% → 20% → 100% 渐进式放量，异常时秒级回滚。

## 作业 2：设计十亿级 Web 爬虫系统（30分）

场景：新闻聚合平台，目标每日增量抓取 1 亿个页面，去重后入库约 3000 万新 URL。

要求：
1. 设计 URL 去重方案：估算布隆过滤器参数（预期元素数、误判率、所需内存），说明为什么不用 HashSet。
2. 画出"种子 → 调度 → 下载 → 解析 → 存储 → 新 URL 回注"的完整数据流，标注反爬对抗环节（代理池、UA 轮换、Cookie 管理）。
3. 设计 robots.txt 合规策略和 Crawl-delay 频率控制方案。
4. 扩展性：Worker 宕机后任务如何自动重新分发？写出故障检测与任务迁移方案。

## 作业 3：设计金融级支付对账系统（35分）

场景：第三方支付公司，日均交易 5000 万笔，对接 10+ 渠道（微信/支付宝/银联/各银行），T+1 对账。

要求：
1. 设计对账数据模型：我方流水表、渠道账单表、对账结果表的字段与联合索引。
2. 写出双向核对的完整 SQL（FULL OUTER JOIN），覆盖三种差错：掉单、漏单、金额不一致。
3. 差错处理 SOP：自动修复（掉单查单补单）与人工工单（大额差错）的流转规则，画出状态机。
4. 幂等设计：对账任务失败后重跑不重复入账，写出你的幂等方案（联合唯一键 + INSERT ON DUPLICATE UPDATE）。
5. 资损防控：如何实时监控"当日差错率"与"累计未修复金额"？给出告警阈值与熔断策略。
