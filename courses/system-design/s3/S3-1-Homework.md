# 课后作业：分布式消息 / 缓存 / ID 生成器设计

## 作业 1：设计高可靠消息链路（30分）

场景：电商平台订单系统需要"下单成功后异步发短信 + 扣库存 + 记日志"。

要求：
1. 画出 Producer → Broker → Consumer 完整链路，标注每一步防止消息丢失的配置参数。
2. 如果消费端处理"扣库存"成功但"记日志"失败，如何保证幂等？写出你的去重方案。
3. 当 Broker 集群中某台机器宕机时，ISR 机制如何保证消息不丢？说明 Leader 选举流程。

## 作业 2：缓存一致性方案设计（35分）

场景：金融交易系统，账户余额数据，峰值 QPS 10 万，要求读到最新值概率 ≥ 99.99%。

要求：
1. 选择一致性策略（Cache Aside / Write Through / 延迟双删），说明选择理由。
2. 设计防止缓存穿透、击穿、雪崩的具体方案，每种给出实现要点。
3. 写出"先更新 DB 后删缓存"失败后的补偿机制：如何用 Canal 监听 binlog 做最终一致性保障。

## 作业 3：ID 生成器方案选型与实现（35分）

场景：分布式电商平台，日均订单 5000 万，要求 ID 趋势递增、不依赖单点。

要求：
1. 对比 UUID / 数据库自增 / 号段模式 / Snowflake 四种方案，给出选型结论与理由。
2. 若选 Snowflake：计算 41 位时间戳能支撑多少年？10 位机器 ID 如何分配？时钟回拨 ≤5ms 怎么处理？
3. 若选号段模式：画出双 Buffer 预加载的时序图，说明如何避免取号段时的毛刺。
4. 编程：用 Java 实现一个简化版 Snowflake（含时钟回拨保护），单元测试验证同一毫秒内不重复。
