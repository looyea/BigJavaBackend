# 热点参数限流、集群限流与规则持久化（关联） · 小测

> 本卷满分 100 分：单选 7×6=42，多选 2×9=18，简答 1×40=40。

### 1. 热点参数限流（`ParamFlowRule`）与接口级限流的区别是（6分）

- A. 没区别
- B. 前者按某个"参数值"单独统计限流，后者对整个接口总量限流
- C. 后者能防爆款
- D. 前者只能限 URL

> 答案：B
> 解析：热点参数按参数值（如 itemId）粒度限流，才能挡住"单个 SKU 打爆链路"。

### 2. 秒杀爆款场景，正确的限流做法是（6分）

- A. 只配接口总阈值
- B. 热点参数设大盘阈值 + 给爆款 SKU 配例外项单独控制
- C. 不限流
- D. 关掉集群

> 答案：B
> 解析：`paramFlowItemList` 为特定值设例外，爆款单独放宽/收紧，避免与正常商品共用大盘阈值互相误伤。

### 3. 多实例部署只配"单机限流 100"，全局实际放行约（6分）

- A. 100
- B. N×100（各限各的，总量失真）
- C. 100/N
- D. 0

> 答案：B
> 解析：每台独立计数，N 台就放到 N×100，需要集群限流才能得到全局统一阈值。

### 4. 集群限流中统一发放令牌的组件是（6分）

- A. Dashboard
- B. Token Server
- C. Nacos
- D. Gateway

> 答案：B
> 解析：各实例作为 Token Client 向 Token Server 申请令牌，实现全局视角限流。

### 5. 集群限流的"退化（degrade）"指的是（6分）

- A. 降低阈值
- B. Token Server 不可用/通信失败时自动退化为本地限流
- C. 关闭限流
- D. 熔断下游

> 答案：B
> 解析：牺牲全局精度换可用性——TC 挂了这个点仍能本地限流，不至于"全不限"或"全限死"。

### 6. Sentinel 默认规则存内存的最大问题是（6分）

- A. 太占内存
- B. 控制台改完重启即丢、无法程序化批量下发
- C. 不支持限流
- D. 只能存 Nacos

> 答案：B
> 解析：内存态规则不持久、不可动态下发，生产要接外部数据源。

### 7. 生产环境推荐 Sentinel 规则接（6分）

- A. 只存控制台
- B. `NacosDataSource` 等外部数据源做动态规则源 + 本地快照兜底
- C. 写死代码
- D. 不需要规则

> 答案：B
> 解析：外部数据源做到"改规则实时生效、重启不丢"，本地快照防拉取失败裸奔。

### 8.（多选）以下哪些是限流生产化必须处理的？（9分）

- A. 多实例总量失真 → 集群限流或按实例数折算阈值
- B. 爆款参数值 → 热点参数例外项
- C. 规则易丢 → 外部数据源 + 兜底快照
- D. Token Server → 配退化策略

> 答案：A、B、C、D
> 解析：四项都是把"玩具级限流"变"生产级限流"的关键动作。

### 9.（多选）关于集群限流 Token Server，正确的有（9分）

- A. 可嵌入某业务节点，也可独立部署
- B. TC 不可用时若没配退化，可能全站不限流或全限死
- C. TC 是限流的统一令牌发放点
- D. TC 挂了完全不影响任何限流

> 答案：A、B、C
> 解析：D 错——正因 TC 影响全局，才必须配退化避免它成为单点。

### 10. 电商大促"某爆款 SKU 秒杀"会把查询接口整体打挂，且你们是 20 实例部署、规则靠控制台手配。请给出 Sentinel 三块能力的落地方案。（40分）

> 参考答案：
- 要点1：热点参数——对 `itemId` 建 `ParamFlowRule` 设大盘阈值，给爆款 SKU 配例外项单独控制，防"一个值打爆整体"（10分）
- 要点2：集群限流——用 Token Server 做全局限流（否则 20 实例各限会把总量放大 20 倍），并配退化：TC 不可用时回落本地限流保证不阻断（10分）
- 要点3：规则持久化——规则接 `NacosDataSource` 动态推送、重启不丢、可批量下发；内置快照兜底，防拉取失败"无规则裸奔"（10分）
- 要点4：降级兜底——`blockHandler` 对超限请求返回缓存/排队页而非抛异常，形成"热点隔离+全局兜底"闭环（10分）
