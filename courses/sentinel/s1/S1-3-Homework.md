# 热点参数限流、集群限流与规则持久化（关联） · 作业

### 作业 1：热点参数限流保护爆款

- 目标：用 `ParamFlowRule` 挡住"单个参数值打爆接口"。
- 任务：对 `queryStock(itemId)` 配热点参数规则，大盘阈值 100，给爆款 `8888L` 配例外项 500；用压测脚本对普通 itemId 和爆款 itemId 分别打流，验证爆款被单独限、普通商品不受牵连；对比"只配接口总阈值"时正常查询被误伤的现象。
- 验收标准：爆款命中例外阈值、正常 itemId 走大盘阈值；`blockHandler` 对超限请求返回缓存兜底而非抛异常。
- 参考解法要点：`setParamIdx`、`ParamFlowItem` 例外项、`@SentinelResource` 传参。

### 作业 2：集群限流与退化验证

- 目标：复现"单机限流总量失真"并用集群限流纠正，验证 TC 故障退化。
- 任务：部署多实例，先各配单机 100，压测统计全局实际放行≈N×100；切换到集群模式（Token Server 统一发令牌），全局阈值收敛到设定值；再 kill 掉 Token Server，观察各实例退化为本地限流而非"全不限/全限死"。
- 验收标准：能展示单机 vs 集群的全局放行差异；TC 不可用时退化生效、业务不中断；说明嵌入/独立模式选择。
- 参考解法要点：集群限流阈值是全局量；degrade 策略保证 TC 不作单点。

### 作业 3：规则接 Nacos 持久化 + 兜底

- 目标：让规则"改即生效、重启不丢、拉取失败有兜底"。
- 任务：用 `NacosDataSource` 把流控规则源指向 Nacos 某 dataId，改 Nacos 配置验证规则热更新；重启服务确认规则仍在（对比只存控制台内存时重启丢失）；模拟启动时 Nacos 不可达，验证回退到本地最后快照而非无规则裸奔。
- 验收标准：动态推送实时生效；重启不丢；数据源不可用有兜底；能说清"推拉结合"的规则源原理。
- 参考解法要点：`register2Property`、内置默认规则文件、启动拉取失败降级。
